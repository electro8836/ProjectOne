### 구글 로그인 — 지금 있는 것과 맞춰야 하는 것

코드는 이미 있다: `GoogleLoginHandler`(GoogleSignIn 으로 idToken → `Backend.BMember.AuthorizeFederation`), `NetworkManager.createLoginHandler` 의 Google 분기, 타이틀의 구글 버튼(`TitleHUD`). 웹 클라이언트 ID 도 코드에 들어 있다. 기기에서 돌려 본 적은 없다.

넷이 모두 맞아야 한다.

```
앱(패키지명 + 서명 키 SHA-1)  ─┐
                               ├─ 구글 클라우드 콘솔: 같은 프로젝트 안에
웹 클라이언트 ID(코드에 있음) ─┘    ① Android 클라이언트(패키지명+SHA-1)  ② 웹 클라이언트
                                    ③ OAuth 동의 화면(테스트 상태면 테스트 사용자 등록)
idToken ──────────────────────────→ ④ 뒤끝 콘솔: 구글 로그인 설정에 웹 클라이언트 ID 등록
```

- 증상으로 원인 가르기 — 실패 로그에 상태 코드가 남는다(`[Backnd] 구글 로그인 취소/실패: <Status>`)
  - `DeveloperError` → 패키지명·SHA-1 이 Android 클라이언트와 다르다
  - `Canceled` → 유저가 계정 선택을 닫았다
  - 뒤끝 인증 실패(401) → 웹 클라이언트 ID 가 뒤끝 콘솔과 다르다
- 서명 키가 바뀌면 SHA-1 도 바뀐다: 디버그 키, 릴리스 키, 스토어 업로드 뒤의 Play 앱 서명 키가 각각 다르다. 쓰는 키마다 Android 클라이언트를 등록한다
- 지문 뽑기: `keytool -J-Duser.language=en -list -v -keystore <키스토어> -alias <별칭>` (한글 로캘에서는 출력이 깨져 SHA-1 과 SHA-256 줄이 섞여 보인다)
- **플러그인 위험**: 지금 플러그인은 구글 공식 `google-signin-unity` v1.0.4(2018)이고, 그 밑의 레거시 Google Sign-In API 는 구글이 폐기 절차를 밟고 있다. 설정을 다 맞춰도 최신 기기에서 실패할 수 있다. 먼저 지금 플러그인으로 끝까지 돌려 보고, 플러그인이 원인이면 교체한다
- 안드로이드 의존성은 EDM(External Dependency Manager)이 푼다. 빌드 대상이 Android 일 때 해석되며, 아직 한 번도 해석된 적이 없다(`ProjectSettings/AndroidResolverDependencies.xml` 없음)
