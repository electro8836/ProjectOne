# 제작 시스템 설계

> 2D 탑다운 방치형 핵앤슬래시 (Unity, 싱글플레이) — 장비 제작 사슬 / 티어 / 재료 조합 / 재련
> 관련 문서: `월드진행_설계.md`, `아이템시스템_설계.md`, `보상시스템_설계.md`, `전투력시스템_설계.md`, `뒤끝서버시스템_설계.md`, `UI구조_설계.md`
> 제작·재련·분해 환급(데이터·공유 규칙·서버 펑션·화면)이 구현되어 있다. 정하지 않은 것은 10장에 모았다. 표의 수치·이름은 임시 데이터다.

---

## 1. 핵심 컨셉

- **가지고 있는 장비를 다음 장비로 만들어 올린다.** 기초 장비(1티어)에 재료와 재화를 넣어 2티어 장비로, 2티어 장비를 3티어 장비로 만든다. 등급·강화 레벨·품질은 그대로 이어지므로 "키운 장비가 더 좋은 장비가 된다"는 체감이 생긴다.
- **진행을 막는 것은 재료뿐이다.** 제작에 레벨·단계 조건은 없다. 대신 상위 티어 제작법은 월드·보스 고유 재료와 재화를 요구하므로, 그 보스를 잡을 수 있어야 만들 수 있다.
- **재료도 조합한다.** 보스가 떨구는 조각 재료를 모아 상위 재료를 만들고, 그 재료로 장비를 만든다. 조합법은 "장비 ← 이전 장비 + 재료 ← 하위 재료" 로 여러 층의 트리가 된다 (워크3 유즈맵 '더월드RPG' 조합 방식 벤치마킹).
- **갈래를 고른다.** 1티어 장비 하나에서 2티어 장비 여러 개 중 하나를 골라 만들 수 있다.
- **장비 성장 기능은 제작 화면 한곳에 모은다.** 제작·재련·강화·승급·전이가 모두 제작 화면 안에 있다. 분해만 장비 화면에 남는다.
- 장소 컨셉(대장간 등)이나 별도 영구 성장 트리는 두지 않는다. 제작은 장비를 다루는 기능이다.

### 1.1 콘텐츠 고리

```
보스 처치 ──▶ 조각 재료 ──(재료 조합)──▶ 상위 재료
                     │
                     ▼
드랍 / 제작 ──▶ 1티어 기초 장비 ──(장비 + 재료 + 재화)──▶ 2티어 장비 (갈래 중 택1) ──▶ 3티어 장비
                     │                      실패 시 재료·재화만 소모, 장비 유지
                     │
                     ├──▶ 재련 ──▶ 품질을 100% 까지 올림
                     │
                     └──▶ 분해 (장비 화면) ──▶ 마력의 결정 · 제작비 환급
```

## 2. 화면

### 2.1 네비게이션 바

오른쪽 끝 **'제작' 탭**이 제작 화면(`UIScreenId.Craft`, `UIPrefab_CraftInfo`)을 연다. 탭 배치는 바꾸지 않는다.

- 아이템 정보 팝업의 강화·승급 버튼(`CraftPresenter.Preselect`)은 제작 화면을 열고 해당 모드에서 그 장비를 선택한 상태로 연다.

### 2.2 모드

| 모드 | 내용 |
|---|---|
| **제작** | 재료 조합, 1티어 기초 장비 제작, 티어 올리기 (3장) |
| **재련** | 품질 올리기 (4장) |
| **강화** | 지금의 강화 그대로 (`아이템시스템_설계.md` 6장) |
| **승급** | 지금의 승급 그대로 |
| **전이** | 지금의 전이 그대로 |

- 열면 제작 모드에서 시작한다.
- 강화·승급·전이는 규칙을 바꾸지 않았다. 재련·강화·승급·전이는 위 등록 칸 + 아래 장비 목록 구조를 함께 쓴다.
- 분해는 지금처럼 **장비 화면**에 둔다.

### 2.3 제작 모드 배치 (시안 `UI대장간_제작모드_시안.png` A안)

위는 고른 조합법의 트리, 아래는 조합법 목록이다. 보유 장비 목록은 보이지 않는다.

- **트리:** 결과 칸(금색 테두리, `TN` 배지) + 이름 → ㄱ자 연결선 → 재료 줄.
  - 재료 줄은 이전 장비(보유하면 초록 체크) · 재료 · 재화 순이다. 칸에 `보유/필요` 를 적고, 모자라면 빨간 테두리·빨간 숫자·빨간 이름으로 표시한다.
  - 모자란 재료 중 조합법이 있는 첫 재료는 그 하위 재료를 한 층 더 보이고, 옆의 **조합** 버튼으로 그 재료의 조합법으로 넘어간다.
  - 제작하기 버튼 안에 성공 확률을 적고, 아래에 "실패 시 재료만 소모 · 실패할수록 확률 상승" 안내를 둔다.
- **목록:** 분류 탭(재료 · 대검 · 단검 · 수리검 · 소총) + 조합법 행. 행은 결과 칸·`TN`·이름·"← 이전 장비 TN" 또는 "← 재료만"·상태 알약(제작 가능 / 재료 부족 / 잠김)이다. 고른 행은 금색 테두리다.
- 티어 올리기에 쓸 이전 장비는 **자동으로 고른다** — 장착 중인 것, 없으면 등급 → 강화 → 품질이 가장 좋은 것. 이전 장비 칸을 누르면 장비 정보가 열린다.
- 재료 조합은 한 번에 1개씩 만든다 (서버는 묶음 요청을 받는다 — 10장).
- **보유 재료 팝업** (시안 `UI재료목록_획득처_시안.png` 2안): 결과 칸 오른쪽 위 둥근 **재료** 버튼으로 연다.
  - 위는 재료 격자(4열, 개수 배지, 0개는 흐리게), 아래는 고른 재료의 이름·보유량·획득처. 처음 열 때 첫 칸을 고른다.
  - 대상은 제작법의 재료나 결과로 나오는 `Material` 아이템이다 (보물상자 열쇠처럼 제작과 무관한 재료는 빠진다).
  - 획득처는 문구 컬럼 없이 테이블에서 찾는다.
    - **보스 처치**: 보상 그룹에 그 재료가 있는 보스 이름을 나열한다. 3종을 넘으면 "보스 N종"으로 줄인다.
    - **조합**: 결과가 그 재료인 제작법의 재료 목록. **조합하기**를 누르면 팝업이 닫히고 재료 탭의 그 제작법을 고른다.
    - **분해 환급**: 티어 올리기 비용에 그 재료가 있으면 "N티어 이상 장비 분해" (N = 그 제작법 결과 중 가장 낮은 티어).

## 3. 제작

### 3.1 티어 (태생 단계)

- 장비 행마다 고정된 **티어**다. `Equipment.Tier` (지금은 1~3, 월드가 늘면 단계도 늘어난다. 비우면 1).
- 등급(일반~신화)과 다른 축이다. 등급은 승급으로 끝까지 올릴 수 있지만, 티어는 그 장비 행에 고정되어 있고 **다음 티어 장비로 제작해야만** 올라간다.
- 티어가 정하는 것은 **기본 성능**이다. 장비 행이 다르므로 `EquipOption` 수치가 티어마다 다르다.
- 품질 상한은 티어와 무관하게 **100%** 다.
- 표기: 아이템 칸·목록 같은 배지에서는 **`T1`, `T2`** 로 짧게 쓴다. 장비가 그려지는 모든 아이템 칸에서 틀 윗변 가운데에 걸친 어두운 알약(티어색 테두리·글자)으로 보인다. 문장으로 서술할 때("1티어 장비를 분해하면 얻는다")는 **"1티어", "2티어"** 로 쓴다.
- 테이블 컬럼은 `Equipment.Tier` 다. 강화 구간(`ItemEnhanceTier`)·드랍 구간(`DropTier`)과는 다른 값이다.

### 3.2 제작 사슬

```
                ┌──▶ 화염대검 (T2) ──▶ 브레이커 (T3)
강철대검 (T1) ──┤
                └──▶ 냉기대검 (T2) ──▶ …
```

- 사슬은 **같은 부위·같은 무기 종류**로만 잇는다. 무기는 `WeaponType` 이 같아야 한다 (마스터리·평타·애니메이터가 무기 종류에 묶여 있다).
- **갈래를 허용한다.** 한 장비에서 이어지는 제작법이 여러 개면 유저가 그중 하나를 골라 만든다. 한 장비로 만들 수 있는 결과는 하나뿐이므로, 갈래를 고르는 것이 곧 그 장비의 진로를 정하는 것이다.
- ID 는 장비 ID 규칙 `1 01 SS TT NNN` 을 그대로 쓰고 순번만 이어 붙인다 (순번에 티어를 인코딩하지 않는다). 사슬 관계는 제작법 테이블(3.7)이 가진다.

### 3.3 재료 조합

- 재료 + 재화 → 상위 재료. **항상 성공한다.**
- 서버는 한 번에 여러 개를 받는다 (요청 1회 최대 100묶음 — 펑션 요금이 호출 수 기준이다).
- 상위 재료의 재료가 다시 조합 재료일 수 있다. 그래서 조합법 트리는 여러 층이 된다.

```
화염대검 T2
 ├─ 강철대검 T1
 ├─ 불꽃 결정 ×2 ── 불꽃 결정 조각 ×5 + 악마의 뿔 조각 ×2
 ├─ 악마의 뿔 ×1 ── 악마의 뿔 조각 ×5
 └─ 골드 · 마력의 결정
```

### 3.4 1티어 기초 장비 제작

- 1티어 장비는 드랍으로도 얻고, **재료와 재화만으로** 만들 수도 있다.
- 결과 등급은 제작법이 정한다 (`ResultGrade`).
- 품질은 드랍과 같은 분포(`EquipQuality`)로 굴린다.
- 레벨은 1이다.

### 3.5 티어 올리기

- 재료: **이전 티어 장비 1개 + 재료 여러 종 + 재화 여러 종.**
- 결과 장비는 **같은 UID** 를 그대로 쓰고 `ItemID` 만 다음 티어 장비로 바뀐다.

| 항목 | 결과 |
|---|---|
| 장비 종류 | 사슬의 다음 장비 |
| 등급 | 유지 |
| 강화 레벨 | 유지 |
| 품질 | 유지 |
| 잠금 | **자동 잠금** |

- 장착 중인 장비도 올릴 수 있다. 장비 행이 바뀌므로 성공 직후 장비 스탯·평타·무기 외형을 다시 적용하고(`Loadout.ReapplyEquipped`) 전투력을 다시 계산한다.

### 3.6 성공 확률 · 실패 · 보정

```
성공 확률(‰) = min(1000, 제작법 기본 확률 + 연속 실패 횟수 × 제작법 실패 보정)
```

- 품질은 성공 확률과 무관하다.
- **실패하면 재료와 재화만 사라지고 장비는 그대로 남는다.**
- 실패할 때마다 그 장비의 **연속 실패 횟수**(`EquipmentInstanceDto.forgeFails`)가 1 오르고, 성공하면 0으로 돌아간다. 실패가 쌓이면 결국 확정 성공에 닿는다.
- 실패 횟수는 장비 인스턴스에 붙어 있다. 그 장비를 분해하면 함께 사라지고, 갈래를 바꿔 시도해도 이어진다.
- 재료 조합과 1티어 기초 제작은 항상 성공한다 (확률 1000‰).
- 모든 확률은 ‰ 정수로 다룬다.

### 3.7 제작법 테이블 (`Forge.xlsx` `#ForgeRecipe`)

제작법 1행 = 결과 1종이다. 종류는 컬럼이 아니라 행 내용으로 정한다 (`ForgeRules.GetKind`).

| 종류 | 조건 |
|---|---|
| 재료 조합 | `SourceItemID` 0, 결과가 장비가 아님 |
| 1티어 기초 제작 | `SourceItemID` 0, 결과가 장비 |
| 티어 올리기 | `SourceItemID` 가 장비, 결과가 장비 |

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 제작법 ID |
| `SourceItemID` | `!int` | 이전 티어 장비. 0이면 재료 조합·기초 제작 |
| `ResultItemID` | `!int` | 결과 (장비 또는 재료) |
| `ResultCount` | `!int` | 재료 조합 1회의 결과 수량. 장비는 1 |
| `ResultGrade` | `!ItemGradeType` | 1티어 기초 제작의 결과 등급. 그 밖에는 비운다 (티어 올리기는 등급 유지) |
| `Mat1~4_ID` / `Mat1~4_Count` | `!int` | 재료. 안 쓰는 칸은 빈칸 |
| `Cur1~2_ID` / `Cur1~2_Count` | `!Currency` / `!int` | 재화. 안 쓰는 칸은 빈칸 |
| `SuccessRate` | `!int` | 기본 성공 확률 (‰). 티어 올리기만 쓴다 |
| `FailBonus` | `!int` | 실패 1회당 확률 보정 (‰). 티어 올리기만 쓴다 |

**제작법 예시 (임시 데이터)**

| 결과 | 이전 장비 | 재료 | 재화 | 기본 확률 | 실패 보정 |
|---|---|---|---|---|---|
| 악마의 뿔 ×1 | ‒ | 악마의 뿔 조각 5 | 골드 1,000 | 항상 | ‒ |
| 불꽃 결정 ×1 | ‒ | 불꽃 결정 조각 5 + 악마의 뿔 조각 2 | 골드 2,000 | 항상 | ‒ |
| 강철대검 T1 | ‒ | 철괴 20 | 골드 10,000 | 항상 | ‒ |
| 화염대검 T2 | 강철대검 | 불꽃 결정 2 + 악마의 뿔 1 | 골드 50,000 + 마력의 결정 100 | 400‰ | 100‰ |
| 냉기대검 T2 | 강철대검 | 악마의 뿔 3 + 악마의 뿔 조각 5 | 골드 50,000 + 마력의 결정 100 | 400‰ | 100‰ |

- 상위 티어 제작법일수록 **뒤쪽 월드의 고유 재료·재화**를 요구한다. 그래서 티어는 월드 진행과 함께 열린다.
- 앞쪽 월드의 재료도 상위 제작법에 섞어 넣어, 지나온 보스를 잡을 이유를 남긴다.
- **분해로 돌려받는 양만으로는 다시 만들 수 없다.** 환급률이 80%(7장)이므로 같은 장비를 다시 만들려면 항상 새 재료가 더 든다.

### 3.8 제작 조건

- 티어 올리기: 그 장비의 `ItemID` 가 제작법의 `SourceItemID` 와 같고, 제작법이 사슬 규칙(같은 부위·무기 종류, 티어 +1)을 지킨다.
- 재료와 재화가 모두 충분하다. 검사를 먼저 끝내고 한 번에 차감한다.
- 1티어 기초 제작: 인벤토리에 빈칸이 있다 (장비 1개 = 1칸). 티어 올리기는 칸을 새로 쓰지 않는다.

### 3.9 재료 공급 원칙

- 보스는 고유 조각 재료·고유 재화를 드랍한다. 보스 보상 그룹(`91xx`, `Monster.RewardGroupID`)에 넣는다.
- 여러 조합법에 두루 쓰이는 **공통 재료**와, 특정 보스에서만 나오는 **고유 재료**를 나눈다.
- **보스 재료·고유 재화는 보스 처치로만 얻는다.** 상점·패스·우편·출석 보상에 넣지 않는다. 제작에 단계 조건이 없으므로 이 원칙이 무너지면 티어 진행 제한이 함께 사라진다.
- 재료 이름·수량은 보스 외형·이름이 정해질 때 함께 정한다.

---

## 4. 재련

### 4.1 규칙

- **모든 장비**의 품질을 올린다. 드랍 장비·제작 장비를 가리지 않는다.
- **상승량 더하기 방식**이다. 상승량을 굴려 지금 품질에 더하고, 100% 를 넘으면 100% 로 맞춘다. 품질은 내려가지 않는다.

```
새 품질 = min(100%, 지금 품질 + 굴린 상승량)
```

- 재련한 장비는 자동으로 잠그지 않는다.
- 화면은 장비 한 칸 + "품질 50.0% · 한 번에 +2.0~6.0%" 안내 + 비용 띠 + 재련하기 버튼이다.

### 4.2 등급별 상승량 · 비용 (`Forge.xlsx` `#ForgeReforge`, 임시 데이터)

| 등급 | 상승량 | 비용 |
|---|---|---|
| Normal | 2 ~ 6% | 골드 2,000 |
| Magic | 1.5 ~ 5% | 골드 5,000 |
| Rare | 1 ~ 4% | 골드 10,000 + 마력의 결정 10 |
| Epic | 1 ~ 3% | 골드 20,000 + 마력의 결정 30 |
| Legendary | 0.5 ~ 2% | 골드 40,000 + 마력의 결정 60 |
| Mythic | 0.5 ~ 1.5% | 골드 80,000 + 마력의 결정 100 |

- 높은 등급일수록 한 번에 오르는 양은 작고 비용은 크다.
- 상승량은 0.1% 단위 정수로 굴린다.

## 6. 전투력

- 장비의 티어는 장비 옵션값(`EquipOption`)에 이미 들어 있으므로 장비 항목으로 계산된다. 따로 더하는 항목은 없다.
- 티어 올리기·재련이 성공하면 서버가 랭킹 전투력을 다시 계산한다(`RankOps.Refresh`).

## 7. 분해

장비 화면에서 한다. 환급은 다음과 같다.

| 항목 | 환급 |
|---|---|
| 마력의 결정 (강화·승급에 쓴 것) | 80% (지금과 같음) |
| 티어 올리기 제작비 (재료 + 재화) | **80%** |
| 재련 비용 | 없음 |
| 실패로 사라진 재료·재화 | 없음 |

- 티어 올리기 제작비는 그 장비까지 이어진 티어 올리기 제작법(1티어→2티어, 2티어→3티어)의 재료·재화를 합해 80%를 돌려준다. 테이블에서 계산하므로 장비마다 쓴 내역을 저장하지 않는다.
- 품질과 무관하다. 재련으로 품질을 올려도 환급이 늘지 않는다.
- 1티어 기초 제작비는 돌려주지 않는다. 드랍한 1티어와 제작한 1티어를 구분하지 않기 위해서다.
- 갈래가 있는 사슬은 그 장비가 실제로 거친 제작법(`ItemID` 로 거슬러 올라간다)만 더한다.
- 재료·재화마다 사슬 합계에 80% 를 곱하고 버림한다. 1개만 쓴 재료는 돌려받지 못한다.
- 단일·일괄 분해에 적용한다. 자동 분해는 드랍 장비만 판정하고 2티어 이상은 제작으로만 얻으므로 해당이 없다.

**잠금 · 자동 분해**

- 1티어 기초 제작과 티어 올리기의 결과는 **자동 잠금**된다. 분해하려면 유저가 직접 잠금을 푼다.
- 자동 분해는 **새로 얻은 장비**만 판정한다. 보관함 장비와 장착 중인 장비는 대상이 아니다.

## 8. 서버 저장 · 펑션

**전부 서버 권위다.** 클라는 공유 규칙으로 버튼 상태·비용·확률을 미리 보여 주고, 서버가 다시 검증한 뒤 차감·지급한다.

### 8.1 저장

| 테이블 | DTO | 내용 |
|---|---|---|
| `USER_INVENTORY` (기존) | `EquipmentInstanceDto` | `forgeFails` 추가 — 티어 올리기 연속 실패 횟수 |

- 고유 재화는 `USER_CURRENCY` 의 재화다. 보스 재료는 `USER_INVENTORY` 의 스택 아이템이다.
- 장비의 티어는 `ItemID` 에서 나오므로 따로 저장하지 않는다.
- 제작·재련은 `USER_INVENTORY`·`USER_CURRENCY` 만 바꾸므로 새 테이블이 필요 없다.

### 8.2 펑션

| 펑션 | 요청 | 서버 검증 | 결과 |
|---|---|---|---|
| `ForgeCraft` | 제작법 ID, (티어 올리기) UID, (재료 조합) 묶음 수 | 장비 소유, `ItemID = SourceItemID`, 사슬 규칙, 재료·재화 보유, (1티어 기초 제작) 인벤토리 빈칸 | 재료·재화 차감. 재료 조합: 결과 재료 지급. 기초 제작: 1티어 지급(품질 굴림, 자동 잠금). 티어 올리기: 확률 굴림 → 성공이면 ItemID 교체 + 자동 잠금 + 실패 횟수 0, 실패면 실패 횟수 +1 |
| `ForgeReforge` | UID, 요청 시점 품질 | 장비 소유, 품질 100% 미만, 비용 보유. 품질이 요청과 다르면 바꾸지 않고 현재 상태만 돌려준다 | 비용 차감, 상승량 굴림, 품질 갱신 |
| (기존) 분해 3종 | ‒ | 기존과 같음 | 마력의 결정 + 티어 올리기 제작비 80% (응답 `gained` / `gainedItems`) |

- 새 펑션 2개는 유저가 직접 누르는 상태 변경이므로 **중복 방지 대상**(`RequestOps.IsGuarded`)에 등록했다.
- 응답은 증감(`spent` / `spentItems` / `gainedItems`)으로 싣는다. 클라는 서버 값으로 덮어쓰지 않는다.
- 확률·품질은 **서버가 요청을 받은 순간 굴린다** (상점 상자와 같은 `ServerRandomSource`). 정수만 쓴다.
- 패킷은 `Packet_Forge.cs`, 서버는 `Function_Forge.cs`, 클라 반영은 `ForgeService.ApplyCraftResponse` / `ApplyReforgeResponse` 다.

### 8.3 공유 규칙

| 규칙 | 위치 | 내용 |
|---|---|---|
| `ForgeRules` | `Core/Network/Shared/Forge/` | 조합법 종류·사슬 검증·갈래 조회, 재료·재화 비용, 성공 확률, 재련 상승량·비용, 분해 시 티어 올리기 제작비 환급(`AddDecomposeRefund`) |

## 9. 테이블

| 테이블 | 파일 | 내용 |
|---|---|---|
| `ForgeRecipe` | `Forge.xlsx` | 제작법 (3.7) |
| `ForgeReforge` | `Forge.xlsx` | 등급별 재련 상승량 범위(%)·비용 (4.2) |
| `Equipment` | 기존 | `Tier` 컬럼 |
| `Item` / `EquipOption` | 기존 | 2티어·3티어 장비 행, 등급별 옵션 행, 재료 아이템 |
| `Reward` | 기존 | 보스 보상 그룹(`91xx`)에 고유 재료·재화 |
| `Currency` | 기존 | 월드 고유 재화 (정식 데이터 때) |

**검증**

- `SourceItemID` 와 `ResultItemID` 는 부위가 같고, 무기는 `WeaponType` 이 같아야 한다.
- `ResultItemID` 의 `Tier` = `SourceItemID` 의 `Tier` + 1. 기초 제작이면 결과 `Tier` = 1.
- 한 `SourceItemID` 에 제작법이 여럿이면 갈래다.
- 재료·재화 ID 는 어딘가에서 지급되는 것이어야 한다 (얻을 수 없는 재료 금지). 보스 재료·고유 재화는 보스 보상 그룹에서만 지급되어야 한다.

### 9.1 첫 구현 범위

- **무기 4종 사슬의 1티어 → 2티어까지만** 만든다. 3티어와 방어구·장신구 사슬은 구조만 두고 데이터는 나중에 채운다.
- 지금 들어간 것은 **임시 데이터**다. 이름·수치·아이콘은 정식 데이터로 바꾼다.
  - 2티어 무기 5종 (`1010101005`~`009`, 대검은 화염·냉기 두 갈래), 아이콘은 1티어 재사용, 옵션은 1티어의 1.5배
  - 재료 5종 (`1020300001`~`005`: 철괴·악마의 뿔 조각·악마의 뿔·불꽃 결정 조각·불꽃 결정), 아이콘은 열쇠 재사용. `10202` 대역은 옛 보상 행(그룹 3001·3002)이 참조하고 있어 피했다
  - 보스 공용 보상 그룹 `9101` 에 철괴·악마의 뿔 조각·불꽃 결정 조각 확정 지급
- 밸런스는 **풀강(최대 강화) 기준**으로 측정해 맞춘다.
