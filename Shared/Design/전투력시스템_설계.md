# 전투력 · 랭킹 시스템 설계

> 2D 탑다운 방치형 핵앤슬래시 (Unity, 싱글플레이) — 전투력 계산 / 전투력 랭킹 / 플레이어 정보
> 관련 문서: `기반테이블_설계.md`, `아이템시스템_설계.md`, `무기마스터리시스템_설계.md`, `펫시스템_설계.md`, `뒤끝서버시스템_설계.md`
> **이 문서는 현재 구현 상태를 기술한다.** 컬럼·행 수는 실제 테이블 기준, 동작 서술은 `GamePlay/Unit/Stats/BattlePowerCalculator.cs`·`Contents/Ranking/` 과 서버 계산용 공유 규칙 `Core/Network/Shared/Ranking/BattlePowerRules.cs` 구현 기준이다.

| 런타임 | 파일 |

### 1.2 핵심 규칙

```
전투력 = Σ ( 영구 출처 스탯 × Weight )  +  Σ ( 보유 스킬 옵션 Point )
```

- **전투력은 육성 결과만 보여준다.** 버프·디버프 같은 임시 스탯은 들어가지 않는다.
- **선형 합이다.** 실제 피해식은 곱연산이지만 전투력은 가중 합으로 근사한다 — 단조증가가 보장되고 기획 튜닝이 쉽다.
- **계산 구현이 둘이다.** 화면에 보이는 값은 클라가 살아 있는 히어로에서 계산하고, 랭킹 점수는 서버가 저장 데이터에서 계산한다. **두 값은 같아야 한다** (4장).
- **랭킹 점수는 최고 전투력이다.** 클라가 보내는 값은 없다.

## 2. 테이블

### 2.1 `BattlePower_Stat` — 스탯 가중치 (3컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 일련번호 |
| `SourceStat` | `!Stat` | 대상 스탯 |
| `Weight` | `!float` | 스탯 1당 전투력 |

`Weight` 는 **"기준 빌드에서의 한계 기여도"** 다. 그 스탯이 1 오를 때 기준 빌드의 화력·생존력이 얼마나 오르는지를 전투력 단위로 환산한 값이다.

**현재 18행**

| 스탯 | Weight | 스탯 | Weight |
|---|---|---|---|
| `Stat_Atk` | 6 | `Stat_DefPen` | 2,000 |
| `Stat_AtkSpeed` | 3,300 | `Stat_MaxHp` | 0.2 |
| `Stat_CritRate` | 4,600 | `Stat_HpRegen` | 12 |
| `Stat_CritDamage` | 1,400 | `Stat_Def` | 2.6 |
| `Stat_DamageBonus` | 3,750 | `Stat_DamageReduction` | 5,000 |
| `Stat_MeleeDamageBonus` | 3,750 | `Stat_LifeOnHit` | 18 |
| `Stat_RangeDamageBonus` | 3,750 | `Stat_EvasionRate` | 4,400 |
| `Stat_BossDamageBonus` | 1,100 | `Stat_BlockRate` | 4,400 |
| `Stat_FinalDamageAmp` | 5,500 | `Stat_MoveSpeed` | 0 |

`Percent` 스탯의 Weight 가 큰 것은 내부값이 0~1 배율이기 때문이다 — 치명타 확률 10%는 `0.1 × 4,600 = 460` 이다.

테이블에 없는 스탯(`ExpBonus` / `PickupRange` / `GoldDropBonus` 등 유틸리티)은 전투력에 들어가지 않는다.

### 2.2 `BattlePower_Option` — 스킬 옵션 점수 (3컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 일련번호 |
| `SourceOption` | `!Option` | 대상 옵션. **`SkillGrant` 타입만 의미가 있다** |
| `Point` | `!float` | 그 스킬을 보유했을 때의 전투력 |

**현재 1행** — `OPT_LEARN_DualBlades_Active_01` = 1,500.

> **`SkillGrant` 만 점수가 된다.** `Stat` 타입 옵션(공격력 +N 등)은 이미 최종 스탯에 녹아 있으므로 여기서 또 점수를 주면 이중 계산이 된다. `SkillLevel` / `Modifier` 는 전투력에 쓰이지 않는다.

스킬은 스탯으로 환산되지 않는 화력이라 별도 축으로 정액을 준다.

## 3. 계산 규칙

### 3.1 영구 출처만 센다

| 출처 | 내용 |
|---|---|
| 기본 스탯 | `CharacterStat` × 캐릭터 레벨 |
| 장비 | 장착 장비의 기본·해금 옵션 |
| 마스터리 | 무기별 레벨 보너스 + 총합 레벨 보너스 + **현재 무기의** 스킬 트리 |
| 펫 | 보유한 펫 전부의 옵션 |

**버프·패시브가 붙이는 임시 스탯과 던전 한정 효과는 들어가지 않는다.**

> **블랙리스트가 아니라 화이트리스트다.** 임시 모디파이어의 출처 태그는 `SkillEffect` ID 라 미리 열거할 수 없다. 그래서 클라는 `StatContainer.GetStat`(최종값) 대신 **`HeroAspectRegistry` 에 등록된 Aspect 의 `SourceKey` 만 합산한 값**을 읽는다. 새 영구 컨텐츠가 Aspect 로 들어오면 자동으로 포함되고, 버프는 Aspect 가 아니므로 자동으로 빠진다.

현재 무기의 트리가 들어가므로 **무기를 바꾸면 전투력이 달라진다.** 무기별 레벨 보너스와 총합 보너스는 무기와 무관하게 유지된다.

### 3.2 스탯 합성

스탯 값은 `기반테이블_설계.md` 8장의 식을 그대로 쓴다.

```
(Base + ΣAdd) × (1 + ΣRatio) × (1 + ΣAmp)  →  Stat.MinValue / MaxValue 클램프 1회
```

클램프를 거치므로 **상한을 넘긴 스탯은 점수에 잡히지 않는다.** 치명타 확률을 100% 넘게 쌓아도 전투력은 오르지 않는다.

### 3.3 Percent 스탯은 Lv1 기본값 초과분만 점수화한다

```
Flat 스탯      점수 = 값 × Weight
Percent 스탯   점수 = (값 - Lv1 기본값) × Weight
```

1레벨 캐릭터가 이미 공격 속도 1.5 · 치명타 피해 1.5 를 갖고 있다. 절대값으로 재면 전투력의 대부분이 **"아무것도 안 한 기본값"** 에서 나오고 성장 체감이 뭉개진다.

- 기준선은 `CharacterStat` 의 **`BaseValue`(1레벨 값)만** 쓴다. `PerLevel` 성장분은 일부러 뺀다 — 기준선이 레벨과 같이 오르면 레벨업이 전투력에 안 잡힌다.
- `Flat` 스탯(공격력·최대 생명력 등)은 절대값이 곱셈의 주축이므로 차감하지 않는다.

### 3.4 스킬 옵션

보유한 스킬 중 `BattlePower_Option` 에 점수가 있는 것의 `Point` 를 더한다.

클라는 `SkillContainer` 를 그대로 믿는다. 장비 등급 해금 옵션은 "현재 등급 이하 누적"으로 걸러져 등록되므로, 도달하지 못한 등급의 스킬은 애초에 컨테이너에 없다.

### 3.5 반올림

합계를 `Mathf.RoundToInt` 와 같은 규칙(짝수 반올림)으로 정수로 만든다. 서버도 같은 규칙을 쓴다.

## 4. 두 구현 — 화면과 서버

| | `BattlePowerCalculator` | `BattlePowerRules` |
|---|---|---|
| 위치 | 클라 전용 | 클라·서버 공용 폴더 (서버가 쓴다) |
| 입력 | 살아 있는 히어로의 `StatContainer` + `SkillContainer` | 저장 DTO 4종 (`LoadoutDto` / `InventoryDto` / `MasteryDto` / `PetDto`) + 테이블 |
| 용도 | HUD · 장비창 · 내 정보의 "현재 전투력" | 랭킹 점수, 공개 스냅샷 |
| 영구 출처 판별 | Aspect 의 `SourceKey` 화이트리스트 | 출처 4갈래를 직접 다시 조립 |

**구현이 따로인 이유** — 서버에는 히어로도 `StatContainer` 도 없다. 저장 데이터와 테이블만으로 같은 결과를 내야 하므로, 서버용은 Aspect 들이 하는 일을 DTO 에서 직접 재현한다.

> **⚠ 영구 스탯 출처를 새로 추가하면 `BattlePowerRules` 에도 넣어야 한다.**
>
> 클라는 Aspect 를 등록하는 것만으로 자동 포함되지만 서버는 그렇지 않다. 빠뜨리면 **화면의 전투력과 랭킹 점수가 조용히 갈라진다.** 새 `IHeroAspect` 를 만들 때 반드시 함께 고친다.

같은 이유로 스탯 합성식·옵션 해석·장비 옵션 계산·마스터리 레벨 환산을 바꾸면 서버용도 같이 바꿔야 한다. `BattlePowerRules` 는 이들을 클라 구현과 같은 규칙으로 따로 갖고 있다.

## 5. 랭킹

뒤끝 유저 리더보드를 쓴다. 서버 쪽 처리의 상세는 `뒤끝서버시스템_설계.md` 7장 "랭킹"이 소유하고, 여기서는 구조와 클라 동작을 적는다.

### 5.1 점수와 갱신

- **점수는 최고 전투력이다.** 현재 전투력이 떨어져도(무기 교체 등) 순위는 내려가지 않는다.
- **서버가 계산한다.** 전투력이 바뀌는 펑션(장비 강화·승급·장착, 마스터리 저장, 펫 강화 등)이 저장을 끝낸 뒤 스스로 갱신한다. 점수는 최고 기록일 때만 오른다.
- 갱신 실패는 본래 행동을 실패시키지 않는다.
- 전 유저가 등록된다.

### 5.2 테이블 둘

| 테이블 | 공개 여부 | 내용 |
|---|---|---|
| `USER_RANKDATA` | 비공개 | 점수 컬럼(`BattlePower`). 리더보드 대상은 비공개여야 한다 |
| `USER_PROFILE` | **공개** | 남에게 보이는 정보 스냅샷 (`PlayerProfileDto`) |

**공개 스냅샷 (`PlayerProfileDto`)**

```
level             캐릭터 레벨 (마스터리 제외)
masteryLevel      전 마스터리 레벨 합
battlePower       현재 전투력 (서버 계산)
bestBattlePower   최고 전투력 — 랭킹 점수와 같다
weaponCostumeId   0 = 미착용
bodyCostumeId     0 = 미착용 (기본 바디)
equipped          장착 중인 장비 인스턴스 목록
```

서버가 자기 데이터로 만들며, 달라졌을 때만 다시 쓴다.

### 5.3 클라 — 목록

`IRankingProvider` 가 랭킹의 출처를 추상화한다. 구현체는 `BackndRankingProvider` 하나다.

- **100위까지, 50명씩 받는다.** 첫 화면에 50위와 내 순위를 받고, 스크롤이 목록 끝에 가까워지면 딤 없이 다음 50명을 이어 받는다.
- **목록은 5분 캐시한다.** 팝업은 열 때마다 새로 만들어지지만 Provider 를 하나로 같이 써서 캐시가 이어진다.
- 내 순위가 0 이하면 리더보드 미등록(순위 외)이다.
- 1 ~ 3위는 테두리가 금·은·동 색이다.

### 5.4 클라 — 플레이어 정보 팝업

랭킹의 한 줄을 누르면 그 플레이어의 정보 팝업이 뜬다.

- **팝업은 `Account` 를 보지 않고 `PlayerProfile` 스냅샷만 그린다.** 내 것이든 남의 것이든 같은 모양으로 넘긴다.
- 남의 정보는 누를 때마다 조회한다(`RankProfile`). 캐시하지 않는다.
- **"나"는 `MyPlayerProfile` 이 내 `Account` 에서 만든다.** 랭킹 출처가 무엇이든 같다.
- 외형은 스냅샷의 코스튬 ID 와 장착 장비로 그린다 (`코스튬시스템_설계.md` 4.2).

**내 최고 전투력** — 서버 기록과 현재 값 중 큰 쪽을 보여준다. 아직 서버에 보고되지 않은 상승분이 화면에서 누락되지 않게 하기 위함이다.

**닉네임** — 로그인 응답(`GetUserData`)으로 받은 값을 쓴다. SDK 의 닉네임은 로그인 시점 캐시라 서버가 방금 부여한 값을 모른다.

## 6. 표시 위치

| 위치 | 값 |
|---|---|
| 메인 HUD 히어로 정보 패널 (`HeroInfo`) | 현재 전투력 |

현재 전투력은 살아 있는 히어로가 있어야 계산된다. 씬 전환 중처럼 히어로가 없으면 0이다.

## 7. 부트 순서

`BattlePowerCalculator.Build()` 는 **`StatCatalog` 와 `OptionCatalog` 이후**에 불려야 한다 — 둘을 모두 참조한다 (`기반테이블_설계.md` 9장). 재호출하면 인덱스를 다시 만든다.

`BattlePowerRules` 는 테이블 인덱스를 처음 쓸 때 1회 만든다.

## 8. 참조 관계

```
BattlePower_Stat.SourceStat      →  Stat.ID
BattlePower_Option.SourceOption  →  Option.ID   (SkillGrant 타입)

(계산 입력)  CharacterStat / EquipOption / WeaponMastery / MasteryLevelBonus / SkillTreeNode / Pet
```

## 9. 검증 규칙

| # | 항목 | 분류 |
|---|---|---|
| 1 | `SourceStat` 이 `Stat` 에 존재하는가 | 오류 |
| 2 | 같은 `SourceStat` 이 2행 이상인가 | 오류 (어느 Weight 가 쓰일지 알 수 없다) |
| 3 | `SourceOption` 이 `OptionType = SkillGrant` 인가 | 경고 (다른 타입은 점수가 되지 않는다) |
| 4 | `Weight` / `Point` 가 음수인가 | 경고 (육성했는데 전투력이 내려간다) |
| 5 | 스킬 트리·장비로 얻을 수 있는 스킬인데 `BattlePower_Option` 에 없는가 | 경고 (배워도 전투력이 오르지 않는다) |
| 6 | 화면 전투력과 서버 전투력이 같은가 | 수동 확인 — 영구 출처를 추가·변경했을 때 |

## 10. 미결 / 다음 작업

- **스킬 옵션 점수가 1행뿐이다** — 쌍검 찌르기만 점수가 있다. 스킬 트리의 다른 습득 노드는 전투력에 반영되지 않는다.
- **`Stat_MoveSpeed` 의 Weight 가 0이다** — 행은 있으나 점수가 없다.
- **Weight 가 임시 밸런스다** — 기준 빌드를 정하고 다시 산정해야 한다.
- **두 구현의 일치를 자동으로 확인하지 않는다** — 4장의 경고가 사람의 주의에만 의존한다. 같은 계정으로 두 값을 비교하는 검증 수단이 있으면 좋다.
- **랭킹이 전투력 하나뿐이다** — 랭킹을 더 만드는 절차는 `뒤끝서버시스템_설계.md` 7장.
- **순위권 밖 정리가 없다** — 리더보드 항목 삭제는 콘솔에서만 된다.
