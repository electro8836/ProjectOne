# 맵 시스템 설계

> 2D 탑다운 방치형 핵앤슬래시 (Unity, 싱글플레이) — 맵 / 액트 / 필드 / 던전 구조
> 관련 문서: `퀘스트시스템_설계.md`, `몬스터시스템_설계.md`, `보상시스템_설계.md`, `기반테이블_설계.md`, `뒤끝서버시스템_설계.md`
> **이 문서는 현재 구현 상태를 기술한다.** 컬럼·행 수는 실제 테이블 기준, 동작 서술은 `GamePlay/Map/`·`GamePlay/Dungeon/`·`GamePlay/Field/` 구현 기준이다.

### 1.2 게임 흐름

```
마을 (1개, 상시 이동 가능)
  ├ 월드 화면 → 액트 선택 → 필드 선택 → 이동
  └ 던전 UI  → 던전 종류 선택 → 단계 선택 → 입장
```

- **마을은 딱 하나만 존재**하며 UI로 언제든 이동 가능하다.
- 필드는 **클리어 개념이 없는 사냥터**다. 몬스터를 처치하면 일정 시간 후 그 자리에 다시 나온다.
- 던전은 종류별로 고유 규칙과 클리어 조건을 가지며, 단계가 올라갈수록 난이도가 상승한다.

### 1.3 핵심 설계 원칙

> **"실제로 들어갈 수 있는 맵"과 "묶음·진행 개념"을 분리한다.**

| 개념 | 성격 | 맵 프리팹 보유 |
|---|---|---|
| `Map` | 실제 맵. 마을·필드·던전 맵이 전부 여기 | O |
| `Act` | UI에서 진행 단계를 보여주는 **그룹** | X |
| `Field` | 필드의 **진행·해금 정보**. `Map` 과 ID를 공유 | X (Map이 가짐) |
| 던전 단계 테이블 (`GoldDungeon` 등) | 던전의 **진행 단위**. 던전 종류마다 따로 있고 맵은 참조만 | X |

> **맵은 씬이 아니라 프리팹이다.** 전투 씬은 비어 있고 `MapManager` 가 `Map.MapPrefab` 주소로 맵 프리팹을 로드해 띄운다. 그래서 액트 내 이동에 씬 전환이 없다.

## 2. Map 통합 테이블을 쓰는 이유

마을·필드·던전 맵을 하나의 테이블에 둔다. 참조하는 쪽(`NpcSpawn.MapID`, 던전 단계 테이블의 `MapID`, `Quest.QuestParam`)이 **"어느 테이블의 ID인가"를 따질 필요가 없어진다.**

타입별로 테이블을 나누면 `MapID` 를 받는 모든 컬럼이 `MapType + ID` 두 컬럼이 되거나, ID 대역으로 타입을 역추론해야 한다.

## 4. `Map` — 모든 맵 통합 (7컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 기본 키 |
| `Name` | `!string` | 표시명 |
| `Desc` | `!string` | 설명 |
| `Icon` | `!string` | 목록 아이콘 |
| `MapType` | `!MapType` | Town / Field / Dungeon |
| `MapPrefab` | `!string` | **맵 프리팹 어드레서블 주소** |
| `BGM` | `!string` | 배경음. FMOD 이벤트 이름이다 (`event:/BGM/<값>`) |

### ID 대역

| 대역 | 용도 | 예 |
|---|---|---|
| `1` | 마을 | `1` |
| `2` + 액트(2) + 순번(2) | 필드 | `20101` = 1액트 1번 필드 |
| 던전종류(1) + `001` | 던전 맵 | `1001`(골드) / `2001`(균열) / `3001`(미궁) / `4001`(유적) |

> **던전 맵 ID와 필드 ID의 대역이 겹치지 않도록 자릿수가 다르다.** 필드는 5자리, 던전 맵은 4자리다.

**현재 55행** — 마을 1 + 던전 맵 4 + 필드 50(5액트 × 10필드). 액트 1·2는 필드마다 전용 맵 프리팹이 있고, 액트 3~5는 아직 액트 1 프리팹을 빌려 쓴다.

**맵 프리팹이 없다.** 들어갈 수 없는 개념이기 때문이다. 액트 자체의 해금 조건도 두지 않고 첫 필드의 `ReqQuestID` 로 갈음한다.

**현재 5액트.**

## 6. `Field` — 필드 진행 정보 (5컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | **`Map.ID` 와 동일한 값** |
| `ActID` | `!int` | 소속 액트 |
| `Order` | `!int` | 액트 내 순서 (1부터) |
| `Name` | `!string` | 표시명 (`Map.Name` 과 중복 보관) |
| `ReqQuestID` | `!int` | **해금 선행 퀘스트.** 빈칸이면 조건 없음 |

**현재 50행** — 액트당 10필드. 레벨 해금 조건은 두지 않는다 (필요해지면 다시 추가). `ReqQuestID` 는 액트 1·2의 19개 필드에만 채워져 있다(첫 필드는 조건 없음). 액트 3~5는 퀘스트가 없어 비어 있다.

### 6.1 클리어 판정이 없다

**필드 클리어 기록을 저장하지 않는다.** `FieldProgress` 는 `클리어한 마지막 퀘스트 ID ≥ ReqQuestID` 로 판정한다 (`ReqQuestID` 가 0이면 항상 열림).

```
해금 = 이동 가능 = 클리어한 것으로 간주
```

퀘스트를 진행하면 뒤 필드가 순서대로 열리므로 **필드를 건너뛰는 개념도, 되돌아갈 수 없는 개념도 없다.**

잠긴 필드로 가는 맵 포털(`MapPortal`)은 장막으로 길을 막고, 포털 근처 안내 영역(`WarningArea`)에 히어로가 들어오면 제한 메시지로 `"{선행 퀘스트명}" 퀘스트 완료 후 개방` 를 띄운다.

> 이 판정이 월드 화면·액트 목록·필드 슬롯 세 화면에서 같은 질문에 답한다. 판정을 흩으면 한쪽만 고쳐져 화면끼리 어긋나므로 `FieldProgress` 한곳이 소유한다.

### 6.2 `Map` 과 ID를 공유한다

`Field` 에는 `MapID` 컬럼이 없다. **자기 `ID` 가 곧 `Map.ID`** 다 (`아이템 ↔ 장비` 와 같은 패턴).

이 덕분에 `Quest.QuestParam_1` 이 `Map.ID` 하나로 필드를 지목할 수 있다.

## 7. 맵 배치와 로딩

### 7.1 액트 하나를 통째로 로드한다

`FieldDirector` 는 **액트 하나에 속한 필드 맵 전부를 동시에 로드**한다. 던전은 1개만 로드한다.

| 이동 | 처리 |
|---|---|
| 같은 액트 안의 필드 이동 | **로드 없음.** 히어로 위치만 옮긴다 |
| 다른 액트로 이동 | 씬 전환 없이 그리드맵 전량 교체 |
| 마을 ↔ 필드 ↔ 던전 | 씬 전환 |

**필드 이동에는 회복이 없다** (`기반테이블_설계.md` 5.3). 액트 진행이 연속된 소모전이 되도록 한 것이다.

### 7.2 배치 좌표는 테이블이 아니라 코드 공식이다

```
MapSpacing = 10000
맵 원점 = ( (Field.Order - 1) × MapSpacing,  (Act.ID - 1) × MapSpacing )
```

액트를 세로축, 필드 순서를 가로축으로 하는 **격자에 맵을 나란히 배치**한다. 좌표 컬럼을 두지 않는 이유는 `Order` 와 `ActID` 만으로 위치가 결정되기 때문이다 — 컬럼을 두면 둘이 어긋날 수 있다.

간격이 10000인 것은 **맵끼리 물리·탐색이 간섭하지 않게** 하기 위함이다.

### 7.3 씬 마커

맵 프리팹 안의 마커가 좌표를 소유한다. 테이블에는 좌표 컬럼이 없다.

| 마커 | 참조 방향 | 소유 정보 |
|---|---|---|
| `MapAnchor` | **테이블 행 없음** | 히어로 시작·부활 지점. 없으면 그리드 중심 |
| `MonsterSpawnPoint` | **씬 → 테이블** | 마커가 `SpawnGroupId` + `Radius` 를 지정 |
| `DungeonSpawnSlot` | **익명 슬롯** | `SlotIndex` + `Radius` 만. 구성은 던전 단계 테이블이 결정 |
| `DungeonWaypoint` | **테이블 행 없음** | 균열 던전 몬스터의 이동 경로 지점 |
| `NpcSpawnPoint` | **테이블 → 씬** | `NpcSpawn(MapID, SpawnPointID)` 가 마커를 지목 |

던전 종류별 전용 마커는 맵 루트 컴포넌트가 모아 갖는다 — 미궁 `LabyrinthMap`(구간 트리거 `LabyrinthSpawnTrigger`, 불 `LabyrinthFireWall`, 상자, 출구), 유적 `RuinsMap`(코어 자리, 방어장치 슬롯, 위험 지점 `RuinsHazardPoint`).

**세 방향이 다른 것은 의도적이다.** 판단 기준은 "조건이 어디에 있는가"다 (`테이블규약_설계.md` 7.2).

### 7.4 지형

| 요소 | 구현 |
|---|---|
| 이동 가능 영역 | `TilemapGrid` — 타일맵 셀 단위 |
| 경로 탐색 | `FlowField` — 맵 단위로 굽는다 |
| 장애물 | `MapBlocker` — 스프라이트 장애물 차단 + Y축 정렬 |
| 벽 충돌 | `MapManager.ResolveWallCollision` |

`Physics2D` 를 쓰지 않는다. 유닛 이동과 충돌은 자체 처리다.

> **전 맵의 기준은 `Grid.cellSize = 0.64` + 각 Tilemap 의 `orientation = Custom`, 행렬 `scale(2.01, 2.01, 1)` 이다.** 타일 스프라이트(32px / PPU 100)를 행렬이 2배로 그려 셀을 메우고, 0.01 의 겹침이 이동 중 타일 경계에 보이던 검은 선을 없앤다. **맵을 키울 때 트랜스폼 스케일을 쓰지 않는다** — `TilemapGrid` 가 `cellSize`(로컬값)를 캐시하므로 충돌·플로우필드가 실제 셀과 어긋난다.

## 8. `Dungeon` — 던전 종류 (12컬럼, EnumTable)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!Dungeon` | Gold / Rift / Labyrinth / Ruins |
| `Name` | `!string` | 표시명 |
| `Desc` | `!string` | 던전 설명 (줄바꿈 포함) |
| `Icon` | `!string` | 목록 아이콘 |
| `Thumbnail` | `!string` | **선택 화면 대표 이미지** |
| `DefaultEnterCount` | `!int` | 기본 일일 입장 횟수 |
| `MaxEnterCount` | `!int` | **확장 상한** |
| `RevivalCostType` | `!Currency` | 부활에 소모하는 재화 |
| `RevivalCost` | `!int` | 1회차 부활 비용 |
| `RevivalCostRatioStep` | `!float` | 회차당 **비율** 증가폭 |
| `MaxRevivalCount` | `!int` | 1회 입장당 부활 가능 횟수. 0이면 부활 불가 |
| `TimeLimit` | `!int` | 제한시간(초). 0이면 무제한. **던전 종류 단위**이며 단계마다 다르지 않다 |

**enum과 데이터를 한 시트에서 관리한다.** 코드가 `EDT.Dungeon` 값으로 모드를 분기하므로 `!EnumTable` 이다. 단, 던전 종류를 추가하려면 행 외에 **단계 테이블과 모드 클래스**도 함께 만들어야 한다 (9장).

**현재 4종** — 일일 5회 / 상한 30회 / 루비 500 / Step 2.0 / 부활 2회는 전부 같고, 제한시간만 미궁 300초 · 나머지 180초다.

### 8.1 부활 정책

```
n회차 부활 비용 = RevivalCost + (n - 1) × RevivalCostRatioStep × RevivalCost
```

현재 값 기준 1회차 500, 2회차 1500 루비다. **비율 증가**이므로 `RevivalCostRatioStep` 은 배수이지 가산값이 아니다. 계산은 공유 `DungeonRules.GetRevivalCost` 가 하고, **차감은 서버(`DungeonRevive`)가 한다.**

- 이 값은 **던전 단계가 아니라 그 입장에서 몇 번째 부활인지**에 붙는다.
- **부활 횟수는 입장 단위로 초기화된다.** 일일 카운터가 아니다 (`DungeonRunState.ReviveUsedCount`).
- 부활해도 **입장 횟수를 다시 소모하지 않는다.**
- 단계별 차등은 두지 않는다. 필요해지면 단계 테이블이 아니라 여기에 단계 계수를 추가한다 — 단계 테이블에 넣으면 단계 수만큼 같은 값이 반복된다.
- 미궁의 불에 닿아 죽는 것은 부활 대상이 아니다. 즉시 실패다 (10.3).

### 8.2 입장 횟수 정책

- **입장 비용 개념이 없다.** 재화도 입장권 아이템도 소모하지 않는다.
- **입장하면 무조건 1회가 소모된다.** 클리어·실패·즉시 이탈을 가리지 않으며 환불도 없다.
- 던전별 일일 카운터만 존재하며 **매일 한국 시간 오전 6시에 초기화**된다 (`ResetDay` — 클라와 서버가 같은 식을 쓴다).
- **인벤토리가 가득 차 있으면 입장할 수 없다** (`DungeonEntry`, `아이템시스템_설계.md` 4.2).
- `Default` 와 `Max` 를 분리하는 것이 핵심이다. 현재 상한은 유저 데이터로 관리하며 `Default` 에서 시작해 `Max` 까지 증가한다.
- **증가 수단(계정 레벨·아이템·과금)은 이 테이블에 넣지 않는다.** 각 시스템이 `ExpandMaxCount(+1)` 을 부르는 형태다.

**저장 데이터**

```
던전별 사용 횟수
던전별 확장된 상한      (Default 에서 시작, Max 까지)
던전별 최고 클리어 단계  (영구 누적)
마지막 초기화 시각
```

**던전별 최고 클리어 단계**는 일일 초기화 대상이 아니며, **단계 해금과 `Quest.DungeonClear` 판정의 유일한 근거**다. 균열은 이 값을 **최고 기록 웨이브**로 쓴다.

**서버(`USER_DUNGEON`)가 소유한다.** 로그인 때 받아 `DungeonProgress` 에 반영하고, 입장·소탕·정산 응답마다 서버값으로 갱신한다. 입장 차감과 일일 초기화 판정은 서버가 서버 시간으로 하며, 클라의 사용 횟수는 표시용 사본이다.

### 8.3 입장과 정산 — 런

```
DungeonEntry.RequestAsync
  └ 서버 DungeonEnter      해금·남은 횟수 확인 → 차감 → 런(runId, seed) 발급
       └ DungeonContext.Run 으로 전투 씬에 전달
            └ 한 판 진행 (DungeonRunLedger 가 주운 보상·연 상자를 기록)
                 └ 종료(클리어·실패·강제 귀환) 시 서버 DungeonClear
                        런 시드로 재현해 클리어 보상·상자 보상 지급, 최고 단계 저장. 런은 한 번만 정산된다
```

던전 팝업 4종과 결과창의 **재도전·다음 단계**가 모두 이 경로를 쓴다. 미로그인(오프라인 테스트)·개발용 이동은 서버 런 없이 로컬 런으로 돈다. 정산 규칙의 상세는 `뒤끝서버시스템_설계.md` 7장.

## 9. 던전 단계 테이블 — 던전마다 따로 둔다

던전 종류마다 필요한 컬럼이 달라 **단계 테이블을 던전별로 분리**한다. 공통 컬럼은 넷이다.

| 공통 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 기본 키. 던전종류(1) + 단계(3) |
| `MapID` | `!int` | 사용할 맵 (`Map.ID`) |
| `MonsterSpawnGroupIDs` | `!int[]` | **배열.** 원소의 뜻은 던전마다 다르다 |
| `MonsterLevel` | `!int` | 이 단계 몬스터 레벨 오버라이드. 0이면 `MonsterSpawn.Level` |

제한시간은 단계 테이블이 아니라 `Dungeon.TimeLimit` 이 갖는다.

**`GoldDungeon` (7컬럼, 15행)** — 공통 + `Stage`(단계 번호) / `RewardExp`(클리어 경험치) / `RewardGroupID`(클리어 보상). `MonsterSpawnGroupIDs` 는 **웨이브 순서**다.

**`RiftDungeon` (7컬럼, 20행)** — 공통 + `Wave`(웨이브 번호) / `RewardCurrency` · `RewardCount`(그 웨이브를 통과하면 받는 재화). `MonsterSpawnGroupIDs` 는 그 웨이브에 내보낼 그룹이다. 행 하나가 단계가 아니라 **웨이브 하나**다.

**`RiftSkill` (4컬럼, 5행)** — 균열 입장 때 고르는 전용 스킬.

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 기본 키 |
| `SkillID` | `!Skill` | 발동할 스킬 (`Skill_Rift_*`) |
| `ReqGauge` | `!int` | 1회 발동에 필요한 게이지. 발동하면 이만큼 소모한다 |
| `MaxGauge` | `!int` | 모을 수 있는 최대 게이지. 비어 있으면 1회분만 모은다 |

**`LabyrinthDungeon` (12컬럼, 20행)** — 공통 + `Stage` / `FireDelay`(불이 출발하기까지 지연, 초) / `FireSpeed`(불이 올라오는 속도) / `ChestCount`(맵의 상자 수 — 맵과 다르면 에러 로그) / `ClearRewardGroupID` / `ChestRewardGroupID_Normal` · `_Advanced` · `_Premium`(상자 등급별 보상 그룹). `MonsterSpawnGroupIDs` 는 **구간 트리거 순서**다.

**`RuinsDungeon` (7컬럼, 10행)** — 공통 + `Stage` / `ClearRewardGroupID` / `CorePhaseGroupID`(→ `RuinsCorePhase.GroupID`). `MonsterSpawnGroupIDs` 는 `[0]` 코어, `[1]` 방어장치, 그 뒤는 코어 페이즈가 소환하는 그룹이다.

**`RuinsCorePhase` (6컬럼, 4행)** — 코어 HP 구간별 방어 시스템 패턴.

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 기본 키 |
| `GroupID` | `!int` | 패턴 묶음 (`RuinsDungeon.CorePhaseGroupID`) |
| `PhaseOrder` | `!int` | 페이즈 순서 |
| `HpThreshold` | `!float` | 코어 HP 비율이 이 값 이하가 되면 진입 (0~1) |
| `SpawnGroupIndex` | `!int` | 진입 시 1회 소환할 그룹. `MonsterSpawnGroupIDs` 의 **1부터 세는 위치**. 0이면 소환 없음 |
| `HazardIDs` | `!int[]` | **배열.** 이 페이즈의 공격 순서 (`RuinsHazard.ID`) |

**`RuinsHazard` (11컬럼, 5행)** — 공격 하나의 모양과 타이밍.

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` / `Name` | `!int` / `!string` | 기본 키 / 기획용 이름 |
| `HazardType` | `!RuinsHazardType` | 가로줄 / 지점 원형 / 지점 도넛 / 유저 위치 낙뢰 |
| `Count` | `!int` | 한 번에 내는 개수(가로줄 수, 낙뢰 연타 수) |
| `Radius` / `InnerRadius` | `!float` | 반경(가로줄은 두께). `InnerRadius` 는 도넛의 안쪽 반경 |
| `WarnTime` | `!float` | 예고 장판을 보여주는 시간(초) |
| `RepeatInterval` | `!float` | 연타 간격(초). 0이면 동시 |
| `PointGroup` | `!int` | 맵의 어느 위험 지점 묶음을 쓰는가 (`RuinsHazardPoint`) |
| `DamageEffectID` | `!SkillEffect` | 적중 시 적용할 효과. 시전자는 코어다 |
| `AfterDelay` | `!float` | 이 공격이 끝난 뒤 다음 공격까지의 간격(초) |

### 9.1 왜 Map과 ID를 공유하지 않는가

`Field` 는 `Map` 과 ID를 공유하지만 던전 단계 테이블은 `MapID` 로 **참조만** 한다.

공유하면 **단계 하나당 맵 하나가 강제된다.** 실제로 현재 네 던전 모두 전 단계가 같은 맵 하나를 쓰고 레벨만 올라간다. 공유 구조였다면 같은 맵을 단계 수만큼 복제해야 했다.

### 9.2 해금 조건 컬럼을 두지 않는다

단계 테이블에는 `ReqLevel` / `ReqQuestID` 가 없다. 해금 조건이 **"직전 단계 클리어" 하나뿐**이라 단계마다 같은 규칙이 반복되기 때문이다.

```
Stage N 입장 가능 ⟺ 최고 클리어 단계 ≥ N - 1        (DungeonRules.IsStageUnlocked)
```

판정은 공유 규칙이 하고 근거는 서버의 **던전별 최고 클리어 단계**다. 균열은 단계를 고르지 않고 **체크포인트에서 시작**한다 (10.3).

### 9.3 클리어 방식은 코드가 소유한다

**모드 컬럼이 없다.** `Dungeon` enum 값 자체가 규칙이며 `StageModeFactory` 가 분기한다.

던전 모드별 규칙은 조합으로 표현되지 않는다. "웨이브 전멸"과 "경로 방어"와 "탈출"은 컬럼 몇 개로 나눌 수 있는 축이 아니다. 그래서 **모드가 자기 단계 테이블을 직접 읽는다.**

## 10. 던전 진행 구조

### 10.1 1회 입장 = 1단계

**연속 스테이지 진행이 없다.** 한 판이 끝나면 결과창에서 **재도전 / 다음 단계 / 나가기** 를 고르고, 다음 단계는 다시 입장하는 것이다(입장 횟수를 또 소모한다).

### 10.2 구조

```
DungeonContext (DungeonType, Stage, Run, RiftSkillId)
  └ DungeonDirector.Begin()
       ├ 맵 로드 → 카메라 → 히어로 스폰 → 전체 회복
       ├ DropManager / 던전 HUD 준비
       ├ IStageMode.SetupAsync(ctx)          모드가 자기 단계 테이블을 읽어 스폰 구성을 짠다
       └ 매 틱 IStageMode.CheckResult()       클리어/실패 판정
          + Dungeon.TimeLimit 카운트다운
```

`IStageMode` 는 **`SetupAsync` 와 `CheckResult` 두 메서드뿐**이다. 모드가 달라지는 것은 "무엇을 언제 스폰하는가"와 "언제 끝나는가" 두 가지다. 히어로 전멸 판정 같은 공통 처리는 `StageModeBase` 가 갖는다.

종료하면 `DungeonMessage` 로 클리어·실패를 띄우고, 서버 정산 응답을 기다린 뒤 결과창을 연다. 결과창은 **런 중 실제로 주운 보상 + 클리어 보상**을 합쳐 보여준다 (`DungeonRunLedger`).

### 10.3 구현된 모드

| 모드 | 클래스 | 규칙 |
|---|---|---|
| `Gold` | `GoldDungeonMode` | **웨이브형.** `MonsterSpawnGroupIDs` 순서가 웨이브 순서, 전멸하면 다음 웨이브. 웨이브 시작 3초 뒤 스폰. 마지막 웨이브까지 전멸시키면 클리어 |
| `Rift` | `RiftDungeonMode` | **경로 방어형 무한 웨이브.** 아래 참조 |
| `Labyrinth` | `LabyrinthDungeonMode` | **탈출형.** 아래 참조 |
| `Ruins` | `RuinsDungeonMode` | **방어 시스템 무력화.** 아래 참조 |

**균열 (`Rift`)**

- 웨이브마다 그 행의 그룹을 **1초 간격으로 한 마리씩** 시작 지점에 내보낸다. 몬스터는 공격하지 않고 `DungeonWaypoint` 를 따라 도착 지점으로 간다 (`MonsterPathBehavior`).
- 도착하면 사라지고 **라이프가 1 깎인다**(최대 5). 웨이브를 다 내보냈고 남은 몬스터가 0이면 곧바로 다음 웨이브다 — 끝이 없다.
- **라이프 0 또는 제한시간 종료가 곧 정산이다.** 균열에는 실패가 없고 "어디까지 갔는가"만 있다.
- **체크포인트** — 5웨이브 간격(1, 6, 11 …)에서만 시작할 수 있다. 다음 도전의 시작 웨이브는 최고 기록에서 정해진다(기록 17 → 16, 기록 4 → 1).
- **보상** — 입장 보상(1 ~ 시작 웨이브의 `RewardCount` 합) + 시작 웨이브 다음부터 통과한 웨이브의 합. **소탕**(`DungeonSweep`)은 전투 없이 입장 보상만 받는다.
- **균열 스킬** — 입장 때 `RiftSkill` 하나를 고른다. 처치로 게이지가 차고(일반 25 / 엘리트 200), `ReqGauge` 이상이면 발동하며 그만큼 소모한다.

**미궁 (`Labyrinth`)**

- 시작 지점에서 위쪽 출구로 올라가는 탈출형이다. 구간 트리거가 **순서대로 하나씩** 발동해 스폰 그룹을 내고 장막으로 앞길을 막으며, 그 구간을 전멸시켜야 장막이 걷힌다.
- 아래에서 **불**이 `FireDelay` 뒤 `FireSpeed` 로 올라온다. **닿으면 부활 없이 즉시 실패**다.
- 모든 구간을 정리한 뒤 출구 구역에 3초 머물러 기관장치를 작동하면 클리어다.
- **상자** — 상자 반경 안에 2초 머물면 열리고, 그 상자 등급의 보상 그룹을 **런 시드로 굴려 바닥에 떨군다.** 주운 것만 서버가 지급하고, 끝날 때 바닥에 남은 것은 사라진다. 상자 등급은 맵 프리팹이 정한다(`Prefab_DungeonChest_Normal / Advanced / Premium`).

**유적 (`Ruins`)**

- 움직이지 않는 **코어**(보스)와 **방어장치**가 있다. 코어를 파괴하면 남은 몬스터가 함께 사라지고 곧바로 클리어다.
- **공격은 코어 몸이 아니라 던전(방어 시스템)이 내린다** (`RuinsCoreSequencer`). 코어의 HP 구간(`RuinsCorePhase`)마다 공격 순서(`HazardIDs`)가 바뀌고, 구간 진입 시 가디언을 1회 소환한다.
- 공격은 예고 장판을 `WarnTime` 동안 보여준 뒤 그 모양 안의 히어로에게 `DamageEffectID` 를 적용한다. 시전자를 코어로 넘기므로 **코어 레벨(단계)의 공격력**을 받는다.
- 순서의 끝에 닿으면 처음으로 돌아가고, 페이즈가 바뀌면 새 순서의 처음부터 쓴다.

> **코드 상수로 남아 있는 수치** — 균열 최대 라이프 5 · 스폰 간격 1초 · 체크포인트 간격 5 · 처치 게이지 25/200, 미궁 상자 개봉 2초 · 출구 장치 3초, 골드 웨이브 시작 지연 3초. 밸런싱 대상이 되면 테이블로 뺀다.

### 10.4 스폰

`SpawnGroupRunner` 가 `MonsterSpawn` 의 `GroupID` 묶음을 씬의 **익명 슬롯**(`DungeonSpawnSlot`)에 배치한다.

- 슬롯이 부족하면 **순환 재사용**한다.
- 슬롯이 하나도 없으면 히어로 주변 반경 4에 폴백 스폰한다.
- 슬롯 위치에서 반경 1로 산포한다.
- **던전에는 리젠이 없다.** 죽으면 그걸로 끝이다 (`몬스터시스템_설계.md`).

## 11. 부활 지점과 회복

### 11.1 부활 지점은 맵이 소유한다

`Map` 테이블에 좌표 컬럼이 없다. 맵 프리팹의 `MapAnchor` 마커가 히어로 시작·부활 지점을 갖고, 없으면 그리드 중심으로 폴백한다.

좌표를 테이블에 두면 **지형이 바뀔 때마다 어긋난다.**

### 11.2 사망 처리

| 상황 | 처리 |
|---|---|
| 필드에서 사망 | 3초 연출 후 해당 맵의 `MapAnchor` 에서 부활. 비용 없음 |
| 던전에서 사망 | `ContinuePopup` — 재화를 소모해 사망 지점에서 부활 (서버 `DungeonRevive` 가 차감) |
| 부활 포기 / 횟수 소진 | 던전 실패. 마을로 귀환 |
| 제한시간 초과 | 던전 실패. 균열만 예외로 정산 종료다 |
| 미궁의 불에 닿음 | 부활 없이 즉시 실패 |

### 11.3 회복 시점

| 시점 | 회복 |
|---|---|
| 필드(액트 내 맵) 이동 | **회복하지 않는다** |
| 던전 입장 | **전체 회복** |
| 마을 귀환 | 전체 회복 |
| 부활 | 전체 회복 |

상세는 `기반테이블_설계.md` 5.3절이 소유한다.

## 12. 참조 관계

```
Map.ID            ─ ID 공유 ─  Field.ID
                  ←  GoldDungeon / RiftDungeon / LabyrinthDungeon / RuinsDungeon .MapID
                  ←  NpcSpawn.MapID
                  ←  Quest.QuestParam_1 (MonsterKill / EliteKill / BossKill)

Act.ID            ←  Field.ActID

Dungeon.ID        ←  Quest.QuestParam_1 (DungeonClear)
                  ←  (코드) StageModeFactory 가 종류별 단계 테이블과 모드를 고른다

(던전 단계).MonsterSpawnGroupIDs[]   →  MonsterSpawn.GroupID
GoldDungeon.RewardGroupID            →  Reward.GroupID
LabyrinthDungeon.ClearRewardGroupID / ChestRewardGroupID_*  →  Reward.GroupID
RuinsDungeon.ClearRewardGroupID      →  Reward.GroupID
RuinsDungeon.CorePhaseGroupID        →  RuinsCorePhase.GroupID
RuinsCorePhase.HazardIDs[]           →  RuinsHazard.ID
RuinsHazard.DamageEffectID           →  SkillEffect.ID
RiftDungeon.RewardCurrency           →  Currency.ID
RiftSkill.SkillID                    →  Skill.ID

Field.ReqQuestID  →  Quest.ID
Dungeon.RevivalCostType →  Currency.ID
```

## 13. 검증 규칙

| # | 항목 | 분류 |
|---|---|---|
| 1 | `Field.ID` 에 대응하는 `Map` 행이 있고 `MapType = Field` 인가 | 오류 |

| 3 | `Field` 의 `(ActID, Order)` 가 중복되는가 | 오류 |
| 4 | `Field.ActID` 가 `Act` 에 존재하는가 | 오류 |
| 5 | 던전 단계 테이블의 `MapID` 가 존재하고 `MapType = Dungeon` 인가 | 오류 |
| 6 | 한 단계 테이블 안에서 `Stage`(균열은 `Wave`)가 중복되는가 | 오류 |
| 7 | `Stage` / `Wave` 가 1부터 빠짐없이 연속인가 | 오류 (중간이 비면 해금이 끊긴다) |
| 8 | `MonsterSpawnGroupIDs` 가 비어 있는가 | 오류 (아무도 안 나온다) |
| 9 | `MonsterSpawnGroupIDs` 의 각 값이 `MonsterSpawn.GroupID` 에 존재하는가 | 오류 |
| 10 | `Map.MapPrefab` 이 비어 있는가 | 오류 |
| 11 | `Map.MapPrefab` 주소가 어드레서블에 등록돼 있는가 | 런타임 로드 실패로 드러남 |

## 14. 미결 / 다음 작업

- **액트 3~5 필드 맵 미제작** — 30개 필드가 액트 1 맵 프리팹을 빌려 쓰고, 해금 퀘스트(`ReqQuestID`)도 비어 있어 처음부터 열려 있다.
- **네 던전 모두 전 단계가 같은 맵 하나를 쓴다** — 레벨만 다르다. 단계별 맵 다양화가 필요하다.
- **유적 던전 클리어 보상이 비어 있다** — `RuinsDungeon.ClearRewardGroupID` 가 전 행 0이다. 처치 드랍만 나온다.
- **유적 코어 패턴이 1벌뿐이다** — 전 단계가 `CorePhaseGroupID = 1` 을 쓴다.
- **던전 수치 일부가 코드 상수다** — 10.3절 끝의 목록.
- **입장 횟수 확장 수단 없음** — `DungeonProgress.ExpandMaxCount` 는 있으나 호출하는 상품·시스템이 없다.
- **레이드 콘텐츠** — `Monster` 에 대응 구조가 없고 `MapType` 도 없다. 던전과 달리 일일 카운터가 아닐 수 있다.
