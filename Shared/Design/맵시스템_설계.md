# 맵 시스템 설계

> 2D 탑다운 방치형 핵앤슬래시 (Unity, 싱글플레이) — 맵 / 액트 / 필드 / 던전 구조
> 관련 문서: `퀘스트시스템_설계.md`, `몬스터시스템_설계.md`, `보상시스템_설계.md`, `기반테이블_설계.md`
> **이 문서는 현재 구현 상태를 기술한다.** 컬럼·행 수는 실제 테이블 기준, 동작 서술은 `GamePlay/Map/`·`GamePlay/Dungeon/`·`GamePlay/Field/` 구현 기준이다.

## 1. 개요

### 1.1 구성 요소

| 대상 | 파일 | 시트 | 현재 행 수 |
|---|---|---|---|
| 맵 | `Map.xlsx` | `Map` | 55 |
| | | `Act` | 5 |
| | | `Field` | 50 |
| | | `Dungeon` | 4 |
| | | `DungeonStage` | 35 |

| 런타임 | 파일 |
|---|---|
| 맵 로드·배치·플로우필드 | `GamePlay/Map/MapManager.cs` |
| 필드 진행 (액트 단위 로드) | `GamePlay/Field/FieldDirector.cs` |
| 필드 해금 판정 | `Contents/Field/FieldProgress.cs` |
| 던전 한 판 오케스트레이션 | `GamePlay/Dungeon/DungeonDirector.cs` |
| 던전 모드 | `GamePlay/Dungeon/Modes/` |
| 던전 입장 횟수·최고 단계 | `Contents/Dungeon/DungeonProgress.cs` |
| 흐름 상태 | `Core/Flow/States/TownState.cs`, `FieldState.cs`, `DungeonState.cs` |

### 1.2 게임 흐름

```
마을 (1개, 상시 이동 가능)
  ├ 월드 화면 → 액트 선택 → 필드 선택 → 이동
  └ 던전 UI  → 던전 종류 선택 → 단계 선택 → 입장
```

- **마을은 딱 하나만 존재**하며 UI로 언제든 이동 가능하다.
- 필드는 **클리어 개념이 없는 사냥터**다. 몬스터를 처치하면 일정 시간 후 그 자리에 다시 나온다.
- 던전은 종류별로 고유 규칙과 클리어 조건을 가지며, 단계가 올라갈수록 난이도가 상승한다.

### 1.3 핵심 설계 원칙

> **"실제로 들어갈 수 있는 맵"과 "묶음·진행 개념"을 분리한다.**

| 개념 | 성격 | 맵 프리팹 보유 |
|---|---|---|
| `Map` | 실제 맵. 마을·필드·던전 맵이 전부 여기 | O |
| `Act` | UI에서 진행 단계를 보여주는 **그룹** | X |
| `Field` | 필드의 **진행·해금 정보**. `Map` 과 ID를 공유 | X (Map이 가짐) |
| `DungeonStage` | 던전의 **진행 단위**. 맵은 참조만 | X |

> **맵은 씬이 아니라 프리팹이다.** 전투 씬은 비어 있고 `MapManager` 가 `Map.MapPrefab` 주소로 맵 프리팹을 로드해 띄운다. 그래서 액트 내 이동에 씬 전환이 없다.

## 2. Map 통합 테이블을 쓰는 이유

마을·필드·던전 맵을 하나의 테이블에 둔다. 참조하는 쪽(`NpcSpawn.MapID`, `DungeonStage.MapID`, `Quest.QuestParam`)이 **"어느 테이블의 ID인가"를 따질 필요가 없어진다.**

타입별로 테이블을 나누면 `MapID` 를 받는 모든 컬럼이 `MapType + ID` 두 컬럼이 되거나, ID 대역으로 타입을 역추론해야 한다.

## 4. `Map` — 모든 맵 통합 (7컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 기본 키 |
| `Name` | `!string` | 표시명 |
| `Desc` | `!string` | 설명 |
| `Icon` | `!string` | 목록 아이콘 |
| `MapType` | `!MapType` | Town / Field / Dungeon |
| `MapPrefab` | `!string` | **맵 프리팹 어드레서블 주소** |
| `BGM` | `!string` | 배경음 주소 |

### ID 대역

| 대역 | 용도 | 예 |
|---|---|---|
| `1` | 마을 | `1` |
| `2` + 액트(2) + 순번(2) | 필드 | `20101` = 1액트 1번 필드 |
| 던전종류(1) + `001` | 던전 맵 | `2001`(골드) / `3001`(균열) |

> **던전 맵 ID와 필드 ID의 대역이 겹치지 않도록 자릿수가 다르다.** 필드는 5자리, 던전 맵은 4자리다.

**현재 55행** — 마을 1 + 던전 맵 4 + 필드 50(5액트 × 10필드).

## 5. `Act` — 필드 묶음 (4컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 액트 번호 (1부터) |
| `Name` | `!string` | `Act I - 붉은 안개 산맥` |

**맵 프리팹이 없다.** 들어갈 수 없는 개념이기 때문이다. 액트 자체의 해금 조건도 두지 않고 첫 필드의 `ReqLevel` 로 갈음한다.

**현재 5액트.**

## 6. `Field` — 필드 진행 정보 (6컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | **`Map.ID` 와 동일한 값** |
| `ActID` | `!int` | 소속 액트 |
| `Order` | `!int` | 액트 내 순서 (1부터) |
| `Name` | `!string` | 표시명 (`Map.Name` 과 중복 보관) |
| `ReqLevel` | `!int` | **해금 요구 캐릭터 레벨** |
| `ReqQuestID` | `!int` | 선행 퀘스트. 빈칸이면 조건 없음 |

**현재 50행** — 액트당 10필드, `ReqLevel` 은 1부터 2씩 증가해 99까지.

### 6.1 클리어 판정이 없다

**필드 클리어 기록을 저장하지 않는다.** `FieldProgress.IsCleared` 는 `캐릭터 레벨 ≥ ReqLevel` 로 판정한다.

```
해금 = 이동 가능 = 클리어한 것으로 간주
```

레벨만 올리면 뒤 필드가 순서대로 열리므로 **필드를 건너뛰는 개념도, 되돌아갈 수 없는 개념도 없다.** 방치형이라 레벨이 곧 진도다.

> 이 판정이 월드 화면·액트 목록·필드 슬롯 세 화면에서 같은 질문에 답한다. 판정을 흩으면 한쪽만 고쳐져 화면끼리 어긋나므로 `FieldProgress` 한곳이 소유한다.

### 6.2 `Map` 과 ID를 공유한다

`Field` 에는 `MapID` 컬럼이 없다. **자기 `ID` 가 곧 `Map.ID`** 다 (`아이템 ↔ 장비` 와 같은 패턴).

이 덕분에 `Quest.QuestParam` 의 지역 한정이 `Map.ID` 하나로 필드를 지목할 수 있다.

## 7. 맵 배치와 로딩

### 7.1 액트 하나를 통째로 로드한다

`FieldDirector` 는 **액트 하나에 속한 필드 맵 전부를 동시에 로드**한다. 던전은 1개만 로드한다.

| 이동 | 처리 |
|---|---|
| 같은 액트 안의 필드 이동 | **로드 없음.** 히어로 위치만 옮긴다 |
| 다른 액트로 이동 | 씬 전환 없이 그리드맵 전량 교체 |
| 마을 ↔ 필드 ↔ 던전 | 씬 전환 |

**필드 이동에는 회복이 없다** (`기반테이블_설계.md` 5.3). 액트 진행이 연속된 소모전이 되도록 한 것이다.

### 7.2 배치 좌표는 테이블이 아니라 코드 공식이다

```
MapSpacing = 10000
맵 원점 = ( (Field.Order - 1) × MapSpacing,  (Act.ID - 1) × MapSpacing )
```

액트를 세로축, 필드 순서를 가로축으로 하는 **격자에 맵을 나란히 배치**한다. 좌표 컬럼을 두지 않는 이유는 `Order` 와 `ActID` 만으로 위치가 결정되기 때문이다 — 컬럼을 두면 둘이 어긋날 수 있다.

간격이 10000인 것은 **맵끼리 물리·탐색이 간섭하지 않게** 하기 위함이다.

### 7.3 씬 마커

맵 프리팹 안의 마커가 좌표를 소유한다. 테이블에는 좌표 컬럼이 없다.

| 마커 | 참조 방향 | 소유 정보 |
|---|---|---|
| `MapAnchor` | **테이블 행 없음** | 히어로 시작·부활 지점. 없으면 그리드 중심 |
| `MonsterSpawnPoint` | **씬 → 테이블** | 마커가 `SpawnGroupId` + `Radius` 를 지정 |
| `DungeonSpawnSlot` | **익명 슬롯** | `SlotIndex` + `Radius` 만. 구성은 `DungeonStage` 가 결정 |
| `NpcSpawnPoint` | **테이블 → 씬** | `NpcSpawn(MapID, SpawnPointID)` 가 마커를 지목 |

**세 방향이 다른 것은 의도적이다.** 판단 기준은 "조건이 어디에 있는가"다 (`테이블규약_설계.md` 7.2).

### 7.4 지형

| 요소 | 구현 |
|---|---|
| 이동 가능 영역 | `TilemapGrid` — 타일맵 셀 단위 |
| 경로 탐색 | `FlowField` — 맵 단위로 굽는다 |
| 장애물 | `MapBlocker` — 스프라이트 장애물 차단 + Y축 정렬 |
| 벽 충돌 | `MapManager.ResolveWallCollision` |

`Physics2D` 를 쓰지 않는다. 유닛 이동과 충돌은 자체 처리다.

## 8. `Dungeon` — 던전 종류 (11컬럼, EnumTable)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!Dungeon` | Gold / Rift / Labyrinth / Ruins |
| `Name` | `!string` | 표시명 |
| `Desc` | `!string` | 던전 설명 (줄바꿈 포함) |
| `Icon` | `!string` | 목록 아이콘 |
| `Thumbnail` | `!string` | **선택 화면 대표 이미지** |
| `DefaultEnterCount` | `!int` | 기본 일일 입장 횟수 |
| `MaxEnterCount` | `!int` | **확장 상한** |
| `RevivalCostType` | `!Currency` | 부활에 소모하는 재화 |
| `RevivalCost` | `!int` | 1회차 부활 비용 |
| `RevivalCostRatioStep` | `!float` | 회차당 **비율** 증가폭 |
| `MaxRevivalCount` | `!int` | 1회 입장당 부활 가능 횟수. 0이면 부활 불가 |

**enum과 데이터를 한 시트에서 관리한다.** 던전 종류가 늘어나면 행 하나만 추가하면 된다. `DungeonType` 으로 코드가 모드를 분기하므로 `!EnumTable` 이다.

**현재 4종 전부 같은 값** — 일일 5회 / 상한 30회 / 루비 500 / Step 2.0 / 부활 2회.

### 8.1 부활 정책

```
n회차 부활 비용 = RevivalCost + (n - 1) × RevivalCostRatioStep × RevivalCost
```

현재 값 기준 1회차 500, 2회차 1500 루비다. **비율 증가**이므로 `RevivalCostRatioStep` 은 배수이지 가산값이 아니다.

- 이 값은 **던전 단계가 아니라 그 입장에서 몇 번째 부활인지**에 붙는다.
- **부활 횟수는 입장 단위로 초기화된다.** 일일 카운터가 아니다 (`DungeonRunState.ReviveUsedCount`).
- 부활해도 **입장 횟수를 다시 소모하지 않는다.**
- 단계별 차등은 두지 않는다. 필요해지면 `DungeonStage` 가 아니라 여기에 단계 계수를 추가한다 — `DungeonStage` 에 넣으면 단계 수만큼 같은 값이 반복된다.

### 8.2 입장 횟수 정책

- **입장 비용 개념이 없다.** 재화도 입장권 아이템도 소모하지 않는다.
- **입장하면 무조건 1회가 소모된다.** 클리어·실패·즉시 이탈을 가리지 않으며 환불도 없다.
- 던전별 일일 카운터만 존재하며 **매일 정해진 시각에 초기화**된다.
- `Default` 와 `Max` 를 분리하는 것이 핵심이다. 현재 상한은 유저 데이터로 관리하며 `Default` 에서 시작해 `Max` 까지 증가한다.
- **증가 수단(계정 레벨·아이템·과금)은 이 테이블에 넣지 않는다.** 각 시스템이 `ExpandMaxCount(+1)` 을 부르는 형태다.

**저장 데이터**

```
던전별 사용 횟수
던전별 확장된 상한      (Default 에서 시작, Max 까지)
던전별 최고 클리어 단계  (영구 누적)
마지막 초기화 시각
```

**던전별 최고 클리어 단계**는 일일 초기화 대상이 아니며, **단계 해금과 `Quest.DungeonClear` 판정의 유일한 근거**다.

> **현재 `DungeonProgress` 는 인메모리다.** 서버 이관과 서버 시간 기준 초기화가 남아 있다.

## 9. `DungeonStage` — 던전 단계 (9컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 기본 키 |
| `DungeonType` | `!Dungeon` | 소속 던전 |
| `Stage` | `!int` | 단계 번호 (1부터) |
| `MapID` | `!int` | 사용할 맵 (`Map.ID`) |
| `MonsterSpawnGroupIDs` | `!int[]` | **배열.** 길이가 곧 웨이브/페이즈 수 |
| `MonsterLevel` | `!int` | 이 단계 몬스터 레벨 오버라이드. 0이면 스폰 테이블 값 |
| `TimeLimit` | `!int` | 제한시간(초). 0이면 무제한 |
| `RewardExp` | `!int` | 클리어 경험치 |
| `RewardGroupID` | `!int` | 클리어 보상 그룹 |

**현재 35행** — Gold 15단계, Rift 20단계.

### 9.1 왜 Map과 ID를 공유하지 않는가

`Field` 는 `Map` 과 ID를 공유하지만 `DungeonStage` 는 `MapID` 로 **참조만** 한다.

공유하면 **단계 하나당 맵 하나가 강제된다.** 실제로 현재 골드 던전 15단계가 전부 같은 맵(`2001`)을 쓰고 레벨만 올라간다. 공유 구조였다면 같은 맵을 15벌 복제해야 했다.

> **다만 맵 재사용에는 대가가 있다.** `MapID` 만으로는 단계를 특정할 수 없어, 맵으로 단계를 되찾는 개발용 경로(`FindStageRowByMapId`)가 경고를 낸다.

### 9.2 해금 조건 컬럼을 두지 않는다

`DungeonStage` 에는 `ReqLevel` / `ReqQuestID` 가 없다. 해금 조건이 **"직전 단계 클리어" 하나뿐**이라 단계마다 같은 규칙이 반복되기 때문이다.

판정은 코드가 하고 근거는 저장 데이터의 **던전별 최고 클리어 단계**다.

### 9.3 클리어 방식은 코드가 소유한다

**모드 컬럼이 없다.** `Dungeon` enum 값 자체가 규칙이며 `StageModeFactory` 가 분기한다.

던전 모드별 규칙은 조합으로 표현되지 않는다. "웨이브 전멸"과 "누적 처치 목표"는 컬럼 몇 개로 나눌 수 있는 축이 아니다.

## 10. 던전 진행 구조

### 10.1 1회 입장 = 1단계

**연속 스테이지 진행이 없다.** 한 판이 끝나면 결과창에서 **재도전 / 다음 단계 / 나가기** 를 고르고, 다음 단계는 다시 입장하는 것이다(입장 횟수를 또 소모한다).

### 10.2 구조

```
DungeonContext (DungeonType, Stage)
  └ DungeonDirector.Begin()
       ├ 맵 로드 → 카메라 → 히어로 스폰 → 전체 회복
       ├ DropManager / 던전 HUD 준비
       ├ IStageMode.SetupAsync(stageRow)     모드가 스폰 구성을 짠다
       └ 매 틱 IStageMode.CheckResult()       클리어/실패 판정
          + TimeLimit 카운트다운
```

`IStageMode` 는 **`SetupAsync` 와 `CheckResult` 두 메서드뿐**이다. 모드가 달라지는 것은 "무엇을 언제 스폰하는가"와 "언제 끝나는가" 두 가지다.

### 10.3 구현된 모드

| 모드 | 클래스 | 규칙 |
|---|---|---|
| `Gold` | `GoldDungeonMode` | **웨이브형.** `MonsterSpawnGroupIDs` 순서가 웨이브 순서, 전멸하면 다음 웨이브. 웨이브 시작 3초 뒤 스폰 |
| `Rift` | `RiftDungeonMode` | **누적 처치 목표형.** 배열 길이가 페이즈 수 |
| `Labyrinth` | ‒ | **미구현** (enum·데이터만 존재) |
| `Ruins` | ‒ | **미구현** |

> **`Rift` 의 수치가 코드 상수다** — 총 처치 목표 300, 화면 유지 20~50마리, 2초마다 2마리 스폰, 페이즈 시작 3초 지연. 테이블에 빼려면 `DungeonStage` 에 컬럼이 필요하다.

### 10.4 스폰

`SpawnGroupRunner` 가 `MonsterSpawn` 의 `GroupID` 묶음을 씬의 **익명 슬롯**(`DungeonSpawnSlot`)에 배치한다.

- 슬롯이 부족하면 **순환 재사용**한다.
- 슬롯이 하나도 없으면 히어로 주변 반경 4에 폴백 스폰한다.
- 슬롯 위치에서 반경 1로 산포한다.
- **던전에는 리젠이 없다.** 죽으면 그걸로 끝이다 (`몬스터시스템_설계.md`).

## 11. 부활 지점과 회복

### 11.1 부활 지점은 맵이 소유한다

`Map` 테이블에 좌표 컬럼이 없다. 맵 프리팹의 `MapAnchor` 마커가 히어로 시작·부활 지점을 갖고, 없으면 그리드 중심으로 폴백한다.

좌표를 테이블에 두면 **지형이 바뀔 때마다 어긋난다.**

### 11.2 사망 처리

| 상황 | 처리 |
|---|---|
| 필드에서 사망 | 3초 연출 후 해당 맵의 `MapAnchor` 에서 부활. 비용 없음 |
| 던전에서 사망 | `ContinuePopup` — 재화를 소모해 사망 지점에서 부활 |
| 부활 포기 / 횟수 소진 | 던전 실패. 마을로 귀환 |
| 제한시간 초과 | 던전 실패 |

### 11.3 회복 시점

| 시점 | 회복 |
|---|---|
| 필드(액트 내 맵) 이동 | **회복하지 않는다** |
| 던전 입장 | **전체 회복** |
| 마을 귀환 | 전체 회복 |
| 부활 | 전체 회복 |

상세는 `기반테이블_설계.md` 5.3절이 소유한다.

## 13. 검증 규칙

| # | 항목 | 분류 |
|---|---|---|
| 1 | `Field.ID` 에 대응하는 `Map` 행이 있고 `MapType = Field` 인가 | 오류 |
| 2 | `MapType = Field` 인 `Map` 행에 `Field` 행이 있는가 | 오류 |
| 3 | `Field` 의 `(ActID, Order)` 가 중복되는가 | 오류 |
| 4 | `Field.ActID` 가 `Act` 에 존재하는가 | 오류 |
| 5 | `DungeonStage.MapID` 가 존재하고 `MapType = Dungeon` 인가 | 오류 |
| 6 | `DungeonStage` 의 `(DungeonType, Stage)` 가 중복되는가 | 오류 |
| 7 | `DungeonStage.Stage` 가 1부터 빠짐없이 연속인가 | 오류 (중간이 비면 해금이 끊긴다) |
| 8 | `MonsterSpawnGroupIDs` 가 비어 있는가 | 오류 (아무도 안 나온다) |
| 9 | `MonsterSpawnGroupIDs` 의 각 값이 `MonsterSpawn.GroupID` 에 존재하는가 | 오류 |
| 10 | `Map.MapPrefab` 이 비어 있는가 | 오류 |
| 11 | `Map.MapPrefab` 주소가 어드레서블에 등록돼 있는가 | 런타임 로드 실패로 드러남 |
| 12 | `Field.ReqLevel` 이 같은 액트 안에서 `Order` 순으로 증가하는가 | 경고 |
| 13 | `Dungeon` enum 값에 대응 `StageMode` 구현이 있는가 | 경고 (입장하면 에러) |
| 14 | 두 `DungeonStage` 가 같은 `MapID` 를 쓰는가 | 경고 (맵으로 단계 역추적 불가) |

## 14. 미결 / 다음 작업

- **`Labyrinth` · `Ruins` 모드 미구현** — enum·던전 데이터·설명 문구는 있으나 `StageModeFactory` 에 분기가 없어 입장하면 에러가 난다. `DungeonStage` 행도 없다.
- **`MapType = None` 인 맵 2행** — `4001`(미궁던전) / `5001`(유적던전)이 `MapPrefab` 도 비어 있다. 두 던전이 미구현이라 그대로 남아 있다.
- **`DungeonProgress` 가 인메모리다** — 일일 입장 횟수·최고 클리어 단계가 서버 미이관이다. `Quest.DungeonClear` 판정이 여기에 의존한다.
- **골드 던전 15단계가 전부 같은 맵(`2001`)을 쓴다** — 레벨만 다르다. 단계별 맵 다양화가 필요하다.
- **`Rift` 던전 수치가 코드 상수다** — 300킬 / 20~50 유지 / 2초 주기. 테이블로 뺄지 결정이 필요하다.
- **`DungeonStage.RewardGroupID` 와 `RewardExp` 가 전부 0이다** — 던전을 클리어해도 보상이 없다 (`보상시스템_설계.md` 10장).
- **`Map.MapPrefab` 과 실제 어드레서블 주소 불일치** — 테이블 값과 등록된 주소가 어긋난 행이 있다.
- **레이드 콘텐츠** — `Monster` 에 대응 구조가 없고 `MapType` 도 없다. 던전과 달리 일일 카운터가 아닐 수 있다.
