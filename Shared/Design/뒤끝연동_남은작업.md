- [ ] 펑션 호출 수 점검. 뒤끝 요금은 호출 수 기준(월 50,000회 무료, 이후 1회당 $0.0000333)이고 `FieldSettle` 20초 주기가 호출의 대부분이다(유저 1명 1시간 사냥 = 180회) — 출시 전 주기 조정 검토
- [x] 네트워크 실패·재시도·중복 요청 처리 정리 (에디터에서 실패 주입으로 검증, 실제 회선 단절은 미확인)
  - 버튼을 누르게 하지 않는다 — 메시지를 잠깐 보여 주고 알아서 진행한다
  - 대상은 딤을 띄우는 요청(유저가 직접 누른 요청)뿐. 백그라운드 저장(장착·외형·마스터리·퀘스트 카운터·필드 정산·강화 묶음·아이템 차감)은 각자 재전송·되돌림을 하므로 조용히 둔다
  - **거절**(서버가 사유를 달아 응답 — 서버 상태 불변): 경고 메시지(`UIPrefab_AlertMessage`, 3초)로 안내(`NetworkFailureHandler.OnRejected`, 문구는 `NetworkMessages`). 호출부가 직접 안내하는 요청은 `notifyRejected: false`(닉네임 변경)
  - **통신 실패**(응답 없음·시간 초과·형식 오류): 같은 요청을 스스로 다시 보낸다(`BackndFunctionCaller`) — 2초 간격, 최대 3회. 그동안 게임을 멈추고(`Time.timeScale = 0`) 네트워크 딤(`UINetworkRespone`)에 "재연결 중입니다." 를 띄운다(`NetworkFailureHandler.BeginRetry/EndRetry`)
    - 다시 보낸 것이 성공하면 호출부 콜백이 성공으로 **한 번** 불려 원래 하려던 일이 그대로 끝난다. 서버가 거절하면 경고 메시지
    - 3회 모두 실패하면 호출부 콜백을 실패로 부르고 타이틀로 돌려보낸다(`OnRetryExhausted`)
  - **서버 중복 방지**(`Function_Request.cs` `RequestOps`, 진입점 `BFunc.Function`): 딤 요청은 번호(`rid`)를 달고 가고, 재전송은 같은 번호에 `retry` 표시를 더한다. 서버는 성공 응답을 번호와 함께 `USER_REQUEST`(유저당 1행, `Data` 컬럼, `RequestRecordDto`)에 남겼다가 같은 번호의 재전송이 오면 핸들러를 다시 돌리지 않고 그 응답을 돌려준다
    - 대상(`RequestOps.IsGuarded`): ShopBuy · DungeonEnter · DungeonSweep · DungeonRevive · EquipmentPromote · EquipmentTransfer · PetPromote · DailyBonusClaim · HeroPassClaim · MailReceive · ChangeNickname. **유저가 직접 누르는 상태 변경 action 을 새로 만들면 여기에 더한다.** 조회와 백그라운드 저장은 대상이 아니다(백그라운드는 `rid` 를 보내지 않는다)
    - 알고 둔 한계: 핸들러가 저장을 끝낸 직후 번호를 기록하기 전에 펑션이 죽으면 재전송이 한 번 더 반영된다. 막으려면 번호 기록을 각 핸들러의 트랜잭션에 넣어야 한다
  - 네트워크 딤의 Text 는 `UIManager.ShowNetworkMessage` 로만 켠다 — 평소 응답 대기는 문구 없이 회전 아이콘만
  - 시간 초과: 시도마다 20초. 넘으면 통신 실패로 치고 다음 시도로 넘어간다. 뒤늦은 응답은 시도 번호로 가려 버린다
  - 계정 데이터 로드(GetUserData, 로그인 직후) 실패: 로딩 화면 아래에서 2초 간격으로 스스로 다시 요청하고, 3회 연속 실패하면 타이틀로 보낸다. 미로그인(Dev·오프라인)은 그대로 통과
  - 타이틀 복귀(`DataLoadState.GoToTitleAsync`): 타이틀에 처음 들어온 것처럼 만든다 — 로딩 표시 → `UIManager.ResetForTitle()`(창·팝업·MainHUD·던전 HUD·네비게이션 바·알림 메시지·월드 게이지 전부 해제, 딤 초기화) → 로그인 상태 초기화 → `GameStateChangedEvent(TitleState)` 발행(맵 해제 등) → **다음 프레임**에 타이틀 전이. 타이틀 씬이 뜨면 `TitleState` 가 로딩을 걷고 "서버와의 연결이 실패했습니다." 확인 팝업을 띄운다
    - 전이를 같은 프레임에 걸면 맵 인스턴스 해제와 비동기 씬 로드가 겹쳐 메인 스레드가 멈춘다(에디터 정지로 확인)
  - 게스트 로그인: 실패 시 게스트 정보 삭제 후 재시도는 `bad customId` 일 때만(`GuestLoginHandler`) — 통신 오류로 기존 계정을 잃지 않게
  - 남은 것: 거절 사유별 문구(지금은 "부족"과 공통 문구 두 가지), 실제 회선 단절·던전 진행 중 재동기화 실기 확인

## 우편 첨부 차트(MailItem) 갱신 절차
1. `Shared/Backnd/MailItem.bat` 실행 → 같은 폴더에 `MailItem.csv` (테이블 .bytes 기준이라 엑셀을 고쳤으면 ExcelDataTable 변환을 먼저)
   - 행: 재화 전부 + 장비를 뺀 아이템 전부(스택·수집품). 컬럼 `MailItemID, RewardType, TargetID, Name`
2. 뒤끝 콘솔 차트 관리에 MailItem 이름으로 업로드(재업로드)하고 '우편 사용'을 켠다.
3. 우편 발송 시 MailItem 차트에서 행을 고르고 수량을 입력한다. 서버는 RewardType·TargetID·수량만 본다.
- 아이템·재화를 추가·삭제하면 다시 내보내서 올린다. 테이블에 없는 첨부는 서버가 지급하지 않고 건너뛴다.

## 새 펑션 추가 절차 (공통 패턴)
1. 공유 규칙 `Core/Network/Shared/<영역>/<영역>Rules.cs` — 클라·서버가 같은 판정을 쓴다.
2. 패킷 `Shared/Packet/Packet_<영역>.cs` + `FunctionName` 상수
3. 서버 `Server/Functions/BackendFunction/Function_<영역>.cs` + `Function_Main.cs` 분기
   - 처리 순서: `GameData.EnsureLoaded` → req 파싱 → `MyData.Load` → 판정 → 변경 → `TransactionWriteV2`
4. 클라 `NetworkManager.Request<X>`
   - 버튼 1회 행위는 딤을 쓴다.
   - 전투 중 자동 처리·묶음 전송은 딤을 쓰지 않는다.
5. 재화 반영은 차감량(증감)으로만 한다. 미정산 필드 처치분과 섞여도 값을 덮어쓰지 않기 위해서다.
6. 새 USER_ 테이블은 뒤끝 콘솔에서 먼저 만든다(`Data` 컬럼에 JSON, 비공개). GetUserData에서 ensure한다.
7. 검증: 서버 `dotnet build` / Unity 컴파일 → Build.bat 배포 → 실기 확인
