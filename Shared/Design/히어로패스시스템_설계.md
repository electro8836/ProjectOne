# 히어로패스 시스템 설계

> 2D 탑다운 방치형 핵앤슬래시 (Unity, 싱글플레이) — 시즌 패스 (활동 경험치 → 레벨별 보상)
> 관련 문서: `보상시스템_설계.md`, `상점시스템_설계.md`, `출석시스템_설계.md`, `뒤끝서버시스템_설계.md`
> **이 문서는 현재 구현 상태를 기술한다.** 컬럼·행 수는 실제 테이블 기준, 동작 서술은 `Contents/HeroPass/` 와 클라·서버 공용 규칙 `Core/Network/Shared/HeroPass/HeroPassRules.cs` 구현 기준이다.

---

## 1. 개요

### 1.1 구성 요소

| 대상 | 파일 | 시트 | 현재 행 수 |
|---|---|---|---|
| 히어로패스 | `Pass.xlsx` | `#Enum` (`HeroPassExpType`) | 4값 |
| | | `HeroPass` | 50 |
| | | `HeroPassLevelExp` | 50 |
| | | `HeroPassExpInfo` | 4 |

| 런타임 | 파일 |
|---|---|
| 규칙 (클라·서버 공용) | `Core/Network/Shared/HeroPass/HeroPassRules.cs` |
| 진행도 도메인 | `Contents/HeroPass/HeroPassBook.cs` |
| 이벤트 → 활동 카운터 | `Contents/HeroPass/HeroPassTracker.cs` |
| 조회 위임 · 정합성 검증 | `Contents/HeroPass/HeroPassCatalog.cs` |
| 저장 DTO | `Core/Network/Shared/Dto/HeroPassDto.cs` |
| UI | `UI/Popup/HeroPassPopupPresenter.cs` |

### 1.2 핵심 규칙

- **플레이하면 패스 경험치가 쌓이고, 레벨마다 보상을 받는다.** 몬스터 처치와 던전 클리어가 경험치원이다.
- 보상은 레벨마다 **일반 / 추가** 두 줄이다. 일반은 누구나 받고, 추가는 패스를 구매해야 받는다.
- **시즌은 35일이고 계정 생성일부터 센다.** 전 유저 공통 달력이 아니라 계정마다 주기가 다르다.
- 시즌이 넘어가면 **경험치·활동 카운터·수령 기록·구매 여부가 전부 초기화**된다. 받지 않은 보상은 사라진다.
- **서버 권위다.** 경험치는 서버가 세고, 수령·구매는 서버 응답 후에만 반영한다.

## 3. 테이블

### 3.1 `HeroPass` — 레벨별 보상 (3컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | **곧 레벨이다** (1부터) |
| `RewardGroupID_Normal` | `!int` | 일반 보상 → `Reward.GroupID` (`75xx`) |
| `RewardGroupID_Advanced` | `!int` | 추가 보상 → `Reward.GroupID` (`76xx`). 패스 구매 필요 |

**현재 50레벨.**

### 3.2 `HeroPassLevelExp` — 레벨 곡선 (2컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 레벨 |
| `TotalExp` | `!int` | 그 레벨에 도달하는 **누적** 경험치 |

현재 레벨당 500 — 1레벨 500, 50레벨 25,000.

> **캐릭터·마스터리 곡선과 기준이 다르다.** `CharacterLevelExp` 는 1레벨의 누적이 0이지만(1레벨에서 시작), 히어로패스는 **0레벨에서 시작해 500을 모아야 1레벨**이다. 그래서 1레벨 행의 `TotalExp` 가 0이 아니다.

- 최대 레벨 누적치를 넘는 경험치는 버린다.
- **보상이 있는 레벨까지만 경험치를 둔다.** `HeroPass` 에 행이 없는 레벨은 도달해도 받을 것이 없다.

### 3.3 `HeroPassExpInfo` — 획득 규칙 (4컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 일련번호 |
| `ExpType` | `!HeroPassExpType` | 활동 유형 |
| `ReqCount` | `!int` | 이 횟수를 채울 때마다 |
| `ExpAmount` | `!int` | 이만큼 준다 |

| ExpType | ReqCount | ExpAmount |
|---|---|---|
| `MonsterKill_Normal` | 1 | 10 |
| `MonsterKill_Elite` | 1 | 20 |
| `MonsterKill_Boss` | 1 | 250 |
| `DungeonClear` | 1 | 50 |

**활동 유형별 카운터가 `ReqCount` 의 배수에 닿을 때마다 `ExpAmount` 가 쌓인다.** `ReqCount = 10` 이면 10마리마다 한 번 준다. 한 유형에 규칙을 여러 행 둘 수 있고, 각 행이 독립적으로 판정된다.

## 4. 경험치 적립

### 4.1 누가 세는가

```
[서버]  처치 정산(FieldSettle) · 던전 종료(DungeonClear) 를 받을 때 같은 규칙으로 센다   ← 정본
[클라]  HeroPassTracker 가 이벤트로 로컬에서도 센다                                   ← 표시용
```

`HeroPassTracker`(영속 `MonoSingleton`)가 `MonsterKillEvent` / `DungeonStageClearedEvent` 를 구독해 `HeroPassBook.AddCount` 를 부른다. 몬스터 등급은 이벤트에 실리지 않아 `Monster.MonsterType` 을 테이블로 역조회한다.

로그인 때 서버 값으로 다시 맞춘다. 클라가 센 값은 화면에 보여주기 위한 것일 뿐이다.

### 4.2 레벨 계산

```
레벨 = 누적 경험치가 HeroPassLevelExp.TotalExp 이상인 마지막 행   (아무것도 못 넘었으면 0)
```

레벨은 저장하지 않고 경험치에서 파생한다.

### 4.3 클라와 서버의 시간차

필드 처치는 20초 주기 배치로 정산되므로 **서버 경험치는 클라보다 늦게 오른다.**

- 클라에서 레벨이 오르면 `HeroPassBook` 이 **밀린 처치 배치를 바로 보낸다.** 막 오른 레벨을 곧 수령할 수 있어야 하기 때문이다.
- 그래도 틈이 남는다. **드랍이 바닥에 남은 처치는 최대 60초까지 서버 경험치에 반영되지 않아**, 그 사이 막 오른 레벨을 수령하면 거절될 수 있다.

## 5. 수령

```
받을 수 있는가 = 그 레벨에 도달했고
              AND 아직 받지 않았고
              AND (추가 보상이면) 이번 시즌 패스를 구매했는가
```

판정은 `HeroPassRules.CanClaim` 하나다. 클라 버튼 상태와 서버 최종 판정이 같은 코드를 쓴다.

- 칸 하나를 눌러 받거나 **모두 받기**로 한 번에 받는다. 받을 수 있는 `(레벨, 추가 여부)` 목록을 모아 서버(`HeroPassClaim`)에 한 번에 요청한다.
- **서버가 자신이 센 경험치로 레벨을 판정한다.** 통과하면 보상 그룹을 굴려 지급하고 수령을 기록한다.
- 클라는 응답의 지급 결과를 인벤/지갑에 반영하고(`RewardGranter.FromServer`) 수령 표시를 한다. 팝업이 닫혔어도 계정 반영은 한다 — 서버에는 이미 저장됐다.
- 수령 판단은 항상 `HeroPassBook` 에서 다시 확인한다. 연타나 다시 그려지기 전의 늦은 클릭을 막는다.

**패스를 나중에 사도 지나간 레벨의 추가 보상을 받는다.** 수령 기록이 일반·추가 따로이므로, 구매 후에는 이미 도달한 레벨의 추가 보상이 전부 수령 가능해진다.

## 6. 구매

상점의 히어로패스 상품(`ShopGoods` ID 1, `GoodsType = HeroPass`)으로 산다.

- **보상 그룹이 없다.** 구매 효과는 이번 시즌 패스 활성화다.
- **시즌당 1회.** 상점 구매 횟수(`USER_SHOP`)가 아니라 패스의 `purchased` 로 판정한다. 시즌이 넘어가면 풀려 다시 살 수 있다.
- **[임시] 결제 검증 없이 활성화된다.** 인앱 결제 연동 시 영수증 검증으로 교체한다 (`출시후 작업.md`).

---

## 7. 시즌

```
시즌 길이   = 35일 (HeroPassRules.SeasonDays)
시즌 시작   = 계정 생성일 (startResetDay)
하루 경계   = 한국 시간 오전 6시 (ResetDay)

seasonIndex = (오늘 - startResetDay) / 35
```

저장된 `seasonIndex` 가 지금 시즌과 다르면 **경험치·카운터·수령 기록·구매 여부를 전부 초기화**한다 (`HeroPassRules.EnsureSeason`). 모든 판정·변경 전에 먼저 부른다 — 경계를 넘긴 상태를 읽지 않게 하기 위함이다.

팝업은 시즌 종료까지 남은 시간을 보여준다.

> **전 유저 공통 시즌이 아니다.** 계정마다 시작일이 달라 시즌 경계도 다르다. 공통 달력으로 바꾸려면 시작일 기준을 계정이 아니라 고정 날짜로 옮겨야 한다.

## 8. 저장 데이터

```
startResetDay     int                       ← 시즌 주기의 기준일 (계정 생성일)
seasonIndex       int                       ← 지금 값과 다르면 초기화
exp               int                       ← 이번 시즌 누적 경험치
purchased         bool                      ← 이번 시즌 패스 구매 여부
counters          List<{ typeId, count }>   ← 활동 유형별 누적 횟수
claimedNormal     List<int>                 ← 일반 보상을 받은 레벨
claimedAdvanced   List<int>                 ← 추가 보상을 받은 레벨
```

서버(`USER_HEROPASS`)가 보관한다 (`HeroPassDto`). 미로그인(오프라인 테스트)이면 오늘을 시즌 시작일로 둔다.

## 9. 참조 관계

```
HeroPass.ID                        ─ 같은 레벨 ─  HeroPassLevelExp.ID
HeroPass.RewardGroupID_Normal      →  Reward.GroupID
HeroPass.RewardGroupID_Advanced    →  Reward.GroupID

HeroPassExpInfo.ExpType            ←  (코드) MonsterType → MonsterKill_* / 던전 클리어 → DungeonClear

ShopGoods (GoodsType=HeroPass)     →  패스 활성화 (보상 그룹 없음)
```

## 11. 미결 / 다음 작업

- **결제 검증이 없다** — 패스 구매가 무검증으로 통과한다 (`출시후 작업.md`).
- **수령 지연** — 막 오른 레벨의 수령이 최대 60초 동안 거절될 수 있다 (4.3).
- **보상 데이터가 임시다** — 100개 그룹이 전부 재화다.
- **경험치원이 넷뿐이다** — 퀘스트 완료·출석 등은 경험치를 주지 않는다. 늘리려면 `HeroPassExpType` 값과 `HeroPassTracker` 구독, 서버 적립 지점을 함께 추가해야 한다.
- **시즌이 계정별이다** — 공통 시즌 이벤트(시즌 한정 보상 교체 등)를 하려면 구조를 바꿔야 한다 (7장).
