# 대장간 설계

> 2D 탑다운 방치형 핵앤슬래시 (Unity, 싱글플레이) — 장비 제작 사슬 / ★ / 재련 / 대장간 트리 · 초월 노드
> 관련 문서: `월드진행_설계.md`, `아이템시스템_설계.md`, `보상시스템_설계.md`, `무기마스터리시스템_설계.md`, `전투력시스템_설계.md`, `뒤끝서버시스템_설계.md`, `UI구조_설계.md`
> **이 문서는 아직 구현되지 않은 목표 설계를 기술한다.** 확정된 내용만 본문에 두고, 정하지 않은 것은 11장에 모았다. 표의 수치·이름은 구조를 보이기 위한 가안이다.

---

## 1. 핵심 컨셉

- **가지고 있는 장비를 다음 장비로 만들어 올린다.** 기초 장비(★1)에 재료와 재화를 넣어 ★2 장비로, ★2 장비를 ★3 장비로 만든다. 등급·강화 레벨·품질은 그대로 이어지므로 "키운 장비가 더 좋은 장비가 된다"는 체감이 생긴다.
- **진행을 막는 것은 재료뿐이다.** 제작에 레벨·단계 조건은 없다. 대신 상위 ★ 제작법은 월드·보스 고유 재료와 재화를 요구하므로, 그 보스를 잡을 수 있어야 만들 수 있다.
- **장비 성장 기능은 대장간 한곳에 모은다.** 제작·재련·강화·승급·전이와 대장간 트리가 모두 대장간 안에 있다. 분해만 장비 화면에 남는다.
- **대장간 트리가 영구 성장 축이다.** 분해로 얻는 정수로 노드를 해금하고 레벨을 올린다. 가지를 다 찍으면 레벨 상한이 없는 초월 노드가 열린다. 초기화는 없다.

### 1.1 콘텐츠 고리

```
보스 처치 ──▶ 보스 고유 재료 · 고유 재화
                     │
                     ▼
드랍 / 제작 ──▶ ★1 기초 장비 ──(장비 + 재료 + 재화)──▶ ★2 장비 ──▶ ★3 장비
                     │                      실패 시 재료·재화만 소모, 장비 유지
                     │
                     ├──▶ 재련 ──▶ 품질을 ★ 상한까지 올림
                     │
                     └──▶ 분해 (장비 화면) ──▶ 마력의 결정 · 제작비 환급 · 정수
                                                                  │
                                                                  ▼
                                      대장간 트리 ──▶ 노드 해금 · 레벨업 ──▶ 초월 노드
```

## 2. 탭 배치

### 2.1 네비게이션 바

| 자리 | 탭 | 비고 |
|---|---|---|
| 1 | 상점 | 유지 |
| 2 | 장비 | 유지 |
| 3 (가운데) | **대장간** | 지금의 '월드' 자리 |
| 4 | 숙련도 | 유지 |
| 5 | (미정) | 지금의 '제작' 탭은 대장간에 흡수된다. 이 자리의 처리는 11장 |

- `NavigationBar` 의 `UIScreenId.World` 자리를 대장간 화면이 쓴다. "준비 중" 알림 분기는 없어진다.
- 아이템 정보 팝업의 강화·승급 버튼(`CraftPresenter.Preselect`)은 대장간 화면을 열고 해당 모드에서 그 장비를 선택한 상태로 연다.

### 2.2 대장간 안 구성

| 모드 | 내용 |
|---|---|
| **제작** | ★1 기초 장비 제작, ★ 올리기 (3장) |
| **재련** | 품질 올리기 (4장) |
| **강화** | 지금의 강화 그대로 (`아이템시스템_설계.md` 6장) |
| **승급** | 지금의 승급 그대로 |
| **전이** | 지금의 전이 그대로 |

- 강화·승급·전이는 규칙을 바꾸지 않는다. 화면만 대장간 안으로 옮긴다.
- 대장간 화면 머리에 **트리 버튼**을 두고, 누르면 대장간 트리(6장)를 연다.
- 분해는 지금처럼 **장비 화면**에 둔다.
- 화면 모양(크기·색·배치)은 구현 단계에서 시안을 보고 정한다.

## 3. 제작

### 3.1 ★ (태생 단계)

- 장비 행마다 고정된 **★ 단계**다. `Equipment.Star` (1~3).
- 등급(일반~신화)과 다른 축이다. 등급은 승급으로 끝까지 올릴 수 있지만, ★ 은 그 장비 행에 고정되어 있고 **다음 ★ 장비로 제작해야만** 올라간다.
- ★ 이 정하는 것은 둘이다.
  1. **품질 상한** — ★1 100% / ★2 120% / ★3 140%
  2. **기본 성능** — 장비 행이 다르므로 `EquipOption` 수치가 ★ 마다 다르다
- 표기: 문장에서는 **"N성"**, 장비 칸에서는 별 하나 + 숫자로 **`★N`** 을 줄여 쓴다. 넓은 화면(아이템 정보)에서는 "N성" 또는 별 N개로 쓴다.
- 코드 이름은 `EquipStar` 계열로 쓴다. `Tier` 는 `ItemEnhanceTier`·`DropTier` 가 이미 쓰고 있어 피한다.

### 3.2 제작 사슬

```
강철대검 (★1) ──▶ 화염대검 (★2) ──▶ 브레이커 (★3)
```

- 사슬은 **같은 부위·같은 무기 종류**로만 잇는다. 무기는 `WeaponType` 이 같아야 한다 (마스터리·평타·애니메이터가 무기 종류에 묶여 있다).
- 사슬은 ★1 장비마다 하나다. 한 장비에서 갈래가 나뉘지 않는다.
- ID 는 장비 ID 규칙 `1 01 SS TT NNN` 을 그대로 쓰고 순번만 이어 붙인다 (순번에 ★ 을 인코딩하지 않는다). 사슬 관계는 제작법 테이블(3.5)이 가진다.

### 3.3 ★1 기초 장비 제작

- ★1 장비는 드랍으로도 얻고, **재료와 재화만으로** 만들 수도 있다.
- 결과 등급은 제작법이 정한다 (`ResultGrade`).
- 품질은 드랍과 같은 분포(`EquipQuality`)로 굴린다.
- 레벨은 1이다.

### 3.4 ★ 올리기

- 재료: **이전 ★ 장비 1개 + 재료 여러 종 + 재화 여러 종.**
- 결과 장비는 **같은 UID** 를 그대로 쓰고 `ItemID` 만 다음 ★ 장비로 바뀐다.

| 항목 | 결과 |
|---|---|
| 장비 종류 | 사슬의 다음 장비 |
| 등급 | 유지 |
| 강화 레벨 | 유지 |
| 품질 | 유지 (상한만 다음 ★ 상한으로 넓어진다) |
| 잠금 | **자동 잠금** |

- 장착 중인 장비도 올릴 수 있다. 장비 행이 바뀌므로 성공 직후 장비 스탯·평타·무기 외형을 다시 적용하고 전투력을 다시 계산한다.

### 3.5 성공 확률 · 실패 · 보정

```
성공 확률(‰) = min(1000, 제작법 기본 확률 + 트리 노드 보정 + 연속 실패 횟수 × 제작법 실패 보정)
```

- 품질은 성공 확률과 무관하다.
- **실패하면 재료와 재화만 사라지고 장비는 그대로 남는다.**
- 실패할 때마다 그 장비(UID)의 **연속 실패 횟수**가 1 오르고, 성공하면 0으로 돌아간다. 실패가 쌓이면 결국 확정 성공에 닿는다.
- ★1 기초 제작은 항상 성공한다 (확률 1000‰).
- 모든 확률은 ‰ 정수로 다룬다.

### 3.6 제작법 테이블

제작법 1행 = 결과 1종이다.

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 제작법 ID |
| `SourceItemID` | `!int` | 이전 ★ 장비. 0이면 ★1 기초 제작 |
| `ResultItemID` | `!int` | 결과 장비 |
| `ResultGrade` | `!ItemGradeType` | ★1 기초 제작의 결과 등급. ★ 올리기는 비운다 (등급 유지) |
| `Mat1~4_ID` / `Mat1~4_Count` | `!int` | 재료. 안 쓰는 칸은 빈칸 |
| `Cur1~3_ID` / `Cur1~3_Count` | `!int` | 재화. 안 쓰는 칸은 빈칸 |
| `SuccessRate` | `!int` | 기본 성공 확률 (‰) |
| `FailBonus` | `!int` | 실패 1회당 확률 보정 (‰) |

**제작법 예시 (가안)**

| 결과 | 이전 장비 | 재료 | 재화 | 기본 확률 | 실패 보정 |
|---|---|---|---|---|---|
| 강철대검 ★1 | ‒ | 철괴 20 | 골드 10,000 | 1000‰ | ‒ |
| 화염대검 ★2 | 강철대검 | 월드1 보스 재료 10 + 불꽃 정수 5 | 골드 50,000 + 월드1 고유 재화 20 | 400‰ | 100‰ |
| 브레이커 ★3 | 화염대검 | 월드2 보스 재료 15 + 월드1 보스 재료 10 | 골드 200,000 + 월드2 고유 재화 30 | 250‰ | 60‰ |

- 상위 ★ 제작법일수록 **뒤쪽 월드의 고유 재료·재화**를 요구한다. 그래서 ★ 은 월드 진행과 함께 열린다.
- 앞쪽 월드의 재료도 상위 제작법에 섞어 넣어, 지나온 보스를 잡을 이유를 남긴다.
- **분해로 돌려받는 양만으로는 다시 만들 수 없다.** 환급률이 80%(8장)이므로 같은 장비를 다시 만들려면 항상 새 재료가 더 든다.

### 3.7 제작 조건

- ★ 올리기: 그 장비의 `ItemID` 가 제작법의 `SourceItemID` 와 같다.
- 재료와 재화가 모두 충분하다. 검사를 먼저 끝내고 한 번에 차감한다.
- ★1 기초 제작: 인벤토리에 빈칸이 있다 (장비 1개 = 1칸). ★ 올리기는 칸을 새로 쓰지 않는다.

### 3.8 재료 공급 원칙

- 보스는 고유 재료·고유 재화를 드랍한다. 보스 보상 그룹(`91xx`, `Monster.RewardGroupID`)에 넣는다.
- **보스 재료·고유 재화는 보스 처치로만 얻는다.** 상점·패스·우편·출석 보상에 넣지 않는다. 제작에 단계 조건이 없으므로 이 원칙이 무너지면 ★ 진행 제한이 함께 사라진다.
- 재료 이름·수량은 보스 외형·이름이 정해질 때 함께 정한다.

## 4. 재련

### 4.1 규칙

- **모든 장비**의 품질을 올린다. 드랍 장비·제작 장비를 가리지 않는다.
- **상승량 더하기 방식**이다. 상승량을 굴려 지금 품질에 더하고, 구간 끝을 넘으면 구간 끝으로 맞춘다. 품질은 내려가지 않는다.

```
새 품질 = min(구간 끝, 지금 품질 + 굴린 상승량 + 트리 노드 상승량 보정)
```

- 재련한 장비는 자동으로 잠그지 않는다.

### 4.2 구간

| 구간 | 품질 | 열리는 ★ | 상승량 (가안) | 비용 (가안) |
|---|---|---|---|---|
| 1 | 0 ~ 100% | ★1 이상 | 1 ~ 5% | 골드 |
| 2 | 100 ~ 120% | ★2 이상 | 0.5 ~ 2% | 골드 + 재련 재료 |
| 3 | 120 ~ 140% | ★3 | 0.2 ~ 1% | 골드 + 상위 재련 재료 |

- **구간을 건너뛰지 않는다.** 119%에서 굴려도 120%에서 멈춘다. 구간 끝에 닿아야 다음 구간 재련이 화면에 나온다.
- 다음 구간은 장비의 ★ 이 그 구간을 허용할 때만 나온다. ★1 장비는 100%가 끝이다.
- 구간마다 비용이 다르다. 뒤 구간일수록 상승량은 작고 비용은 크다.
- 구간 이름은 미정이다 (11장).

### 4.3 품질 100% 초과

- 해금 옵션(`UnlockOpt`)은 품질로 최소~최대 사이를 보간한다. 100%를 넘으면 **같은 기울기로 최대값 너머까지 늘린다.**

```
옵션값 = Min + (Max - Min) × 품질 / 1000      (품질은 0.1% 단위 정수, 최대 1400)
```

- 아이템 정보의 "(최소~최대)" 표시는 그 장비 ★ 의 품질 상한 기준 최대값을 보인다.

## 6. 대장간 트리

### 6.1 규칙

- 대장간 화면 가운데에서 시작하는 **방사형 영구 성장 트리**다. 대장간 레벨·경험치는 없다.
- 노드는 **정수**로 해금하고, 해금한 노드는 정수로 **레벨을 올린다.** 노드마다 최대 레벨이 있다.
- 해금한 노드에 **인접한 노드만** 해금할 수 있다. 가운데 시작 노드는 처음부터 해금돼 있다.
- 바깥 고리는 **안쪽 고리 경계의 관문 노드를 최대 레벨로 찍으면** 열린다.
- **초기화는 없다.** 쓴 정수는 돌아오지 않는다.
- 숙련도와 겹치지 않게 **스킬을 바꾸거나 강화하는 노드는 두지 않는다.**
- `무기마스터리시스템_설계.md` 의 정수 강화 트리는 따로 두지 않는다. 그 역할이 이 트리의 스탯 가지다.

### 6.2 정수

- 트리 전용 재화(`Currency`, `Essence`)다.
- **장비를 분해할 때** 나온다. 단일·일괄·자동 분해 모두 같다. 수량은 8장.

### 6.3 가지 구성 (가안)

```
                    [생존 스탯]
                         │
    [공격 스탯] ─────────┼───────── [강화·승급 절약]
                         │
                      (중심)
                         │
    [분해 정수] ─────────┼───────── [제작 성공]
                         │
                     [재련]
```

| 가지 | 효과 예시 | 전투력 | 초월 그룹 |
|---|---|---|---|
| 공격 스탯 | 공격력 +%, 치명타 피해 +% | 반영 | 전투 |
| 생존 스탯 | 최대 생명력 +%, 방어력 +% | 반영 | 전투 |
| 제작 성공 | ★ 올리기 성공 확률 +‰ | 없음 | 대장간 효율 |
| 재련 | 재련 상승량 +, 재련 비용 -% | 없음 | 대장간 효율 |
| 강화·승급 절약 | 강화 골드 -%, 승급 비용 -% | 없음 | 유틸 |
| 분해 정수 | 분해 정수 +% | 없음 | 유틸 |

- 중심에서 바깥으로 **고리 4개**, 노드는 **총 120개 안팎**이다. 가지 사이에는 이웃 가지를 잇는 연결 노드를 둔다.
- 스탯 가지의 효과는 `Option` 을 거쳐 반영한다 (장비·마스터리·펫과 같은 옵션 목록).
- 나머지 가지의 효과는 스탯이 아니라 **규칙 보정값**이다. 공유 규칙(제작·재련·강화·분해)이 노드 레벨에서 보정값을 읽는다.

### 6.4 초월 노드

- **전투 / 유틸 / 대장간 효율** 3개다. 각 초월 노드는 자기 그룹의 가지(6.3 표)를 **모두 최대 레벨로 찍으면** 열린다.
- **레벨 상한이 없다.** 대신 레벨마다 비용이 급등한다.

```
비용(L) = 기본 비용 × 증가율^L      (증가율 가안 1.15, ‰ 정수 곱으로 계산, 소수점 아래 버림)
효과(L) = 레벨당 효과 × L           (선형)
```

| 초월 노드 | 효과 예시 | 전투력 |
|---|---|---|
| 전투 | 공격력·최대 생명력 +% | 반영 |
| 유틸 | 골드 획득 +%, 마력의 결정 획득 +% | 없음 |
| 대장간 효율 | ★ 올리기 확률 +‰, 재련 비용 -% | 없음 |

- 0으로 수렴하는 효과(비용 감소)는 상한을 둔다 (가안: 최대 50%). 확률 효과는 1000‰ 을 넘지 않는다.
- 트리를 다 찍은 뒤에도 정수를 쓸 곳이 남는다.

### 6.5 조작 (모바일)

- **탭 → 정보 카드 → 확인.** 노드를 탭하면 효과·비용·조건을 담은 카드가 뜨고, 확인을 눌러야 해금·레벨업한다.
- **끌기로 이동, 두 손가락으로 확대·축소.** 처음 열면 마지막으로 찍은 노드를 가운데에 둔다.
- 노드 상태: 최대 레벨 / 해금함 / 해금 가능 / 잠김. 정수가 모자라면 비용을 빨간색으로 표시한다.
- 노드와 연결선은 상태가 바뀔 때만 다시 그린다 (`UI구조_설계.md` 8장 성능 규칙).

## 7. 스탯 · 전투력 반영

### 7.1 스탯 계산 순서

`무기마스터리시스템_설계.md` 8.3 의 순서에서 마스터리 다음에 대장간 단계가 들어간다.

```
[1] 기본값          CharacterStat.BaseValue
[2] 마스터리 보너스   LevelBonusOption
[3] 대장간 트리      스탯 가지 노드 + 전투 초월 노드        ★ 신규 — ForgeAspect, source "Forge"
[4] 장비            EquipOption 기본 · 해금 옵션
[5] 펫              Pet 보유 효과
[6] 버프            SkillEffect (StatChange)
```

- `ForgeAspect` 를 `HeroAspectRegistry` 에 등록한다. 노드 레벨이 바뀌면 source "Forge" 를 통째로 걷어내고 다시 붙인다.

### 7.2 전투력

- 스탯 가지 노드와 전투 초월 노드는 **영구 출처**이므로 전투력에 들어간다. `ForgeAspect` 가 Aspect 로 등록되면 클라 전투력 계산(화이트리스트)에 자동으로 포함된다.
- 서버 전투력 계산(`BattlePowerRules`)에도 같은 값을 더한다. 클라와 서버가 같은 공유 규칙으로 노드 레벨 → 옵션을 풀어낸다.
- 그 밖의 노드는 스탯이 아니므로 전투력과 무관하다.
- 장비의 ★·100% 초과 품질은 장비 옵션값에 이미 들어 있으므로 장비 항목으로 계산된다.

## 8. 분해

장비 화면에서 한다. 환급은 다음과 같다.

| 항목 | 환급 |
|---|---|
| 마력의 결정 (강화·승급에 쓴 것) | 80% (지금과 같음) |
| ★ 올리기 제작비 (재료 + 재화) | **80%** |
| 정수 | 등급 기본량 × (1 + 품질 보너스) |
| 재련 비용 | 없음 |
| 실패로 사라진 재료·재화 | 없음 |

**★ 올리기 제작비**

- 그 장비까지 이어진 ★ 올리기 제작법(★1→★2, ★2→★3)의 재료·재화를 합해 80%를 돌려준다. 테이블에서 계산하므로 장비마다 쓴 내역을 저장하지 않는다.
- 품질과 무관하다. 재련으로 품질을 올려도 환급이 늘지 않는다.
- ★1 기초 제작비는 돌려주지 않는다. 드랍한 ★1 과 제작한 ★1 을 구분하지 않기 위해서다.

**정수**

```
정수 = 등급 기본량 × (1000 + 품질 보너스) / 1000
품질 보너스(‰) = min(품질, 1000) × 200 / 1000      (최대 +20%, 0~100% 구간만 반영)
```

| 분해 장비 등급 | 기본량 (가안) |
|---|---|
| Normal | 1 |
| Magic | 2 |
| Rare | 5 |
| Epic | 12 |
| Legendary | 30 |
| Mythic | 80 |

- 높은 품질로 드랍한 장비는 정수를 더 준다. 100% 초과 구간은 보너스에 넣지 않는다.
- **밸런스 규칙:** 재련으로 품질을 올려 얻는 정수 증가분은 그 재련 비용보다 항상 작아야 한다. 재련한 다음 분해해서 이득을 보는 경로를 만들지 않는다.

**잠금 · 자동 분해**

- ★1 기초 제작과 ★ 올리기의 결과는 **자동 잠금**된다. 분해하려면 유저가 직접 잠금을 푼다.
- 자동 분해는 **새로 얻은 장비**만 판정한다. 보관함 장비와 장착 중인 장비는 대상이 아니다.

## 9. 서버 저장 · 펑션

**전부 서버 권위다.** 클라는 공유 규칙으로 버튼 상태·비용·확률을 미리 보여 주고, 서버가 다시 검증한 뒤 차감·지급한다.

### 9.1 저장

| 테이블 | DTO | 내용 |
|---|---|---|
| `USER_FORGE` (신규) | `ForgeDto` | 트리 노드 레벨 `{노드 ID: 레벨}`, 초월 노드 레벨, 장비별 연속 실패 횟수 `{UID: 횟수}` |

- 정수·고유 재화는 `USER_CURRENCY` 의 재화다. 보스 재료는 `USER_INVENTORY` 의 스택 아이템이다.
- 장비의 ★ 은 `ItemID` 에서 나오므로 따로 저장하지 않는다.
- 연속 실패 횟수는 성공하면 지우고, 그 장비를 분해하면 함께 지운다.
- GetUserData 의 ensure 에 `USER_FORGE` 기본 행 생성을 넣는다.

### 9.2 펑션

| 펑션 | 요청 | 서버 검증 | 결과 |
|---|---|---|---|
| `ForgeCraft` | 제작법 ID (+ ★ 올리기면 UID) | 장비 소유, `ItemID = SourceItemID`, 결과와 부위·무기 종류 일치, 재료·재화 보유, (★1) 인벤토리 빈칸 | 재료·재화 차감, 확률 굴림. 성공: ItemID 교체(또는 ★1 지급) + 자동 잠금 + 실패 횟수 삭제. 실패: 실패 횟수 +1 |
| `ForgeReforge` | UID | 장비 소유, 현재 구간 열림(★·구간 끝 도달), 비용 보유 | 비용 차감, 상승량 굴림, 품질 갱신 |
| `ForgeNodeLevelUp` | 노드 ID | 인접 해금, 고리 열림, 최대 레벨 미만, 정수 보유 | 정수 차감, 노드 레벨 +1 |
| `ForgeTranscend` | 초월 노드 ID | 그룹 가지 전부 최대 레벨, 정수 보유 | 정수 차감, 초월 레벨 +1 |
| (기존) 분해 3종 | ‒ | 기존과 같음 | 마력의 결정 + ★ 올리기 제작비 80% + 정수, 실패 횟수 삭제 |
| (기존) 강화 · 승급 | ‒ | 기존 검증 + 트리 비용 보정 | 기존과 같음 |

- 새 펑션 4개는 유저가 직접 누르는 상태 변경이므로 **중복 방지 대상**(`RequestOps.IsGuarded`)에 등록한다.
- 응답은 증감(`spent` / `rewards`)으로 싣는다. 클라는 서버 값으로 덮어쓰지 않는다.
- 확률·품질은 **서버가 요청을 받은 순간 굴린다.** 요청마다 시드를 새로 만들어 공유 결정적 난수(`DeterministicRandom`)로 굴리고, 정수만 쓴다. 연출은 응답을 기다리는 동안 재생한다.

### 9.3 공유 규칙

| 규칙 | 위치 (가안) | 내용 |
|---|---|---|
| `ForgeRules` | `Core/Network/Shared/Forge/` | 제작 가능 판정, 성공 확률, 재련 구간·상승량, 노드·초월 판정과 비용, 보정값 합산 |
| `EquipmentQuality` | 기존 | 품질 상한을 ★ 기준으로 (1000 고정 → 1000/1200/1400), 100% 초과 보간 |
| `EquipmentGrowthRules` | 기존 | 강화·승급 비용에 노드 보정값 반영 |
| `EquipmentDecomposeRules` | 기존 | ★ 올리기 제작비 환급, 정수 (등급 + 품질 보너스 + 노드 보정) |
| `BattlePowerRules` | 기존 | 스탯 노드·전투 초월 반영, 100% 초과 품질 |

- 서버의 장비 품질 검증도 1000 고정이 아니라 ★ 상한으로 바꾼다.

**검증**

- `SourceItemID` 와 `ResultItemID` 는 부위가 같고, 무기는 `WeaponType` 이 같아야 한다.
- `ResultItemID` 의 `Star` = `SourceItemID` 의 `Star` + 1. 기초 제작이면 결과 `Star` = 1.
- 한 `SourceItemID` 에 제작법은 하나다.
- 재료·재화 ID 는 어딘가에서 지급되는 것이어야 한다 (얻을 수 없는 재료 금지). 보스 재료·고유 재화는 보스 보상 그룹에서만 지급되어야 한다.
- `ForgeNode` 인접 관계는 양방향이고, 시작 노드에서 모든 노드로 이어져야 한다.

### 10.1 첫 구현 범위

- **무기 4종 사슬의 ★1 → ★2 까지만** 만든다. ★3 과 방어구·장신구 사슬은 구조만 두고 데이터는 나중에 채운다.
- 무기 4종 × ★2 장비 1종 × 등급 6개 = `EquipOption` 24행이 늘어난다.
- 밸런스는 **풀강(최대 강화) 기준**으로 측정해 맞춘다.
