# 코스튬 시스템 설계

> 2D 탑다운 방치형 핵앤슬래시 (Unity, 싱글플레이) — 코스튬 보유 / 착용 / 외형 반영
> 관련 문서: `아이템시스템_설계.md`, `무기마스터리시스템_설계.md`, `보상시스템_설계.md`, `상점시스템_설계.md`, `뒤끝서버시스템_설계.md`
> **이 문서는 현재 구현 상태를 기술한다.** 컬럼·행 수는 실제 테이블 기준, 동작 서술은 `Contents/Costume/`·`Contents/Avatar/`·`GamePlay/Unit/Aspect/HeroAvatarAspect.cs` 구현 기준이다.

### 1.2 핵심 규칙

> **코스튬은 외형만 바꾼다. 스탯·스킬에 아무 영향이 없다.**

- **개별 인스턴스가 없다.** 강화·등급 상승이 없어 UID 채번이 무의미하고, **"보유 ID 집합 + 착용 ID 둘"** 이면 상태가 전부 표현된다. 그래서 장비(`Inventory` / `Loadout`)와 분리했다.
- 착용 슬롯은 **무기 1 + 바디 1** 이다.
- **코스튬 ID = 아이템 ID 다.** 수집품 아이템(`MainCategory = Collection`, `SubCategory = Costume`)으로 지급되고, 지급 단계에서 "보유"로 전환된다 (`보상시스템_설계.md` 3.2).

## 3. `Costume` 테이블 (12컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | **`Item.ID` 와 동일** (`1 04 01 NNNNN`) |
| `Name` | `!string` | 표시명 |
| `Desc` | `!string` | 설명 |
| `Icon` | `!string` | 목록 아이콘 |
| `Grade` | `!ItemGradeType` | 표시용 등급 (등급색) |
| `Acquisition` | `!string` | **획득처 안내 문구.** 목록에 그대로 표시한다 |
| `CostumeType` | `!CostumeType` | Weapon / Body |
| `WeaponType` | `!WeaponType` | 무기 코스튬이 맞는 무기 종류. 바디는 비운다 |
| `SetAddress` | `!string` | **파츠 세트(ScriptableObject) 어드레서블 주소** |
| `IsDefault` | `!bool` | 기본 바디. **정확히 1행** |
| `CostCurrencyType` | `!Currency` | 가격 재화 — **현재 코드가 읽지 않는다** (6장) |
| `CostValue` | `!int` | 가격 — 위와 같다 |

**현재 3행**

| ID | 이름 | 타입 | 무기 | 세트 | 비고 |
|---|---|---|---|---|---|
| `1040100001` | 기본 복장 | Body | — | `BodySet_Default` | `IsDefault` |
| `1040100002` | 토끼 코스튬 | Body | — | `BodySet_01` | Mythic. 상점 구매 |
| `1040100003` | 요술봉 | Weapon | DualBlades | `WeaponSet_DualBlades_101` | Mythic. 히드라 처치 |

### 3.1 기본 바디 (`IsDefault`)

바디 착용 ID 가 0(미착용)이면 **`IsDefault` 행의 세트**를 대신 쓴다. 코스튬을 벗었을 때 돌아갈 외형이다.

- **정확히 1개여야 한다.** 0개면 벗었을 때 돌아갈 외형이 없고(프리팹 원본이 남는다), 2개 이상이면 어느 쪽이 쓰일지 데이터로 알 수 없다. `CostumeCatalog.Build()` 가 경고를 낸다.
- 기본 바디는 **코스튬 목록에 나오지 않는다.** 입고 벗을 대상이 아니라 폴백이다.

### 3.2 무기 코스튬의 무기 제한 (`WeaponType`)

무기 코스튬은 특정 무기 종류에만 씌울 수 있다.

> **착용 자체를 막지 않는다. 표시 시점에 판정한다.**
>
> 지금 안 맞는 무기를 들고 있어도 착용은 되고, 그동안은 장비 무기가 그대로 보인다. 맞는 무기로 갈아끼우면 코스튬이 다시 나타난다. 착용 상태는 유지된다 (`CostumeCatalog.CanShowWeapon`).

착용 시점에 막으면 무기를 바꿀 때마다 코스튬이 풀리고, 다시 돌아와도 직접 다시 입어야 한다.

## 4. 외형 반영

### 4.1 파츠 세트 프리로드 (`AvatarCatalog`)

`SetAddress` 는 스프라이트 묶음(`AvatarBodySet` / `AvatarWeaponSet`)의 주소다. **부트에서 테이블이 참조하는 주소를 전부 미리 로드한다.**

장착 경로(`Loadout` 의 히어로 재적용)가 완전 동기라 그 자리에서 `await` 할 수 없기 때문이다 — `MasteryCatalog` 의 애니메이터 오버라이드와 같은 이유, 같은 방식이다.

- 대상: 장비 무기의 `Equipment.WeaponSetAddress` + 코스튬의 `SetAddress`.
- **해제하지 않는다.** 세션 내내 필요하고 종류도 장비·코스튬 수만큼뿐이다.
- 로드에 실패하면 에러 로그를 남긴다. 조용히 넘기면 무기를 껴도 손이 비는 무음 실패가 된다.

### 4.2 적용 순서 (`HeroAvatarAspect`)

`IHeroAspect`, source = `"Avatar"`. 스탯·스킬은 건드리지 않는다.

```
1. 전 파츠를 프리팹 원본으로 되돌린다          ← 이전 장비·코스튬의 잔상 제거
2. 바디 세트를 얹는다                          ← 몸 파츠 전부를 지정
3. 무기 세트를 얹는다                          ← 코스튬 무기가 장비 무기를 덮어쓴다
```

| 부위 | 결정 규칙 |
|---|---|
| 바디 | 착용한 바디 코스튬 → 없으면 기본 바디(`IsDefault`) → 그것도 없으면 프리팹 원본 |
| 무기 | 착용한 무기 코스튬이 **지금 든 무기와 맞으면** 코스튬 → 아니면 장비 무기 → 무기를 안 들었으면 양손이 빈다 |

> **무기를 들지 않으면 무기 코스튬도 보이지 않는다.**

같은 판정을 다른 플레이어의 외형에도 쓴다. 플레이어 정보 팝업은 내 `Account` 가 아니라 착용 ID 와 장비 무기를 직접 받아 그린다 (`ResolveBodySet(equippedId)` / `ResolveWeaponSet(costumeId, weapon)`).

### 4.3 다시 그리는 시점

착용이 바뀌면 `CostumeBook` 이 활성 히어로의 `"Avatar"` 출처만 재적용한다. **인게임 히어로가 없어도 UI 프리뷰는 다시 그려야 하므로 변경 이벤트 발행이 먼저다.**

장비 무기를 바꿀 때도 외형이 다시 그려진다 — 무기 코스튬의 표시 여부가 그때 갈린다.

## 5. 착용과 입어보기

`CostumeBook` 의 착용 API 는 둘이다.

| API | 동작 |
|---|---|
| `EquipWeapon(id)` | 무기 코스튬 착용. `0` 이면 해제 — 장비 무기가 다시 보인다 |
| `EquipBody(id)` | 바디 코스튬 착용. `0` 이면 기본 바디로 되돌린다 |

보유하지 않았거나 타입이 맞지 않으면 거부한다.

**코스튬 창 (`CostumeInfoPresenter`)**

- 무기 / 바디 탭으로 나뉜다. 보유한 것이 앞에 온다.
- **미보유 코스튬도 입어볼 수 있다.** 살지 말지 정하려면 봐야 한다. 입어보는 중인 것을 다시 누르면 해제된다.
- 입어보기는 창에 딸린 프리뷰 리그에서만 일어나고, 창을 닫으면 사라진다. 실제 착용에는 영향이 없다.
- 탭을 옮기면 입어보기를 푼다.
- 장착 중인 것을 다시 누르면 해제다.
- 목록에는 등급(등급색), 무기 코스튬이면 대상 마스터리 이름, 그리고 `Acquisition` 문구를 보여준다.

**저장** — 착용 변경은 로컬에 먼저 반영하고 dirty 로 표시했다가, 창을 닫을 때 외형 저장(`SaveAppearance` — 코스튬 착용 + 펫 장착)으로 한 번에 보낸다. 서버는 보유 여부를 확인한다.

## 6. 획득

| 경로 | 내용 |
|---|---|
| 상점 | 코스튬 탭. 토끼 코스튬 3,000 다이아 / 요술봉 2,500 다이아. 종류당 1회 (`ShopGoods` 32 · 33, 보상 그룹 `42xx`) |

- **이미 가진 코스튬은 다시 얻지 않는다.** 상점은 보유 중이면 구매를 막는다.
- 판매 가격은 `Costume.CostCurrencyType` / `CostValue` 가 아니라 **`ShopGoods` 가 정한다.** 두 컬럼은 현재 코드가 읽지 않는다.
- 새 코스튬을 추가하는 절차는 `데이터작성_가이드.md` 4.12.

## 7. 저장 데이터

```
owned             List<int>    ← 보유한 코스튬 ID
equippedWeaponId  int          ← 0 = 미착용 (장비 무기가 그대로 보인다)
equippedBodyId    int          ← 0 = 미착용 (기본 바디가 적용된다)
```

서버(`USER_COSTUME`)가 보관한다 (`CostumeDto`). 로드할 때 보유하지 않은 것이 착용으로 남아 있으면 버린다.

착용 ID 는 **다른 유저에게 보이는 정보 스냅샷**(`USER_PROFILE`)에도 실린다 (`전투력시스템_설계.md` 5장).

## 8. 참조 관계

```
Item.ID ──(동일 ID)──→ Costume.ID      ★ MainCategory=Collection, SubCategory=Costume

Costume.WeaponType        →  WeaponType (Equipment.xlsx)   ★ WeaponMastery 와 1:1
Costume.SetAddress        →  AvatarBodySet / AvatarWeaponSet (어드레서블)
Costume.CostCurrencyType  →  Currency.ID                   (미사용)

Costume.ID   ←  Reward.TargetID (RewardType=Item)   ←  ShopGoods
```

## 9. 검증 규칙

| # | 항목 | 분류 |
|---|---|---|
| 1 | `Costume.ID` 가 `Item` 에 존재하고 `SubCategory = Costume` 인가 | 오류 |
| 2 | `SubCategory = Costume` 인 `Item` 에 `Costume` 행이 있는가 | 오류 |
| 3 | `IsDefault` 인 바디 코스튬이 **정확히 1개**인가 | 경고 (`CostumeCatalog`) |
| 4 | `IsDefault` 인 행이 `Body` 가 아닌가 | 경고 (`CostumeCatalog`) |
| 5 | `CostumeType = Weapon` 인데 `WeaponType` 이 비었는가 | 오류 (어떤 무기에도 보이지 않는다) |
| 6 | `SetAddress` 가 비었거나 어드레서블에 없는가 | 부트 에러 로그 (`AvatarCatalog`) |
| 7 | `SetAddress` 의 세트 종류가 `CostumeType` 과 맞는가 | 부트 에러 로그 (구상 타입으로 로드한다) |

## 10. 미결 / 다음 작업

- **`CostCurrencyType` / `CostValue` 가 죽은 컬럼이다** — 가격은 `ShopGoods` 가 정한다. 값이 서로 다르게 적혀도 아무 일이 없으므로 컬럼을 지우거나 한쪽으로 정리해야 한다.
- **`Acquisition` 문구와 실제 획득 경로가 다르다** — 요술봉은 "히드라 처치"라고 적혀 있으나 그런 몬스터도 드랍도 없고, 실제로는 상점에서 판다.
- **코스튬이 2종뿐이다** — 무기 코스튬은 쌍검용 하나다.
- **`CostumeInfoPresenter` 머리 주석이 낡았다** — "서버 저장은 아직 없다"고 적혀 있으나 실제로는 창을 닫을 때 저장한다.
