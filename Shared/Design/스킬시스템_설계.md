## 1. 개요

### 1.1 프로젝트 전제

| 항목 | 값 |
|---|---|
| 시점 | 2D 탑다운 |
| 장르 | 핵앤슬래시 (미니 디아블로 스타일) |
| 플레이 | 싱글플레이, 단일 캐릭터 |
| 조작 | 자동 조준 · 자동 전투 |
| 자원 | **없음.** 마나·탄약 제약을 두지 않고 쿨타임만으로 제약한다 |

직업 개념이 없다. **장착한 무기가 그 순간의 스킬 구성을 결정한다** (`무기마스터리시스템_설계.md`).

### 1.2 설계 원칙

1. **판정은 로직이 소유하고 애니메이션은 연출만 한다.** 모션이 잘려도 데미지는 누락되지 않는다.
2. **탐색은 스킬이 한 번만 한다.** `SkillEffect` 에는 탐색 컬럼이 없다.
3. **테이블 원본은 절대 수정하지 않는다.** 모디파이어는 리졸브 사본에만 적용된다.
4. **모디파이어는 슬롯 번호가 아니라 이름(`ParamKey`)으로 지목한다.**
5. **조건은 스킬이 아니라 효과에 건다.** 스킬 단위 조건은 시전 자체를 막아버린다.
6. **코드는 "어떻게", 테이블은 "얼마나".** 밸런싱 대상이 아닌 값은 코드 상수로 둔다.

### 1.3 테이블 구성

`Skill.xlsx` 한 파일에 시트 6개 + enum 블록이 들어 있다.

| 시트 | 컬럼 | 현재 행 수 | 역할 |
|---|---|---|---|
| `#Skill` | 21 | 20 | 스킬 정의. 발동 조건과 탐색 |
| `#SkillEffect` | 13 | 24 | 효과 정의. 실제로 일어나는 일 |
| `#SkillParamDef` | 6 | 45 | `EffectParam_1~5` 의 의미 정의 |
| `#SkillModifier` | 11 | 3 | 스킬·효과 값의 변형 규칙 |
| `#Projectile` | 6 | 2 | 투사체 |
| `#Summon` | 15 | 1 | 소환물 |
| `#Buff` | 12 | 7 | 버프 / 디버프 |

`#ParamMatrix` 는 `SkillParamDef` 를 가로로 뒤집은 **작업용 참조 뷰**이며 변환 대상이 아니다.

### 1.4 현재 데이터 현황

문서만 보고 데이터 양을 오해하지 않도록 명시한다.

| 무기 | 평타 | 액티브 | 패시브 |
|---|---|---|---|
| 쌍검 (`DualBlades`) | 구현 | 2종 (콤보 3타·5타 발동) | 2종 (스파크 소환 포함) |
| 룬소드 (`RuneSword`) | 구현 | **행만 있고 내용 비어 있음** | **비어 있음** |
| 석궁 (`CrossBow`) | 구현 (투사체) | **비어 있음** | **비어 있음** |
| 쌍권총 (`DualPistols`) | 구현 | **비어 있음** | **비어 있음** |

그 외: 몬스터 스킬 4종(근접·원거리·캐스팅·오크장군), 보스 전멸기 1종, 소환물 스킬 1종.

**실질적으로 쌍검만 완성돼 있고 나머지 3무기는 평타와 빈 껍데기 행만 있다.** `Skill_RuneSword_Active_01` 처럼 `EffectID` 가 비어 있는 행은 시전해도 아무 일도 일어나지 않는다.

### 1.5 참조 관계

```
WeaponMastery.NormalAttackSkill ─┐
SkillTreeNode.Option(SkillGrant) ─┼─→ Skill.ID
MonsterSkillSet.SkillID          ─┤
BossMonsterPhase.PhaseSkillID    ─┤
Summon.SkillID_1 / _2            ─┘

Skill.EffectID_01 / _02  ─→ SkillEffect.ID
SkillEffect.ChainEffectIDs[] ─→ SkillEffect.ID          (연쇄)
SkillEffect.EffectParam(RefID) ─→ Projectile / Summon / Buff
Projectile.HitEffectID_1 / _2 ─→ SkillEffect.ID
Buff.EffectID_01 / _02        ─→ SkillEffect.ID

Option(Modifier) ─→ SkillModifier.ID ─→ Scope_* 로 대상 지목
```

### 1.6 ID 명명 규칙

| 소유자 | 형식 | 실제 예 |
|---|---|---|
| 무기 마스터리 | `Skill_{WeaponType}_{Attack \| Active_NN \| Passive_NN}` | `Skill_DualBlades_Active_01` |
| 몬스터 | `Skill_Monster_{종류}_{NN}` | `Skill_Monster_RangeAttack_01` |
| 보스 | `Skill_Monster_Boss_{이름}_{NN}` | `Skill_Monster_Boss_Doom_01` |
| 소환물 | `Skill_{소환물}_{동작}` | `Skill_SummonSpark_Attack` |

| 테이블 | 접두 | 예 |
|---|---|---|
| `SkillEffect` | `SE_` | `SE_DualBlades_Attack_Damage` |
| `SkillModifier` | `SKM_` | `SKM_DualBlades_Active_01_Ratio` |
| `Projectile` | `PJT_` | `PJT_CrossBow_Bolt` |
| `Summon` | `Summon_` | `Summon_Spark` |
| `Buff` | `BUFF_` | `BUFF_Stun` |

**ID 문자열을 파싱해 의미를 추출하는 로직은 만들지 않는다.** 명명은 사람이 읽기 위한 관례다.

## 2. Enum 정의

### 2.1 SkillCategoryTypes

| 값 | 의미 |
|---|---|
| `Normal` | 평타. **공속 배율을 받는 유일한 분류다** |
| `Active` | 눌러서 쓰거나 조건으로 발동하는 스킬 |
| `Passive` | 등록 즉시 1회 적용되는 상시 효과 |

> 구버전의 `Skill.IsBasicAttack` 컬럼은 없어졌다. 평타 판정은 `SkillCategory == Normal` 하나다 (`SkillRuntime.IsNormal`).

### 2.2 SkillCastingTypes — 시전 방식

| 값 | `CastingParam` 의 의미 | 단위 | 직접 시전 |
|---|---|---|---|
| `Instant` | 미사용 | ‒ | **가능** |
| `Casting` | CastTime | 초 | **가능** |
| `OnHit` | TriggerChance | 0~1 | 불가 (트리거) |
| `OnCombo` | ComboCount | 회 (정수) | 불가 (트리거) |
| `OnCrit` | TriggerChance | 0~1 | 불가 (트리거) |
| `OnDamaged` | TriggerChance | 0~1 | 불가 (트리거) |
| `OnLowHP` | HPThreshold | 0~1 | 불가 (폴링) |
| `OnKill` | TriggerChance | 0~1 | 불가 (트리거) |
| `Aura` | TickInterval | 초 | 불가 (주기 틱). `Cooldown` 무시 |
| `Passive` | 미사용 | ‒ | 불가 (등록 즉시 1회) |

> **직접 시전 가능한 것은 `Instant` 와 `Casting` 뿐이다** (`SkillContainer.IsDirectCastable`). 나머지는 `TryCast` 로 부를 수 없고 각자의 경로로만 발동한다.
>
> | 발동 경로 | 호출자 |
> |---|---|
> | `OnHit` / `OnCrit` | `SkillEffectApplier` 가 `OnHitTrigger=TRUE` 효과 적중 시 |
> | `OnCombo` | 평타가 **실제로 적중**했을 때 (`NotifyNormalAttackHit`) |
> | `OnDamaged` | 피격 시. `OnHitTrigger` 와 무관 |
> | `OnKill` | 대상 사망 시. 수단 무관, 처치 수만큼 호출 |
> | `OnLowHP` | `SkillContainer` 가 `LOWHP_CHECK_INTERVAL`(0.5초)마다 폴링 |
> | `Aura` | `SkillContainer` 가 `CastingParam` 주기로 스킬 전체를 재실행 |
> | `Passive` | `Register` 시점에 `SkillExecutor.ApplyPassive` 1회 |

모든 확률·비율은 **0~1 배율**이다. 25%는 `0.25` 다.

### 2.3 SkillApplyTarget — 탐색 진영

| 값 | 의미 |
|---|---|
| `Self` | 자신. **탐색하지 않는다** (`ScanRange` 값과 무관) |
| `Enemy` | 적 진영. 시전자가 자동으로 빠진다 |
| `Friendly` | 아군. **시전자를 포함한다** (자힐·자버프) |
| `All` | 전부 |

타겟 불가 상태(무적 등)는 진영과 무관하게 모든 탐색에서 빠진다.

### 2.4 SkillScanTypes — 탐색 형태

| 값 | `ScanRange` | `ScanParam` |
|---|---|---|
| `Circle` | 반경 | 미사용 |
| `Sector` | 반경 | 각도(도) |
| `Line` | 길이 | 폭 |
| `Target` | 사거리 | 최대 대상 수 |

**대상 수 제한은 `Target` 전용이다.** 범위 공격(`Circle`/`Sector`/`Line`)은 범위 안을 전부 타격한다. `Target` 탐색만 가까운 순으로 정렬된다.

### 2.5 SkillEffectTypes

| 값 | 하는 일 |
|---|---|
| `Damage` | 피해 |
| `Heal` | 회복 |
| `Buff` | 버프/디버프 부여 |
| `StatChange` | 스탯 직접 변경 (한시 또는 영구) |
| `Projectile` | 투사체 발사 |
| `Summon` | 소환물 생성 |
| `Force` | 밀기/당기기 |
| `CooldownReduce` | 쿨타임 회복 |
| `BuffConsume` | 버프 스택 소모 (조건 게이트) |

### 2.6 SkillEffectOrigin — 효과를 받는 주체

`None` / `Caster` / `Target` / `Attacker` / `Victim` / `Owner` / `Location`

`Location` 은 대상이 아니라 **좌표**에 적용한다. 시전 시점에 좌표를 못 박고, 발동 시점에 그 좌표 기준으로 다시 탐색한다.

### 2.7 SkillModifierScope

`None` / `Skill` / `Effect` / `Projectile` / `Summon` / `Buff`

### 2.8 ModifierOperator

`None` / `Replace` / `Append` / `Set` / `Add` / `Ratio`

### 2.9 ParamDefValueTypes

`None` / `Float` / `Int` / `Bool` / `SkillID` / `EffectID` / `ProjectileID` / `SummonID` / `BuffID` / `StatID` / `StatDetailID` / `ForceType`

### 2.10 ForceType

`None` / `Push` / `Pull`

### 2.11 SummonAIType

`None` / `Stationary` / `Follow` / `Chase` / `Wander` / `Orbit`

**여섯 종 전부 구현되어 있다** (`GamePlay/Unit/AI/Behavior/Summon/`). `Stationary` 만 전용 비헤이비어 없이 제자리에 머문다.

### 2.12 BuffStackPolicy

| 값 | 의미 |
|---|---|
| `Refresh` | 같은 버프 재부여 시 지속시간 갱신 |
| `Independent` | 인스턴스를 따로 유지 (DoT 다중 스택) |
| `Extend` | 남은 시간에 더한다 |
| `Ignore` | 이미 걸려 있으면 무시 |

### 2.13 ActionBlockType

`None` / `Move` / `Turn` / `Attack` / `Cast`

`Buff.BlockFlags` 가 배열로 갖는다 (`Move;Turn;Attack;Cast` 형태로 기입).

## 3. Skill 테이블 (21컬럼)

### 3.1 컬럼 정의

| 컬럼 | 타입 | Mod | 설명 |
|---|---|---|---|
| `ID` | `!Skill` (PK) | ‒ | `Skill_` 접두 |
| `Name` | `!string` | ‒ | 표시명 |
| `Desc` | `!string` | ‒ | 설명 |
| `Icon` | `!string` | ‒ | 아이콘 주소 |
| `SkillCategory` | `!SkillCategoryTypes` | ‒ | Normal / Active / Passive |
| `AnimName` | `!string` | ○ | **애니메이터 트리거명.** 클립명이 아니다 |
| `AnimLength` | `!float` | ○ | 클립의 실제 길이(초). 공속 1.0 기준 |
| `CastingType` | `!SkillCastingTypes` | ‒ | 판별 컬럼. `CastingParam` 의 의미를 결정 |
| `CastingParam` | `!float` | ○ | 2.2절 표에 의미 정의 |
| `ApplyTarget` | `!SkillApplyTarget` | ‒ | 탐색 진영 |
| `ScanType` | `!SkillScanTypes` | ‒ | 판별 컬럼. `ScanParam` 의 의미를 결정 |
| `ScanRange` | `!float` | ○ | 사거리 / 반경 / 길이 (형태 공통) |
| `ScanParam` | `!float` | ○ | 2.4절 표에 의미 정의 |
| `Cooldown` | `!float` | ○ | 재사용 대기시간(초). 평타는 공격 주기 |
| `EffectID_01` | `!SkillEffect` | ‒ | 효과 슬롯 1 |
| `EffectID_02` | `!SkillEffect` | ‒ | 효과 슬롯 2 |
| `SkillVFX` | `!string` | ‒ | 시전 연출. 시전 위치에 1회 재생 |
| `SkillVFXFacing` | `!bool` | ‒ | TRUE면 시전자 조준 방향으로 회전시킨다 |
| `SkillVFXOffset` | `!float` | ‒ | 조준 방향으로 이만큼 앞에 낸다 |
| `SkillSFX` | `!string` | ‒ | 시전 사운드 |
| `BreakDamage` | `!float` | ‒ | 대상의 브레이크 게이지를 깎는 양. 0이면 브레이크에 관여하지 않는다 |

Mod 열의 ○는 `SkillModifier` 로 변경 가능한 컬럼을 뜻한다.

> **`AnimName` 은 애니메이터 트리거명이다** — 클립 이름이 아니라 `Animator` 의 트리거 파라미터 이름이며, 현재 존재하는 값은 `Attack` / `Skill` / `Hit` / `Die` 넷뿐이다. 오타를 내면 아무 로그 없이 모션만 나오지 않는다.
>
> `AnimName` 이 비면 모션 없이 효과만 나간다. 콤보 발동형 액티브 스킬(`Skill_DualBlades_Active_01`)이 이 방식이다 — 평타 모션 위에 효과만 얹는다.

> **`SkillVFXFacing` / `SkillVFXOffset`** — 방향성 연출용이다. `Facing` 은 범위 판정·인디케이터와 같은 +X 기준 공식을 쓰므로 셋의 방향이 어긋나지 않는다. VFX는 시전자에게 부착되지 않고 그 자리에 한 번 터진다.

### 3.2 판별 컬럼은 2개뿐이다

- `CastingType` → `CastingParam` 의 의미
- `ScanType` → `ScanParam` 의 의미

나머지 19개 컬럼은 전 행에서 의미가 고정된다.

### 3.3 ScanRange = 0 규칙

`ScanRange = 0` 은 세 가지 경우에만 유효하다.

| 경우 | 해석 |
|---|---|
| `ApplyTarget = Self` | 탐색하지 않는다 |
| 소환물이 소유한 스킬 | 소환 시 받은 `Effect.Radius` 를 상속한다 |
| 그 외 | 잘못된 데이터 — 아무도 맞지 않는다 |

두 번째 규칙이 장판 크기의 정의처를 하나로 유지한다. 이 규칙이 없으면 장판 크기가 `SkillEffect.Radius` 와 소환물 스킬의 `ScanRange` 두 곳에 존재하게 되고, "장판 크기 +20%" 옵션이 한쪽만 변경해 비주얼과 판정이 어긋난다.

### 3.4 EffectID 슬롯

`EffectID_01` / `_02` 는 **순서에 의미가 없다.** 실행 시점은 각 효과의 `EffectTime` 이 결정한다.

비어있지 않은 칸만 수집하므로 `_01` 이 비고 `_02` 만 차 있어도 동작하지만, 데이터 정리상 `_01` 부터 채운다.

3개 이상이 필요하면 `SkillEffect.ChainEffectIDs` 로 연쇄하거나 `Append` 모디파이어로 붙인다.

`EffectID_02` 와 `ChainEffectIDs` 는 다르다. **`_02` 는 발동 시 무조건 실행되고, `ChainEffectIDs` 는 그 효과가 적중했을 때만 실행된다.**

### 3.5 브레이크 (`BreakDamage`)

엘리트·보스 전용의 무력화 게이지다. 일반 몬스터에는 컴포넌트 자체가 붙지 않는다 (`MonsterPool.CreateItem` 이 등급을 보고 결정).

```
게이지 최대치 = 대상의 Stat_MaxBreakGauge
피격 1회      = 공격한 스킬의 Skill.BreakDamage 만큼 차감
0 도달        = BUFF_BreakStun 부여 (기절 + 받는 피해 증가)
브레이크 중   = 추가 BreakDamage 무시 + 게이지 회복
```

- 일반 브레이크 유지시간은 `SE_Monster_Break_Stun_Buff`(5초), 보스 패턴 파훼는 `SE_Boss_Break_Stun_Buff`(10초)로 **효과 테이블이 소유한다.** 코드 상수가 아니다.
- 현재 값: 평타 `BreakDamage = 1`, 액티브 `5`. 몬스터 스킬은 전부 0이다(히어로는 브레이크 대상이 아니다).
- 보스는 페이즈 기믹을 파훼당했을 때 게이지와 무관하게 강제 브레이크된다 (`MonsterBreak.NotifyForcedBreak`, `몬스터시스템_설계.md`).

## 4. 스킬 실행 파이프라인

이 장이 타이밍 설계의 핵심이다.

### 4.1 판정은 로직이 소유한다

**애니메이션 진행률로 타격을 판정하지 않는다.** 고속·프레임 드랍에서 판정이 유실되기 때문이다. 로직 타이머가 발동 시점을 소유하고 애니메이션은 따라오기만 한다.

지연은 코루틴이 아니라 **`SkillContainer` 의 예약 큐**가 처리한다. 동시에 수십 개 스킬이 도는 방치형에서 코루틴은 할당 부하가 된다.

| `PendingKind` | 용도 |
|---|---|
| `Effect` | 효과 1개를 통째로 적용 |
| `DamageHit` | 다단히트의 2타 이후 |
| `HealTick` | 지속 회복의 2틱 이후 |
| `ProjectileShot` | 연속 발사의 2발 이후 |
| `RemoveModifier` | 한시 `StatChange` 회수 |

### 4.2 계산식

```
useSpeed     = (평타면 Stat_AtkSpeed, 그 외 1.0)
cycleTime    = Cooldown / useSpeed
animSpeed    = clamp(useSpeed, ANIM_SPEED_MIN, ANIM_SPEED_MAX)
animPlayTime = AnimLength / animSpeed

actionTime   = AnimLength <= 0  → 0
               Cooldown  <= 0  → animPlayTime
               그 외            → min(animPlayTime, cycleTime)

효과 발동 지연 = extraDelay + actionTime × EffectTime
```

`extraDelay` 는 캐스팅 시간처럼 사이클 앞에 붙는 고정 지연이다.

> **`actionTime` 의 3분기를 지켜야 한다** — `min` 을 무조건 적용하면 `Cooldown = 0` 인 패시브에서 모든 효과가 즉시 터진다. `AnimLength = 0` 이면 모션이 없으므로 즉시 발동이 맞다.

### 4.3 공속 영향 범위

**공속은 평타(`SkillCategory = Normal`)에만 적용된다.**

| 대상 | 공속 영향 |
|---|---|
| 평타의 쿨타임·모션 | ○ |
| 액티브/패시브의 쿨타임·모션 | ✕ |
| 캐스팅 시간(`CastingParam`) | ✕ |
| 다단히트 간격(`HitInterval`) | ✕ |
| 버프 지속시간·틱 간격 | ✕ |

평타가 공속을 받지 못하면 공속 스탯이 무의미해지고, 스킬까지 받으면 공속 하나로 모든 딜이 배가 된다.

> `Stat_AtkSpeed` 가 0 이하면 `cycleTime` 이 0으로 나뉘어 붕괴한다. `SkillRuntime.GetUseSpeed` 가 에러 로그를 남기고 1.0으로 폴백하지만, **데이터를 고쳐야 한다** (`StatDetail_AtkSpeed_Base` 필수).

### 4.4 시전 흐름

```
TryCast(id)
  ├ 사망 / IsSkillBlocked(버프) / IsInAction(모션 중) / 쿨타임 → 실패
  └ SkillExecutor.Execute(id, caster, useSpeed)
       ├ Resolve(id)            리졸브 사본 획득. Replace 반영
       ├ SkillCastEvent 발행
       ├ 코드 스킬 등록됨?      → SkillContainer.BeginBehavior 로 위임, 종료
       ├ CastingType=Casting?   → BeginCasting(CastingParam) + VFX
       │                           (모션은 캐스팅이 끝난 순간에 낸다)
       └ 그 외                  → 모션 + VFX/SFX 재생
       └ scheduleEffects()      탐색 1회 → 효과별 지연 예약
  └ beginAction(actionTime)     이 동안 조준 고정 + 다른 스킬 시전 불가
  └ StartCooldown(useSpeed)
```

**한 번에 하나씩이다.** 모션이 도는 동안(`IsInAction`) 다른 스킬을 겹쳐 시전하지 않는다.

### 4.5 세 가지 대상 확정 방식

탐색은 시전 시점에 1회만 하지만, 그 결과를 쓰는 방식이 세 가지다.

| 방식 | 조건 | 동작 |
|---|---|---|
| **스냅샷** | 기본 | 시전 시점 탐색 결과를 그대로 들고 발동 시점에 적용 |
| **좌표 고정** | `EffectOrigin = Location` | 시전 시점 좌표를 못 박고, 발동 시점에 그 좌표 반경(`ScanParam`)으로 재탐색 |
| **재탐색** | `CastingType = Casting` | 대상을 싣지 않고 발동 시점에 시전자 기준으로 다시 탐색 |

- **캐스팅형이 재탐색인 이유** — 선딜 동안 회피가 성립해야 한다. 캐스팅 중 범위를 벗어난 적은 맞지 않고, 뒤늦게 들어온 적은 맞는다.
- **좌표 고정의 중심** — 조건 발동형이면 유발한 대상의 좌표를 그대로 쓴다. 여기서 재탐색하면 방금 그 타격으로 죽은 대상이 빠져 엉뚱한 위치에 터진다. 지정이 없으면 탐색 결과 중 최근접(`scanned[0]`)이다.
- **대상이 없으면 좌표를 잡을 수 없다.** 좌표 고정 효과는 통째로 건너뛴다(헛시전).
- 캐스팅 중에는 **조준 방향이 잠긴다.** `Line`/`Sector` 가 타겟을 따라 휘어 범위를 벗어난 뒤 명중하는 것을 막는다.

### 4.6 캐스팅

```
BeginCasting(castTime)   이동·스킬 차단 + 조준 고정. 모션은 아직 내지 않는다
   ↓ castTime 경과
tickCastMotion()         공격 모션을 낸다 + 모션 길이만큼 액션 락
   ↓ 효과 발동
EndCasting()             차단 해제
```

**모션을 시작 시점에 내지 않는 이유** — 시작에 내면 트리거가 캐스팅 내내 살아 있다가 취소 시에도 공격 모션이 나가 버린다. 캐스팅 동안 시전 자세를 유지하다가 종료 순간에 공격 모션이 나가야 한다.

취소(`CancelCasting`)는 예약된 발동을 제거하고 차단을 해제한다. **쿨타임은 그대로 소모된다.**

### 4.7 캔슬 처리

넉백 등 경직이 발생하면 `CancelPendingEffects()` 가 예약된 모든 지연 효과를 취소한다. 이미 발동한 효과는 되돌리지 않는다.

### 4.8 VFX / SFX 정책

| 구분 | 정책 |
|---|---|
| `Skill.SkillVFX` / `SkillSFX` | **Replace** — 새 사이클이 시작되면 이전 것을 밀어낸다 |
| `SkillEffect.EffectVFX` / `EffectSFX` | **Additive** — 타격마다 개별 재생 |

### 5.3 이름 짓기 = 밸런싱 설계

모디파이어는 `ParamKey` 이름으로 매칭되므로, 이름을 짓는 순간 옵션의 적용 범위가 결정된다.

| 파라미터 | 이름 | 의도 |
|---|---|---|
| 투사체 개수 | `Count` | 둘 다 `Count` → "모든 Count +1"이 투사체와 소환물에 함께 적용 |
| 소환물 개수 | `Count` | |
| 다단 타격 횟수 | `HitCount` | 일부러 분리 → 투사체 증가 옵션이 다단히트를 늘리지 않는다 |

### 5.4 EffectOrigin — 주체 결정

| 상황 | Origin |
|---|---|
| 일반 공격·스킬의 데미지 | `Target` |
| 자기 버프 / 패시브 / 소환 | `Caster` |
| OnDamaged 반사 | `Attacker` |
| OnHit 부가 효과 | `Victim` |
| 소환물이 주인에게 거는 효과 | `Owner` |
| 좌표에 터지는 효과 (장판·낙하 공격) | `Location` |

소환물이 시전자인 경우 `InheritStatType` / `InheritStatRatio` 로 상속된 스탯을 사용한다.

### 5.5 ChainEffectIDs — 연쇄

부모 효과가 **적중했을 때만** 실행된다.

- 연쇄 효과는 `EffectTime` 을 무시하고 부모 발동 시점에 즉시 발동한다. 착탄·연쇄에는 기준이 될 `actionTime` 이 없다.
- 순환은 깊이 `CHAIN_DEPTH_LIMIT`(5)에서 끊는다.
- **적중 개념이 없는 효과는 "성공"을 적중으로 간주한다.** `BuffConsume` 은 스택 소모 성공 시, `Buff` 는 `Chance` 판정 통과 시 연쇄가 실행된다. 이 규칙 덕분에 `ChainEffectIDs` 가 조건 분기로도 쓰인다 (5.8절).
- **`Force` 는 반드시 `ChainEffectIDs` 로 연결한다.** `EffectID_02` 에 두면 공격이 빗나가도 대상이 밀려난다.

실제 예:

```
SE_DualBlades_Active_01_Damage   Damage / Target / Ratio 2.5
   └ ChainEffectIDs = [ SE_Common_Stagger_Buff ]     ← 맞았을 때만 경직
```

### 5.6 OnHitTrigger

이 효과의 적중이 온히트 계열을 발동시키는가를 결정한다. 기본값 FALSE.

TRUE일 때 발동하는 것:
- `CastingType = OnHit` / `OnCrit` 스킬
- `Stat_LifeOnHit` (적중 시 체력 회복)

`OnCombo` / `OnKill` / `OnDamaged` 는 이 플래그와 무관하다.

**다단히트(`HitCount > 1`) 효과에는 TRUE를 넣지 않는다.** 타격 횟수만큼 온히트가 발동해 흡혈과 부가 효과가 폭주한다.

현재 데이터에서 TRUE인 것은 무기 평타의 데미지 효과 4종뿐이다.

### 5.7 중복 히트 규칙

컬럼 없이 코드 규칙으로 처리한다.

```
① 투사체 1 인스턴스는 같은 대상을 1회만 타격한다
   (Pierce는 "서로 다른 대상"의 관통 횟수)
② Damage 효과 1회 실행은 같은 대상에게 1회만 적용된다
③ HitCount 다단히트는 ①②의 예외 — 의도된 반복이다
④ 서로 다른 효과 / 투사체 / 소환물은 각각 독립 적용된다
```

### 5.8 조건 분기 — BuffConsume + ChainEffectIDs

조건을 스킬 단위로 두면 "조건을 만족하지 못하면 스킬 자체를 못 쓴다"가 되어버린다. 대부분의 요구는 "스킬은 정상적으로 쓰되 조건을 만족할 때만 추가 효과가 붙는다"이다.

`BuffConsume` 을 게이트로 두고 `ChainEffectIDs` 로 본 효과를 연결한다.

```
EffectID_01 = SE_XXX_DMG          ← 데미지. 항상 실행
EffectID_02 = SE_XXX_CONSUME      ← 조건 분기 시작

SE_XXX_CONSUME   BuffConsume / Caster
  RefID = BUFF_POWER / Count = 1
  ChainEffectIDs = [ SE_XXX_RESET ]   ★ 소모 성공 시에만

SE_XXX_RESET     CooldownReduce / Caster
  TargetSkillID = (자기 스킬) / Ratio = 1.0
```

버프가 없으면 연쇄가 끊긴다. 데미지는 정상적으로 들어가고 쿨타임도 정상적으로 돈다.

### 5.9 CooldownReduce 계산

```
회복량 = (대상의 최대 쿨타임 × Ratio) + FlatValue
남은쿨 = max(0, 남은쿨 - 회복량)
```

| 항목 | 규칙 |
|---|---|
| `EffectOrigin` | Caster 고정 |
| `Ratio` 기준 | **최대 쿨타임.** 남은 쿨타임이 아니다 |
| 대상이 쿨다운 중이 아님 | 무시한다 |
| `TargetSkillID` | 필수. 자기 자신 지정 가능 |

## 6. Projectile 테이블 (6컬럼)

투사체는 "발사되어 날아가 맞고 끝나는 것"이다. 돌아오거나 머무는 물체는 투사체가 아니라 소환물이다.

| 컬럼 | 타입 | Mod | 설명 |
|---|---|---|---|
| `ID` | `!Projectile` (PK) | ‒ | `PJT_` 접두 |
| `PrefabPath` | `!string` | ‒ | 프리팹 주소 |
| `Pierce` | `!int` | ○ | 관통 횟수. 0 = 첫 적중에 소멸 |
| `ExplodeRadius` | `!float` | ○ | 착탄 폭발 반경. 0 = 충돌 대상 1체만 |
| `HitEffectID_1` | `!SkillEffect` | ‒ | 적중 시 발동할 효과 |
| `HitEffectID_2` | `!SkillEffect` | ‒ | |

> **속도·수명·사거리·궤적은 테이블에 없다.** 전부 **프리팹의 `Projectile` 컴포넌트**가 소유하며, 이동 방식은 프리팹에 붙은 `ITrajectory` 구현(직선·유도·포물선)이 결정한다.
>
> 이유는 충돌 반경을 프리팹에 둔 것과 같다 — 투사체의 시각적 크기·속도감과 판정이 일치해야 하고, 둘의 출처가 나뉘면 어긋난다. 테이블에는 **판정 결과에 해당하는 값만** 남겼다.
>
> 대신 이 값들은 **모디파이어로 바꿀 수 없다.** "투사체 속도 +20%" 같은 옵션이 필요해지면 `SkillEffect` 의 `SpeedRate`(Param_5)를 쓴다 — 발사 시점에 배율로 전달된다.

발사 시 전달되는 값 (`ProjectileData`): 방향, 시작 위치, 시전자, 스킬 ID, 적중 효과, 타겟, 피격 반경, 속도 배율, 관통 수.

적중 효과의 `EffectTime` 은 0이다. 투사체에는 자기 사이클이 없다.

**현재 2종** — `PJT_CrossBow_Bolt`(관통 1), `PJT_Monster_Arrow`(관통 0).

## 7. Summon 테이블 (15컬럼)

### 7.1 컬럼 정의

| 컬럼 | 타입 | Mod | 설명 |
|---|---|---|---|
| `ID` | `!Summon` (PK) | ‒ | `Summon_` 접두 |
| `PrefabPath` | `!string` | ‒ | 프리팹 주소 |
| `ScaleByRadius` | `!bool` | ‒ | 프리팹을 소환 `Radius` 에 맞춰 자동 스케일. 장판 필수 |
| `AIType` | `!SummonAIType` | ‒ | 거동 패턴 |
| `DieWithOwner` | `!bool` | ‒ | 주인 사망 시 소멸 |

| `SkillID_1` | `!Skill` | ‒ | 소환물이 소유한 스킬 |
| `SkillID_2` | `!Skill` | ‒ | |
| `ActionInterval` | `!float` | ○ | 행동 간격(초). 0 = 소유 스킬의 `Cooldown` 이 결정 |
| `FollowDistance` | `!float` | ○ | 추종 유지 거리 / 배회 반경 / 공전 반경 |
| `InheritStatType_1` | `!Stat` | ‒ | 주인 스탯 상속 대상 |
| `InheritStatRatio_1` | `!float` | ○ | 상속 비율 |
| `InheritStatType_2` | `!Stat` | ‒ | |
| `InheritStatRatio_2` | `!float` | ○ | |
| `MaxCount` | `!int` | ○ | 동시 존재 상한 |

### 7.2 AIType별 컬럼 사용

| AIType | ReturnDistance | FollowDistance | 사례 |
|---|---|---|---|
| `Stationary` | ‒ | ‒ | 포탑, 장판 |
| `Follow` | ‒ | 추종 거리 | 검기, 드론 |
| `Chase` | 복귀 임계 | 복귀 위치 | 늑대 |
| `Wander` | ‒ | 배회 반경 | 펫 |
| `Orbit` | ‒ | 공전 반경 | 스파크 |

`SkillID_1` 이 비어 있는 소환물은 아무것도 하지 않는다.

### 7.3 개수 — Count와 MaxCount

| 값 | 위치 | 의미 |
|---|---|---|
| `Count` | `SkillEffect.EffectParam_2` | 1회 소환 시 생성되는 개수 |
| `MaxCount` | `Summon.MaxCount` | 동시에 존재할 수 있는 상한 |

`Count = 2`, `MaxCount = 3` 이면 두 번 시전해도 3마리가 유지된다. 초과분은 **가장 오래된 것부터 소멸**시킨다 (`SummonManager`, 주인×소환종류 키로 관리).

개수 증가 옵션은 `Count` 를 건드린다. 정의처가 `SkillEffect` 하나뿐이라 모디파이어가 어긋날 여지가 없다.

### 7.4 스탯 상속

```
소환물.Stat_Atk = 주인.Stat_Atk × InheritStatRatio_1   (InheritStatType_1 = Stat_Atk)
```

상속은 항상 **실시간 반영(Live)** 이다. 주인의 스탯이 변하면 소환물도 즉시 따라간다 (`StatContainer.Version` 비교로 감지). 단, 소환물이 스킬을 시전하는 순간의 데미지는 시전 시점 스냅샷을 쓴다 (11장).

상속 슬롯이 2개뿐이라 공속을 상속하지 못하는 경우가 많다. **소환물 스킬은 `SkillCategory = Active` 로 만든다** — `Normal` 은 공속을 참조한다.

### 7.5 장판 구조

장판은 별도 개념이 아니라 **`AIType = Stationary` 소환물 + `CastingType = Aura` 스킬**의 조합이다.

```
스킬 (시전 조준용)
 └ SE_XXX_FIELD    Summon
     RefID    = Summon_XXX
     Radius   = 3.0        ★ 장판 크기의 유일한 정의처

    └ Summon_XXX           Stationary / ScaleByRadius = TRUE
        SkillID_1 = Skill_XXX_FieldTick

       └ Skill_XXX_FieldTick   Aura / Enemy / Circle
           CastingParam = 0.5  ← TickInterval
           ScanRange    = 0    ★ 소환 Radius 상속 (3.3절)
```

`Radius` 를 +20% 하면 판정 범위와 `ScaleByRadius` 비주얼이 함께 커진다.

> **`CastingTypes.Aura` 는 "오라 시스템"이 아니다.** `AuraContainer` 같은 별도 구조는 없고, `SkillContainer` 가 주기마다 스킬 전체를 재실행할 뿐이다. 실체가 있는 지속 효과는 전부 위 소환물 구조로 만든다.

### 7.6 현재 데이터

**`Summon_Spark` 1종뿐이다.** `Orbit` / 공전 반경 1.0 / 최대 3기 / `Stat_Atk` 100% 상속 / 주인 사망 시 소멸. `Skill_DualBlades_Passive_02`(패시브)가 3기를 소환하고, 각 스파크가 `Skill_SummonSpark_Attack` 으로 0.25초마다 전기 빔을 쏜다.

이 스킬은 **코드 스킬(`ISkillBehavior`)로 구현된 유일한 사례**이기도 하다 (4장·12장).

## 8. Buff 테이블 (12컬럼)

### 8.1 CC를 별도 타입으로 두지 않는다

| 기존 CC 개념 | 실제 정체 | 이 설계에서의 처리 |
|---|---|---|
| 슬로우 | 이동속도 -30% — 순수 스탯 변화 | Buff + `EffectID`(StatChange) |
| 기절 / 속박 / 침묵 | 행동 가능 여부 플래그 | Buff + `BlockFlags` |
| 넉백 | 지속시간 없는 즉시 위치 이동 | `EffectType.Force` |

감전 = `Move` 차단 + 초당 데미지, 빙결 = `Move` + `Attack` + 받는 피해 증가처럼 **CC enum으로는 불가능한 조합**이 자연스럽게 나온다.

### 8.2 컬럼 정의

| 컬럼 | 타입 | Mod | 설명 |
|---|---|---|---|
| `ID` | `!Buff` (PK) | ‒ | `BUFF_` 접두 |
| `Name` | `!string` | ‒ | 표시명 |
| `Desc` | `!string` | ‒ | 설명 |
| `Icon` | `!string` | ‒ | UI 표시 |
| `IsDebuff` | `!bool` | ‒ | 정화 대상 구분 |
| `StackPolicy` | `!BuffStackPolicy` | ‒ | Refresh / Independent / Extend / Ignore |
| `TickInterval` | `!float` | ○ | 0 = 지속형 / >0 = 주기 발동형 (DoT·HoT) |
| `BlockFlags` | `!ActionBlockType[]` | ‒ | 행동 제한. `Move;Turn;Attack;Cast` |
| `IgnoreImmune` | `!bool` | ‒ | 면역·무적을 무시하고 부여한다 |
| `DebuffMotion` | `!bool` | ‒ | 피격 모션(경직 연출)을 재생하는가 |
| `EffectID_01` | `!SkillEffect` | ‒ | 유지 중 적용되는 효과 |
| `EffectID_02` | `!SkillEffect` | ‒ | |

> **`Duration` 도 `StackMax` 도 Buff 테이블에 없다.** 부여하는 `SkillEffect` 가 정한다 (8.3).

`BlockFlags` 자체가 효과이므로 기절 계열은 `EffectID` 가 비어 있어도 된다.

### 8.3 지속시간과 중첩의 정의처

| 값 | 위치 | 이유 |
|---|---|---|
| 지속시간 | `SkillEffect` Buff `Param_2`(`Duration`) | 같은 버프를 스킬마다 다른 시간으로 부여할 수 있어야 한다 |
| 최대 중첩 | `SkillEffect` Buff `Param_3`(`StackMax`) | 모디파이어로 중첩 수를 변경하려면 여기 있어야 한다 |
| 효과 배율 | `SkillEffect` Buff `Param_4`(`Ratio`) | 같은 버프를 강하게/약하게 거는 경로 |

런타임 호출은 `BuffContainer.Apply(id, duration, stackMax, source, sourceSkill, valueScale)` 이다. `valueScale` 이 `Ratio` 에 해당하며, 버프가 참조하는 효과의 수치에 곱해진다.

같은 버프를 두 스킬이 다른 지속시간으로 쓰는 실제 사례가 있다 — `BUFF_BreakStun` 은 일반 몬스터에 5초, 보스 패턴 파훼에 10초다.

### 8.4 DoT는 별도 개념이 아니다

```
BUFF_XXX   TickInterval = 0.5, StackPolicy = Independent
 └ SE_XXX_TICK   Damage / Ratio 0.20

→ 0.5초마다 ATK × 0.20. 3중첩이면 독립 인스턴스 3개가 각각 틱을 발생시킨다.
```

`StackPolicy = Independent` 때문에 `BuffContainer` 는 리스트를 1차 저장소로 쓰고 ID→대표 인스턴스 딕셔너리를 따로 둔다.

### 8.5 현재 버프 7종

| ID | 성격 | BlockFlags | 비고 |
|---|---|---|---|
| `BUFF_Stagger` | 경직 | Move, Attack, Cast | 0.4초. 피격 반응 |
| `BUFF_Stun` | 기절 | Move, Turn, Attack, Cast | `DebuffMotion` |
| `BUFF_BreakStun` | 브레이크 기절 | Move, Turn, Attack, Cast | `IgnoreImmune` + 받는 피해 증가 |
| `BUFF_DamageTakenUp` | 취약 | ‒ | `StatDetail_DamageTakenAmp_Add` +0.3 |
| `BUFF_Invincible` | 무적 | ‒ | 피해 무효. 보스 전환 연출에 쓴다 |
| `BUFF_CombatRune` | 전투 룬 | ‒ | 공격력·방어력 각 +10%. 필드 드랍 |
| `BUFF_DualBlades_AtkSpeedUp` | 연속공격 | ‒ | 공속 증가. `Independent` 중첩 |

> **`IgnoreImmune` 가 필요한 이유** — 보스는 페이즈 전환 중 `BUFF_Invincible` 상태다. 기믹을 파훼했을 때 주는 기절이 무적에 막히면 파훼 보상이 사라진다.

## 9. SkillModifier 테이블 (11컬럼)

### 9.1 컬럼 정의

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!SkillModifier` (PK) | `SKM_` 접두 |
| `Scope` | `!SkillModifierScope` | 어느 테이블을 건드리는가 |
| `Scope_Skill` | `!Skill` | Scope = Skill 일 때 대상 |
| `Scope_Effect` | `!SkillEffect` | Scope = Effect 일 때 대상 |
| `Scope_Projectile` | `!Projectile` | Scope = Projectile 일 때 대상 |
| `Scope_Summon` | `!Summon` | Scope = Summon 일 때 대상 |
| `Scope_Buff` | `!Buff` | Scope = Buff 일 때 대상 |
| `ParamKey` | `!string` | 변경할 대상의 **이름**. 슬롯 번호가 아니다 |
| `Operator` | `!ModifierOperator` | Replace / Append / Set / Add / Ratio |
| `Value` | `!float` | 값 칸이 없는 부착처용 기본값 |
| `RefValue` | `!string` | Replace / Append / Set(참조) 의 교체·추가 대상 |

대상 컬럼을 Scope별로 분리한 이유 — 타입이 지정되므로 참조 실존이 자동 검증되고, `Scope` 와 대상 테이블이 어긋나는 사고가 구조적으로 막힌다.

### 9.2 ParamKey 해석 경로

`SkillModifierCatalog.Build()` 가 **부팅 시점에 한 번** 문자열을 슬롯로 굽는다 (`BakedModifier`). 런타임에는 조회 없이 분기만 한다.

```
Scope = Skill
  ① EffectID 인가?                → 효과 리스트 (Append 전용)
  ② Skill 명명 컬럼인가?          → 직접 접근
       ScanRange · Cooldown · AnimLength
  ③ SkillCastingTypes 이름인가?   → CastingParam
       CastTime · TriggerChance · HPThreshold · TickInterval · ComboCount
  ④ SkillScanTypes 이름인가?      → ScanParam
       Angle · Width · MaxTarget

Scope = Effect
  ① SkillEffect 명명 컬럼인가?    → 직접 접근 (EffectTime)
  ② SkillParamDef[EffectType]     → EffectParam_N
       Ratio · Count · RefID · Duration · Chance …

Scope = Projectile / Summon / Buff
  → 해당 시트의 명명 컬럼
```

`BakedTarget` 은 `None` / `Named` / `CastingParam` / `ScanParam` / `EffectParam` / `EffectList` 여섯 가지다.

> **`Scope = Projectile / Summon / Buff` 는 현재 동작하지 않는다.** 리졸브 사본은 **스킬과 효과만** 뜨고 이 세 시트는 원본 테이블을 그대로 읽는다. 세 시트의 컬럼을 직접 바꾸려면 원본을 건드려야 하므로 지원하지 않는다.
>
> 대신 **`Scope = Effect` + `ParamKey = RefID`** 로 "어떤 투사체/소환물/버프를 쓰는가"를 바꾸는 경로가 열려 있다 (9.4).

`ParamKey = EffectID` 는 슬롯 번호(`EffectID_01`)가 아니라 **효과 목록 전체**를 지칭하며 `Append` 만 허용된다.

### 9.3 Operator와 연산 순서

```
Replace → Append → Set → Add(전부 합산) → Ratio(전부 합산)

최종값 = (Base + ΣAdd) × (1 + ΣRatio)
```

- **`Replace` 는 반드시 최우선.** 스킬 자체가 교체된 뒤에 나머지가 적용되어야 교체된 스킬에 붙는 모디파이어가 유실되지 않는다.
- **`Append` 는 수치 연산보다 먼저.** 새로 붙은 효과에도 `Scope = Effect` 모디파이어가 닿아야 한다.
- `Ratio` 는 합연산 후 한 번 곱한다. +20%와 +30%가 붙으면 ×1.5다.
- `Set` 이 여러 개 충돌하면 마지막 값이 이긴다. **결과가 비결정적이므로 데이터 설계로 피한다.**

| Operator | 허용 대상 |
|---|---|
| `Add` / `Ratio` | Float / Int 파라미터만 |
| `Set` | 전부. 숫자는 `Value`, 참조·enum은 `RefValue` |
| `Replace` | Scope = Skill + `ParamKey` 공백 + `RefValue` 에 교체할 SkillID |
| `Append` | `ParamKey = EffectID` 전용. `RefValue` 에 추가할 SkillEffect |

**Append — 효과를 동적으로 붙인다**

스킬 행을 복제하지 않고 스킬 트리 노드·장비로 효과를 추가한다. 실제 사례:

```
SKM_DualBlades_Active_01_AppendAtkSpeedBuff
  Scope = Skill / Scope_Skill = Skill_DualBlades_Active_01
  ParamKey = EffectID / Operator = Append
  RefValue = SE_DualBlades_Active_01_AtkSpeedBuff
```

스킬트리 노드에 이 옵션을 찍으면 쌍검 콤보 스킬에 "연속공격" 공속 버프가 추가로 붙는다.

| 규칙 | 내용 |
|---|---|
| Set이 아닌 이유 | `EffectID_02` 가 차 있으면 덮어쓰고, 여러 옵션이 붙으면 마지막 하나만 남는다 |
| 리스트 | 리졸브 사본이 가변 리스트를 갖는다. 테이블은 2슬롯이지만 런타임은 무제한 |
| 중복 | 같은 효과가 두 번 Append 되면 누적된다 |
| `Value` | 사용하지 않는다 |
| 연쇄 | `ChainEffectIDs` 로 딸린 효과는 자동으로 따라온다 |
| 실행 순서 | 리스트 순서와 무관. 각 효과의 `EffectTime` 이 결정한다 |
| 제거 | 별도 연산자가 없다. 옵션이 빠지면 리졸브가 다시 계산되며 자연히 사라진다 |

### 9.4 참조 대상 교체

`ValueType` 이 참조·enum인 파라미터에 `Set` 을 걸면 참조 대상 자체가 교체된다.

| 원하는 변형 | 대상 / ParamKey | RefValue |
|---|---|---|
| 장판이 캐릭터를 따라다님 | `SE_..._FIELD` / `RefID` | 추종형 Summon ID |
| 화살이 화염 화살로 | `SE_..._PJT` / `RefID` | 다른 Projectile ID |
| 둔화가 속박으로 | `SE_..._SLOW` / `RefID` | 다른 Buff ID |
| 데미지 기준이 최대체력으로 | `SE_..._DMG` / `ScaleStat` | `Stat_MaxHp` |
| 넉백이 끌어당김으로 | `SE_..._FORCE` / `ForceType` | `Pull` |

### 9.5 값의 출처

`SkillModifier` 는 **"무엇을 어떻게 바꾸는가"만 정의하고, "얼마나"는 부착처가 정한다.**

```
SkillModifier   SKM_DualBlades_Active_01_Ratio   Effect / SE_..._Damage / Ratio / Ratio   ← 값 없음
Option          OPT_DMG_DualBlades_Active_01     Modifier → SKM_DualBlades_Active_01_Ratio
SkillTreeNode   노드 / OPT_DMG_... / BaseValue 0.1 / PerLevelValue 0.1 / MaxLevel 3
EquipOption     UnlockOpt_ID = OPT_DMG_... / MinVal 0.05 / MaxVal 0.05
```

같은 모디파이어 1행을 장비와 스킬 트리 노드가 다른 값으로 공유한다. 값을 정의에 박으면 부착처 수만큼 모디파이어 행이 늘어난다.

스킬 트리 노드의 값은 `BaseValue + PerLevelValue × (Level - 1)` 로 계산된 결과가 전달된다.

`SkillModifier.Value` 는 값 컬럼이 없는 부착처를 위한 기본값이다. 부착처에 값 컬럼이 있으면 그쪽이 유일한 출처다. **현재 3행 모두 `Value = 0`** 이고 값은 전부 노드가 공급한다.

### 9.6 부착 경로

```
EquipOption / SkillTreeNode / WeaponMastery ──→ OptionID + Value
                        │
                    Option (OptionType 판별)
                        ├─ Stat       → StatContainer       (EquipmentAspect / MasteryAspect)
                        ├─ SkillGrant → 보유 스킬 등록
                        ├─ SkillLevel → 스킬 레벨
                        └─ Modifier   → SkillModifier ★ SkillResolver 가 가져간다
```

`WeaponMastery.LevelBonusOption` 과 `MasteryLevelBonus.LevelBonusOption` 은 같은 경로를 쓰지만 **`Stat` 타입만 허용한다.** 무기와 무관하게 항상 적용되므로, 모디파이어를 붙이면 들고 있지도 않은 무기의 스킬이 변형된다.

### 9.7 태그(Global 스코프) 유보

공용 옵션은 대상마다 한 행씩 작성한다. `Scope = Global` 과 `Tags` 컬럼은 도입하지 않는다. 스킬이 30종을 넘고 같은 옵션이 5개 이상 대상을 가질 때 재검토한다 (15장).

## 10. 데미지 계산식

구현: `GamePlay/Combat/DamageCalculator.cs`

### 10.1 전체 순서

```
[0] 회피 판정    Random(0,1) < 대상 Stat_EvasionRate → 피해 0, 종료
[1] 막기 판정    Random(0,1) < 대상 Stat_BlockRate   → 피해 0, 종료 (표시는 회피와 구분)
[2] 기본 피해    Base = (ScaleStat × Ratio) + FlatValue
                 ※ ScaleStat의 기준 주체는 항상 시전자
[3] 치명타       Random(0,1) < Stat_CritRate → × Stat_CritDamage
[4] 피해 보너스  × (1 + Stat_DamageBonus
                     + Stat_MeleeDamageBonus  (근접 무기일 때)
                     + Stat_RangeDamageBonus  (원거리 무기일 때)
                     + Stat_BossDamageBonus)  (대상이 보스일 때)
[5] 방어 감쇄    유효방어 = 대상 Stat_Def × (1 - Stat_DefPen)
                 감쇄율  = 유효방어 / (유효방어 + K)
                 × (1 - 감쇄율)
[6] 피해 감소    × (1 - 대상 Stat_DamageReduction)
[7] 받는 피해    × (1 + 대상 Stat_DamageTakenAmp)
[8] 최종 증폭    × (1 + Stat_FinalDamageAmp)
     → 음수 클램프 후 반올림(int)
[9] 흡혈         OnHitTrigger = TRUE 일 때만 시전자 HP += Stat_LifeOnHit
```

흡혈은 계산 결과(`Result.LifeOnHit`)로 함께 돌려주고 **호출자가 시전자에게 적용**한다.

### 10.2 레이어 구조

```
[스탯 연산]   (Base + ΣAdd) × (1 + ΣRatio) × (1 + ΣAmp)
[데미지 연산] Base × Crit × (1 + Σ보너스) × 방어 × 감소 × (1 + 최종증폭)
```

`Stat_DamageBonus` 계열이 합연산 레이어, `Stat_FinalDamageAmp` 가 별도 곱연산 레이어다. 보너스를 아무리 쌓아도 최종 증폭은 독립적으로 곱해진다.

### 10.3 방어 공식 — 제산식

```
K = 50 + (AttackerLevel × 20)
```

방어력이 K와 같을 때 감쇄율이 정확히 50%가 된다. 방어력을 무한히 올려도 무적이 되지 않는다. 감산식(`피해 - Def`)은 고레벨에서 0 또는 무적으로 붕괴하므로 쓰지 않는다.

> **기준은 공격자 레벨이다**
>
> | 공격 주체 | AttackerLevel |
> |---|---|
> | 플레이어 | 캐릭터 레벨 |
> | 몬스터 | `MonsterSpawn.Level` (또는 `DungeonStage.MonsterLevel` 오버라이드) |
> | 소환물 · 투사체 | 주인(Owner)의 레벨 |
>
> 피격자 기준으로 두면 플레이어가 레벨업할수록 K가 커져 **자기 방어력의 감쇄율이 떨어진다.** 공격자 기준이면 고레벨 지역일수록 같은 방어력이 덜 먹혀 지역 난이도가 자연스럽게 오른다.
>
> **마스터리 레벨은 쓰지 않는다.** 무기별로 다르므로 같은 캐릭터가 쌍검 200레벨·석궁 3레벨일 때 무기 교체만으로 피해량이 요동친다.

### 10.4 근접 / 원거리 판정

`WeaponMastery.RangeType` 이 결정하며 **장착 무기 단위다. 스킬별 구분은 없다.** 원거리 무기로 근접 모션 스킬을 써도 원거리 보너스를 받는다.

몬스터는 `RangeType` 이 `None` 이라 [4]의 근접·원거리 항이 항상 0이다.

무기를 바꾸면 즉시 뒤집히므로 두 규칙이 따라온다.

1. **스킬 트리 노드**에는 그 마스터리의 `RangeType` 과 맞는 옵션만 넣는다.
2. **방어구·장신구 옵션**도 이 두 스탯을 주축으로 삼지 않는다. 무기를 바꾸면 절반이 사장된다.

### 10.5 회피와 막기

둘 다 피해를 0으로 만든다. 회피를 먼저 판정하고 막기를 나중에 판정한다. 표시는 구분한다(MISS / BLOCK).

```
최종 무효화율 = 1 - (1 - EvasionRate) × (1 - BlockRate)
```

두 스탯 모두 `MaxValue = 0.8` 이므로 최대 96%이며, 100% 무적은 구조적으로 불가능하다.

### 10.6 다단 타격

`HitCount > 1` 인 효과는 타격마다 [0]~[9]를 독립 계산한다. 치명타도 매 타격 개별 판정한다. `HitInterval` 은 고정값이며 공속의 영향을 받지 않는다.

### 10.7 회복 (Heal)

```
회복량 = (ScaleStat × Ratio) + FlatValue
```

치명타·방어·감소를 적용하지 않는다. `TickCount > 1` 이면 `TickInterval` 마다 반복하며 매 틱 독립 계산한다.

### 10.8 사용 스탯 목록

| 스탯 | ValueType | 클램프 | 사용 위치 |
|---|---|---|---|
| `Stat_Atk` | Flat | ‒ | [2] 비례 기준 |
| `Stat_MaxHp` | Flat | Min 1 | [2] 비례 기준, 회복 |
| `Stat_AtkSpeed` | Percent | 0.1 ~ 3 | 4.2절 사이클 |
| `Stat_CritRate` | Percent | ~ 1 | [3] |
| `Stat_CritDamage` | Percent | Min 1.5 | [3] |
| `Stat_DamageBonus` / `Melee` / `Range` / `Boss` | Percent | ‒ | [4] |
| `Stat_DefPen` | Percent | ~ 1 | [5] |
| `Stat_Def` | Flat | ‒ | [5] |
| `Stat_DamageReduction` | Percent | ~ 0.8 | [6] |
| `Stat_DamageTakenAmp` | Percent | ‒ | [7] |
| `Stat_FinalDamageAmp` | Percent | ‒ | [8] |
| `Stat_EvasionRate` / `Stat_BlockRate` | Percent | ~ 0.8 | [0] [1] |
| `Stat_LifeOnHit` | Flat | ‒ | [9] |

> `ANIM_SPEED_MAX`(5.0)와 `Stat_AtkSpeed` 의 상한(3)이 다르다. 코드 주석은 둘을 맞춰 둔다고 되어 있으나 현재 데이터는 3이다. 실효 상한은 **3**이다.

Percent 스탯의 내부값은 0~1 배율이다. 표시할 때만 ×100 한다.

## 11. 리졸브 파이프라인

구현: `GamePlay/Skill/SkillResolver.cs`, `ResolvedSkill.cs`

### 11.1 누가 리졸브되는가

**히어로 1명만이다.** 모디파이어의 출처는 스킬 트리와 장비뿐이고 둘 다 계정에 있으므로 유닛별로 하나면 충분하다.

**몬스터·소환물은 리졸브하지 않는다.** 모디파이어 출처가 없으므로 `ResolvedSkill.CreatePassthrough` 가 만든 **전역 공유 캐시**(테이블 패스스루)를 그대로 돌려준다. 할당이 발생하지 않는다.

히어로의 스킬이라도 **건드릴 모디파이어가 하나도 없으면 사본을 만들지 않는다.** 대부분의 스킬이 이 경로다.

### 11.2 적용 순서

```
0) 보유 스킬의 SkillID 확인
     WeaponMastery.NormalAttackSkill              ← 장착 무기의 평타
     + 현재 마스터리 트리에서 SkillGrant 로 습득한 스킬
     ※ 무기 미착용이면 보유 스킬이 없다

1) Replace 처리                          ★ 반드시 최우선
     Scope=Skill, Operator=Replace 로 SkillID 자체를 교체

2) 테이블 사본 생성
     Skill 행 + EffectID_01/_02 가 가리키는 SkillEffect 행 복사
     효과는 고정 배열이 아니라 가변 리스트로 보관
     ※ 테이블 원본은 절대 수정하지 않는다

3) 스킬 트리 옵션 수집
     현재 마스터리의 투자 노드마다
     BaseValue + PerLevelValue × (노드 레벨 - 1) 을 계산해 모디파이어 큐에 투입
     ※ 노드는 옵션 슬롯을 2개 갖는다 (Option / Option_02)
     ※ 다른 마스터리의 트리는 참여하지 않는다

4) 장비 모디파이어 수집
     Option(Type=Modifier) 경유. 부착처의 Value 를 그대로 사용
     ※ LevelBonusOption 은 Stat 전용이라 여기 들어오지 않는다

5) Append 처리                           ★ 수치 연산보다 먼저
     ParamKey=EffectID, Operator=Append 로 효과 리스트에 추가

6) 수치 연산 적용   Set → Add → Ratio
     이 시점의 효과 리스트 전체가 대상 (Append 된 것 포함)

7) 최종 계산   (Base + ΣAdd) × (1 + ΣRatio)

8) 캐시에 저장
```

### 11.3 테이블 원본을 수정하지 않는 이유

주인의 아이템 옵션이 소환물 스킬까지 오염시킨다. 소환물은 `SkillID` 로 스킬을 참조하는데, 원본을 수정하면 그 참조가 이미 변형된 값을 읽는다.

### 11.4 시전 시점 스냅샷

시전 순간 `Stat_Atk` / `Stat_CritRate` / `Stat_CritDamage` / 스킬 배율을 struct로 복사해 투사체·소환물에 넘긴다. 없으면 시전자 사망 시 비행 중인 투사체에서 참조 오류가 나고, 버프 만료·장비 교체로 이미 발사된 투사체의 데미지가 흔들린다.

### 11.5 캐시 무효화

| 이벤트 | 재계산 | 비고 |
|---|---|---|
| **무기 교체** | ○ | 평타·트리·보유 스킬이 통째로 바뀐다 |
| 장비 착용 / 해제 | ○ | |
| 스킬 트리 노드 투자 / 회수 | ○ | |
| 스킬 트리 초기화 | ○ | |
| 구조 변경 버프 | ○ | 모디파이어를 동반하는 버프 |
| 캐릭터 레벨업 | ✕ | 스탯 캐시만 갱신 |
| 마스터리 레벨업 | ✕ | `LevelBonusOption` 은 Stat 전용 |
| 순수 스탯 버프 / 디버프 | ✕ | **단, 스탯 캐시는 반드시 무효화한다** |
| 체력 변화 | ✕ | |

> **스탯 캐시와 혼동하지 않는다.** 위 표는 **리졸브 캐시**에 대한 것이다. 둘을 분리해 두면 레벨업마다 리졸브를 다시 돌 필요가 없다.

무효화 후 등록된 스킬은 `SkillContainer.RefreshFromResolve()` 로 **값만 다시 읽는다.** `SkillRuntime` 을 재생성하지 않는 이유 — 진행 중인 쿨타임이 날아가면 **장비 교체가 쿨타임 리셋 수단**이 된다.

## 12. 코드 스킬 (ISkillBehavior)

테이블 효과로 표현하기 어려운 시퀀스(연출·이동·조건부 반복)를 코드로 구현하는 경로다.

```csharp
public interface ISkillBehavior
{
    void SetContext(...);
    void OnStart();
    bool Tick(float dt);   // true 를 반환하는 동안 계속 진행
    void OnEnd();
}
```

| 항목 | 규칙 |
|---|---|
| 등록 | `SkillBehaviorRegistry` 의 **명시적 Dictionary**. 리플렉션을 쓰지 않는다 |
| 우선순위 | 등록된 스킬이면 **테이블 효과를 읽지 않고** 코드가 전부 담당한다 |
| 예외 | `CastingType = Casting` 은 캐스팅 흐름(선딜·취소)을 거친 뒤 시작한다 |
| 슬롯 | 유닛당 1개(`_activeBehavior`). 새로 시작하면 이전 것을 정리한다 |

**현재 등록된 것은 `Skill_SummonSpark_Attack` 하나뿐이다.**

> 행동 시퀀스는 `ISkillBehavior`, 부착된 지속 상태는 버프로 나눈다. 둘의 책임을 섞으면 같은 효과가 두 갈래로 표현된다.

## 13. 검증 규칙

변환 시 검증과 부팅 시 카탈로그 검증이 함께 담당한다 (`테이블규약_설계.md` 8장). 아래는 **조용히 아무 일도 일어나지 않는** 사고를 막기 위한 목록이다.

### 13.1 참조 / 구조

| # | 검증 항목 |
|---|---|
| 1 | `!Xxx` 참조 대상이 실존하는가 |
| 2 | `EffectID_01` / `_02` 가 모두 비어있음 — 실행할 효과가 없는 스킬 |
| 3 | `SkillParamDef` 에 `(EffectType, Index)` 중복 |
| 4 | 같은 `EffectType` 내 `ParamKey` 중복 |
| 5 | `Scope` 와 다른 `Scope_*` 컬럼에 값이 있음 |
| 6 | `ChainEffectIDs` 순환 (깊이 5 초과) |
| 7 | `Operator=Replace` 의 `RefValue` 가 실존 SkillID인가 / 순환 |

### 13.2 ParamKey / Operator

| # | 검증 항목 |
|---|---|
| 8 | `ParamKey` 가 대상 `EffectType` 에 존재하는가 (예: Damage에 `Count` 없음 — `HitCount` 오타) |
| 9 | `ParamKey` 가 대상 `CastingType` / `ScanType` 에 존재하는가 |
| 10 | 참조 파라미터에 `Add` / `Ratio` 를 걸었는가 — `RefID` 는 `Set` 만 가능 |
| 11 | `Set` + 참조 파라미터인데 `RefValue` 타입 불일치 |
| 12 | `ParamKey = EffectID` 에 `Append` 외의 Operator |
| 13 | `Operator = Append` 인데 `ParamKey` 가 `EffectID` 가 아님 |
| 14 | `Scope` 가 `Projectile` / `Summon` / `Buff` — **현재 미지원**(9.2) |

### 13.3 값 범위

| # | 검증 항목 |
|---|---|
| 15 | `EffectTime` 이 0 미만 또는 1 초과 |
| 16 | 확률 파라미터가 1을 초과 (25% → 0.25) |
| 17 | `CastingType=OnLowHP` 인데 `CastingParam` 이 0 또는 1 초과 |
| 18 | `CastingType=OnCombo` 인데 `CastingParam` 에 소수부 / 0 이하 |
| 19 | `CastingType=Aura` 인데 `CastingParam` 이 0 — 한 번도 발동하지 않는다 |
| 20 | `ScanRange=0` 인데 `ApplyTarget≠Self` 이고 소환물 스킬도 아님 |
| 21 | Projectile / Summon 의 `Count` 가 0 |
| 22 | `SkillCategory=Normal` 인데 `Cooldown` 이 0 — 평타는 Cooldown이 공격 주기 |
| 23 | `AnimLength > 0` 인데 `AnimName` 이 비었음 |
| 24 | `CooldownReduce` 의 `TargetSkillID` 가 비었거나 `Ratio`·`FlatValue` 가 모두 0 |
| 25 | `BuffConsume` 의 `Count` 가 0 이하 |

### 13.4 의미 (경고)

| # | 검증 항목 |
|---|---|
| 26 | `HitCount>1` 인데 `OnHitTrigger=TRUE` — 온히트가 반복 발동 |
| 27 | `Force` 효과가 `ChainEffectIDs` 가 아닌 `EffectID` 에만 연결 — 빗나가도 밀려난다 |
| 28 | `Buff` 의 `BlockFlags` 와 `EffectID` 가 모두 비었음 — 아무 효과도 없는 버프 |
| 29 | `Buff.TickInterval>0` 인데 Damage/Heal 효과 없음 |
| 30 | `ScaleByRadius=TRUE` 인데 소환 `Radius` 가 0 |
| 31 | `AIType=Chase` 인데 `ReturnDistance` 가 0 — 무한히 추격 |
| 32 | 소환물에 `SkillID_1` 이 비었음 |
| 33 | `ScaleStat` 에 `StatDetail` 을 지정 — `Stat` 을 지정해야 한다 |
| 34 | `StatChange.Param_1` 에 `Stat` 을 지정 — `StatDetail` 이어야 한다 (레이어 필요) |
| 35 | `BuffConsume` 인데 `ChainEffectIDs` 가 비었음 — 소모만 하고 아무 일도 없다 |
| 36 | `WeaponMastery.NormalAttackSkill` 이 가리키는 스킬의 `SkillCategory` 가 Normal이 아님 |
| 37 | 어느 참조원에서도 지목되지 않는 스킬 — 소환물·착탄 스킬은 정상이므로 경고 |

> `AnimName` 오타는 **어떤 검증에도 걸리지 않는다.** 애니메이터 트리거명이라 테이블이 실존을 알 수 없다. 현재 유효한 값은 `Attack` / `Skill` / `Hit` / `Die` 넷뿐이다.

## 14. 신규 스킬 작성 가이드

### 14.1 작성 절차

```
STEP 1  스킬의 성격을 정한다          → SkillCategory
STEP 2  언제 발동하는가               → CastingType + CastingParam
STEP 3  누구를 어떻게 찾는가          → ApplyTarget + ScanType + ScanRange + ScanParam
STEP 4  모션과 주기를 정한다          → AnimName + AnimLength + Cooldown
STEP 5  무슨 일이 일어나는가 분해한다  → EffectID_01 / _02, 각 효과의 EffectType
STEP 6  각 효과의 발동 시점을 정한다   → EffectTime
STEP 7  파라미터를 채운다             → 5.2절 ParamMatrix 를 보고 EffectParam_1~5
STEP 8  하위 테이블을 작성한다        → Projectile / Summon / Buff
STEP 9  검증한다                      → 14.4절 체크리스트
```

### 14.2 STEP별 판단 기준

**STEP 1 — SkillCategory**

| 이런 스킬이면 | 값 |
|---|---|
| 평타 / 기본공격 | `Normal` |
| 조건이나 조작으로 발동하는 스킬 | `Active` |
| 상시 적용 | `Passive` |

`Normal` 만 공속 배율을 받고, 이 선택이 `Cooldown` 의 의미를 바꾼다.

**STEP 2 — CastingType**

직접 시전이 필요하면 `Instant` / `Casting`, 자동 전투에서 조건으로 터뜨리려면 `OnCombo` / `OnHit` / `OnCrit` / `OnKill` / `OnDamaged` / `OnLowHP` 다. **현재 프로젝트는 자동 전투이므로 무기 액티브 스킬은 조건 발동형이 기본이다.**

**STEP 3 — ScanType**

| 원하는 판정 | ScanType |
|---|---|
| 내 주변 전방향 | `Circle` |
| 바라보는 방향 부채꼴 | `Sector` (`ScanParam` = 각도) |
| 찌르기·관통 직선 | `Line` (`ScanParam` = 폭) |
| 가장 가까운 N명 | `Target` (`ScanParam` = 대상 수) |

**STEP 4 — 모션**

`AnimName` 은 애니메이터 트리거명이다(`Attack` / `Skill`). **평타 모션 위에 효과만 얹는 스킬이면 `AnimName` 과 `AnimLength` 를 비운다.**

### 14.3 실제 패턴 3종

**① 평타 (근접)** — `Skill_DualBlades_Attack`

```
Skill
  SkillCategory = Normal      AnimName = Attack   AnimLength = 0.4167
  CastingType   = Instant     Cooldown = 0.5      ← 공속으로 나뉜다
  ApplyTarget   = Enemy       ScanType = Sector   ScanRange = 1.0   ScanParam = 120
  EffectID_01   = SE_DualBlades_Attack_Damage
  BreakDamage   = 1

SE_DualBlades_Attack_Damage
  Damage / Target / EffectTime 0.6
  Ratio 1 / HitCount 1 / ScaleStat Stat_Atk
  OnHitTrigger = TRUE         ← 온히트·흡혈의 기점
  EffectVFX = hit-blue        EffectSFX = blade_hit_08
```

**② 콤보 발동형 액티브** — `Skill_DualBlades_Active_01`

```
Skill
  SkillCategory = Active      AnimName = (없음)   ← 평타 모션 위에 얹는다
  CastingType   = OnCombo     CastingParam = 3    ← 평타 3타마다
  ApplyTarget   = Enemy       ScanType = Line     ScanRange = 3.0   ScanParam = 0.5
  Cooldown      = 0
  EffectID_01   = SE_DualBlades_Active_01_Damage
  SkillVFX = horizontal-slash / SkillVFXFacing = TRUE / SkillVFXOffset = 1.5
  BreakDamage   = 5

SE_DualBlades_Active_01_Damage
  Damage / Target / EffectTime 0
  Ratio 2.5 / HitCount 1 / ScaleStat Stat_Atk
  ChainEffectIDs = [ SE_Common_Stagger_Buff ]     ← 맞았을 때만 경직
```

**③ 패시브 소환** — `Skill_DualBlades_Passive_02`

```
Skill
  SkillCategory = Passive     CastingType = Passive
  ApplyTarget   = Self        ScanType = None      ScanRange = 0
  EffectID_01   = SE_DualBlades_Passive_02_Summon

SE_DualBlades_Passive_02_Summon
  Summon / Caster / EffectTime 0
  RefID Summon_Spark / Count 3 / Duration 0 (영구) / Radius 1.5

Summon_Spark
  Orbit / FollowDistance 1.0 / MaxCount 3 / DieWithOwner TRUE
  InheritStatType_1 = Stat_Atk / Ratio 1.0
  SkillID_1 = Skill_SummonSpark_Attack   ← Normal / Instant / Target / Cooldown 0.25
```

### 14.4 작성 후 체크리스트

```
□ EffectID_01 이 채워져 있는가 (비면 아무 일도 일어나지 않는다)
□ ScanRange 가 0이 아닌가 (Self·소환물 스킬 제외)
□ 평타라면 Cooldown 이 0이 아닌가
□ AnimName 이 Attack / Skill / Hit / Die 중 하나인가 (또는 의도적으로 비었는가)
□ AnimLength 가 실제 클립 길이인가 (밸런스용으로 조정하지 않았는가)
□ 확률·비율이 0~1 배율인가 (25% → 0.25)
□ EffectTime 이 0~1 범위인가
□ ScaleStat 이 Stat_ (StatDetail_ 이 아님) 인가
□ StatChange 의 Param_1 이 StatDetail_ 인가
□ Force 를 ChainEffectIDs 로 연결했는가
□ 다단히트에 OnHitTrigger 를 켜지 않았는가
□ 소환물을 만들었다면 SkillID_1 을 채웠는가
□ 부팅 로그에 Catalog 경고가 없는가
```

### 14.5 자주 하는 실수

| 실수 | 증상 |
|---|---|
| `AnimName` 오타 | 모션만 안 나오고 에러 없음 |
| 확률을 25로 기입 | 항상 발동 |
| `ScaleStat` 에 `StatDetail_Atk_Add` 기입 | 데미지가 0에 가까움 |
| `EffectID_02` 에 `Force` 연결 | 빗나가도 밀려남 |
| 소환물 스킬을 `Normal` 로 | 공속 상속 실패로 주기 붕괴 |
| `Aura` 스킬에 `Cooldown` 기입 | 무시됨 (혼란만 유발) |
| 조건 발동형을 `TryCast` 로 부르려 함 | 직접 시전 불가 — 트리거 경로로만 |

## 15. 확장 시점 판단표

예외가 실제로 생기기 전에 컬럼을 만들지 않는다.

| 추가 구조 | 도입 시점 | 그 전까지의 대안 |
|---|---|---|
| `HitGroupID` / `ImmuneTime` | 공전 소환물의 중복 히트가 실제 문제가 될 때 | 5.7절 중복 히트 규칙 |
| `ModifierOperator.Remove` | 테이블에 원래 있는 효과를 제거해야 할 때 | Replace로 다른 스킬 행 교체 |
| `Skill.CostBuffID` / `CostStack` | 스킬 시전 자체를 자원으로 막아야 할 때 | BuffConsume + 연쇄 (5.8절) |
| `Skill.DamageType` (Melee/Range) | 같은 무기가 근접·원거리 스킬을 섞어 쓸 때 | `WeaponMastery.RangeType` |
| `Projectile` 속도·수명 컬럼 | 모디파이어로 투사체 속도를 바꿔야 할 때 | 프리팹 소유 + `SpeedRate` |
| `EffectID_03` 이상 | 한 스킬이 3개 이상의 독립 효과를 가질 때 | ChainEffectIDs / Append |
| `SkillModifier.Priority` | 같은 `Set` 이 여러 개 충돌할 때 | 데이터 설계로 회피 |
| `ModifierScope.Global` + Tags | 스킬 30종 이상 & 같은 옵션이 5개 이상 대상 | 대상마다 한 행씩 |
| Projectile/Summon/Buff 리졸브 | 이 세 시트의 컬럼을 옵션으로 바꿔야 할 때 | `Scope=Effect` + `RefID` 교체 |
| `Buff.Tags` | 저항·면역·CC 체감 시스템 도입 시 | 미도입 |
| `DamageTag` (속성) | 속성 저항 스탯 도입 시 | 미도입 |
| `Summon.StatBindType` | 스냅샷 상속이 필요해질 때 | 항상 Live |
| Condition 테이블 | 조건 3종 초과 · 조건 값 2개 이상 필요 | CastingType enum 확장 |
| `Cost` / `CostType` | 마나·자원 시스템을 실제로 도입할 때 | 쿨타임 단독 제약 |

## 16. 구현 체크리스트

### 16.1 반드시 지킬 것

| 항목 | 이유 |
|---|---|
| Enum·ParamKey를 엑셀에서 C# 코드로 생성 | 손으로 관리하면 테이블과 코드가 반드시 어긋난다 |
| ParamKey 검증을 에러로 처리 | 경고면 오타 하나로 옵션이 조용히 안 먹힌다 |
| 테이블 원본을 수정하지 않고 사본에 모디파이어 적용 | 주인의 아이템 옵션이 소환물 스킬까지 오염시킨다 |
| 시전 시점 스냅샷 (ATK, CritRate, CritDamage, 배율) | 시전자 사망 시 비행 중 투사체가 참조 오류 |
| 데미지 판정에 애니메이션 진행률을 참조하지 않는다 | 고속·프레임 드랍에서 판정이 유실된다 |
| `AnimLength` 는 실제 클립 길이만 기입 | 밸런스용으로 조정하면 재생 속도가 어긋난다 |
| 개수는 `SkillEffect` 의 `Count` 에만 정의 | 두 곳에 두면 모디파이어 적용 시 어긋난다 |
| 장판 크기는 `SkillEffect.Radius` 에만 정의 | `ScanRange=0` 상속 + `ScaleByRadius` 로 비주얼 동기화 |
| 버프는 `EffectID` 를 참조하고 수치를 직접 갖지 않는다 | 새 파라미터 개념이 생기고 모디파이어가 못 닿는다 |
| Force는 `ChainEffectIDs` 로 연결 | `EffectID_02` 에 두면 빗나가도 밀려난다 |
| Replace를 수치 연산보다 먼저 처리 | 교체된 스킬에 붙는 모디파이어가 유실된다 |
| Append를 수치 연산보다 먼저 처리 | 새로 붙은 효과에 모디파이어가 닿지 않는다 |
| 효과를 고정 배열이 아닌 리스트로 보관 | Append 개수에 상한이 생긴다 |
| 소환물 스탯은 상속 비율로 계산 | 고정값이면 레벨 구간마다 수동 재밸런싱 |
| 읽기는 `Stat`, 쓰기는 `StatDetail` | `ScaleStat` 에 StatDetail을 넣으면 연산 방식이 중복 지정된다 |
| Percent 내부값은 0~1 배율 | 곱연산에 그대로 쓰인다 |
| 조건은 스킬이 아니라 효과에 건다 | 스킬 단위 조건은 시전 자체를 막아버린다 |
| 스탯 캐시와 스킬 리졸브 캐시를 분리한다 | 레벨업마다 리졸브를 다시 돌 필요가 없어진다 |
| 리졸브 무효화 시 `SkillRuntime` 을 재생성하지 않는다 | 장비 교체가 쿨타임 리셋 수단이 된다 |
| 지연을 코루틴이 아니라 예약 큐로 처리한다 | 동시 다수 스킬에서 할당 부하가 된다 |

### 16.2 코드 상수 (`SkillConstants`)

| 상수 | 값 | 용도 |
|---|---|---|
| `ANIM_SPEED_MIN` | 0.1 | 애니메이션 재생 속도 하한 |
| `ANIM_SPEED_MAX` | 5.0 | 애니메이션 재생 속도 상한 |
| `LOWHP_CHECK_INTERVAL` | 0.5 | OnLowHP 체력 검사 주기(초) |
| `CHAIN_DEPTH_LIMIT` | 5 | ChainEffectIDs 순환 방지 |

그 외 방어 상수 `K = 50 + AttackerLevel × 20` 은 `DamageCalculator` 에 있다.

### 16.3 런타임에 필요한 것

| 대상 | 내용 |
|---|---|
| 콤보 카운터 | 캐릭터당 1개. **평타가 실제로 적중**했을 때 +1. 리셋 없음 (재접속 시 0) |
| 치명타 이벤트 | 데미지 [3]단계에서 발행. `OnHitTrigger = TRUE` 인 효과만 |
| 처치 이벤트 | 대상 사망 시 발행. 수단 무관. 동시 처치는 처치 수만큼 |
| 쿨다운 조작 API | 진행 중인 쿨다운 감소. 쿨다운 중이 아니면 무시 |
| 버프 스택 차감 API | 특정 버프 n스택 제거. 부족하면 실패 반환 → 연쇄 중단 |
| 효과 리스트 | 리졸브 결과가 가변 리스트를 보유. Append 대상 |
| 보유 스킬 목록 | `WeaponMastery.NormalAttackSkill` + 트리에서 `SkillGrant` 로 습득한 스킬. **무기 교체 시 재구성** |

### 16.4 설계 원칙 요약

1. 겹치지 않으면 슬롯, 겹치면 명명 컬럼.
2. 모디파이어는 번호가 아닌 이름으로 지목한다.
3. 탐색은 Skill이 한 번만. 착탄 폭발은 투사체 속성이다.
4. 판정은 로직이 소유하고 애니메이션은 연출만 한다.
5. 코드는 "어떻게", 테이블은 "얼마나".
6. 같은 것을 두 갈래로 표현할 수 있으면 하나로 합친다.
7. 예외가 생기기 전에 컬럼을 만들지 않는다.
8. 읽는 참조와 쓰는 참조를 구분한다 — 값만 필요하면 `Stat`, 값을 바꾸면 `StatDetail`.
9. 조건은 스킬이 아니라 효과에 건다.
10. 행동 시퀀스는 `ISkillBehavior`, 부착된 지속 상태는 버프.

## 17. 미결 / 다음 작업

- **3무기(룬소드·석궁·쌍권총)의 액티브·패시브가 전부 빈 행이다.** `EffectID` 가 비어 있어 시전해도 아무 일도 일어나지 않는다.
- **`Scope = Projectile / Summon / Buff` 모디파이어 미지원** — 리졸브 사본이 스킬과 효과만 뜬다 (9.2).
- **`SkillLevel` 옵션 데이터 0행** — 타입과 경로는 있으나 쓰이지 않는다.
- **`Heal` / `Force` / `CooldownReduce` / `BuffConsume` 효과 데이터 0행** — 파라미터 정의와 적용 코드는 있으나 실제 행이 없다.
- **소환물 1종뿐** — `Summon_Spark` 외에 없다. `Stationary` 장판 구조는 설계만 있고 데이터가 없다.
- **`Skill.Icon` / `Desc` 전량 비어 있음** — 스킬 UI 작업 시 필요하다.
