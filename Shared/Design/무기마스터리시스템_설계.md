## 1. 개요 및 설계 원칙

### 1.1 프로젝트 전제

| 항목 | 값 |
|---|---|
| 플레이 | 싱글플레이, 단일 캐릭터 |
| 범위 | 캐릭터 레벨 · 무기 마스터리 · 스킬 트리 · 스킬포인트 |
| 자원 | **없음.** 마나·탄약 제약을 두지 않는다 |

**직업 개념이 없다.** 캐릭터는 하나이며, **어떤 무기를 들고 있는가가 그 순간의 정체성**이 된다. 무기와 마스터리는 1:1로 대응하고, 마스터리마다 독립된 스킬 트리를 가진다.

### 1.2 설계 원칙

1. **무기 교체에 비용·제약·손실이 없다.** 각 마스터리의 진행도는 독립적으로 보존된다.
2. **마스터리 레벨 보너스는 무기와 무관하게 항상 적용되고, 트리 투자는 그 무기를 들었을 때만 작동한다.** 이 둘의 차이가 시스템의 핵심이다.
3. **레벨·가용 포인트·노드 해금 여부는 저장하지 않고 계산한다.** 저장하는 것은 누적 경험치·지식의 서 사용 횟수·노드별 투자 레벨뿐이다.
4. **스킬은 트리에서 배우고 트리에서 강화한다.** 스킬 슬롯도 스킬북 파밍도 없다.

## 2. Enum 정의

### 2.1 WeaponMastery (EnumTable)

`Mastery_DualBlades` / `Mastery_RuneSword` / `Mastery_CrossBow` / `Mastery_DualPistols`

### 2.2 WeaponType

`DualBlades` / `RuneSword` / `CrossBow` / `DualPistols`

**`WeaponMastery` 와 1:1로 대응한다.** 대응 마스터리가 없는 `WeaponType` 은 오류다.

> enum에 항목을 **중간 삽입하면 기존 장비 데이터가 어긋난다.** 신규 항목은 반드시 끝에 추가한다.

### 2.3 WeaponRangeType

`Melee` / `Ranged`

데미지 계산 [4]단계에서 `Stat_MeleeDamageBonus` / `Stat_RangeDamageBonus` 중 무엇이 적용되는지를 결정한다 (`스킬시스템_설계.md` 10.4). **장착 무기 단위로 결정되며 스킬별 구분은 없다.**

### 2.4 SkillPointSourceType

`MasteryLevel` / `Item` / `Achievement`

`SkillPoint` 행의 출처 구분이다. 소모품이 지목할 수 있는 것은 `Item` 뿐이다.

### 2.5 OptionTypes (외부 — `Option.xlsx`)

`Stat` / `SkillGrant` / `SkillLevel` / `Modifier`. 정의는 `기반테이블_설계.md` 6장이 소유한다.

## 3. 캐릭터 레벨과 스탯

### 3.1 CharacterStat

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 기본 키(일련번호) |
| `StatDetailID` | `!StatDetail` | 대상 스탯. 반드시 `_Base` 계열 |
| `BaseValue` | `!float` | **1레벨 기준값** |
| `PerLevel` | `!float` | 레벨당 증가량. 0이면 성장하지 않음 |

**캐릭터는 1종이므로 그룹 키가 없다.** (몬스터는 `MonsterStat.GroupID` 로 묶인다)

현재 데이터 10행은 `기반테이블_설계.md` 4.2절에 있다. 성장하는 것은 `Atk`(+2) · `MaxHp`(+20) · `HpRegen`(+1) · `Def`(+1) 넷뿐이고 나머지는 고정값이다.

### 3.2 성장식

```
기본값 = BaseValue + PerLevel × (Level - 1)
```

> **`BaseValue` 는 1레벨 기준값이다 — 장비와 규칙이 반대다**
>
> `EquipOption.Val` 은 **0레벨 기준값**이라 1레벨 실제 값이 `Val + Step` 이다. 캐릭터는 1레벨부터 시작하고 기획자가 초기 능력치를 그대로 읽을 수 있어야 하므로 `(Level - 1)` 을 곱한다.
>
> **캐릭터는 1레벨 기준, 장비는 0레벨 기준.**

몬스터도 같은 식을 쓴다 (`StatContainerFactory`).

### 3.3 CharacterLevelExp

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 레벨 (PK) |
| `TotalExperience` | `!int` | 해당 레벨에 도달하기 위한 **누적** 경험치 |

```
다음 레벨 요구량 = CharacterLevelExp[Level + 1].TotalExperience
                 - CharacterLevelExp[Level].TotalExperience
```

`ID = 1` 행의 `TotalExperience` 는 0이다. 누적값으로 두면 경험치 대량 획득 시 반복 뺄셈 없이 **이분 탐색 한 번**으로 도달 레벨을 구할 수 있다 (`MasteryCatalog`).

**현재 100레벨까지 있다.** 테이블의 마지막 레벨이 사실상의 만렙이며 이후 획득 경험치는 버린다.

### 3.4 방어 상수 K의 기준

스킬 문서 10.3절의 방어 공식이 쓰는 레벨은 **공격자 레벨**이다.

```
K = 50 + (AttackerLevel × 20)
```

플레이어가 공격할 때는 **캐릭터 레벨**, 몬스터가 공격할 때는 그 몬스터의 레벨, 소환물은 주인의 레벨이다.

**마스터리 레벨은 기준이 될 수 없다.** 무기별로 다르므로 무기를 바꾸는 것만으로 K가 변한다.

## 4. WeaponMastery — 무기 마스터리

### 4.1 컬럼 정의 (13컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!WeaponMastery` | 기본 키. `Mastery_` 접두 |
| `Name` | `!string` | 표시명 |
| `Icon` | `!string` | 마스터리 아이콘 |
| `WeaponType` | `!WeaponType` | 대응 무기 종류. **마스터리마다 유일** |
| `RangeType` | `!WeaponRangeType` | 근접 / 원거리 |
| `AnimControllerName` | `!string` | **무기별 애니메이터 오버라이드 컨트롤러 이름** |
| `LevelBonusOption` | `!Option` | 이 마스터리 레벨당 보너스. **`Stat` 타입만 허용** |
| `LevelBonusPerLevel` | `!float` | 레벨당 증가량 |
| `NormalAttackSkill` | `!Skill` | 이 무기의 평타. `SkillCategory` 가 `Normal` 이어야 한다 |
| `MaxRow` | `!int` | 스킬 트리 보드 세로 크기 |
| `MaxColumn` | `!int` | 보드 가로 크기 |
| `SkillTreeNodeGroupID` | `!int` | `SkillTreeNode.GroupID` 참조 |
| `Dev_SkillIDs` | `!Skill[]` | **개발용.** 트리와 무관하게 강제로 보유시킬 스킬 목록 |

> **`Dev_SkillIDs` 는 정식 데이터가 아니다.** 트리 없이 스킬을 테스트하기 위한 개발 편의 컬럼이며 현재 전 행이 비어 있다. 정식 전환 시 제거 대상이다.

### 4.2 현재 4종

| ID | 무기 | RangeType | LevelBonusOption | PerLevel | 평타 | 보드 | 트리 |
|---|---|---|---|---|---|---|---|
| `Mastery_DualBlades` | 쌍검 | Melee | `OPT_ATK_ADD` | 1 | `Skill_DualBlades_Attack` | 6×4 | 101 |
| `Mastery_RuneSword` | 룬검 | Melee | `OPT_ATK_SPEED_ADD` | 0.001 | `Skill_RuneSword_Attack` | 6×4 | 101 |
| `Mastery_CrossBow` | 석궁 | Ranged | `OPT_CRIT_RATE_ADD` | 0.001 | `Skill_CrossBow_Attack` | 6×4 | 101 |
| `Mastery_DualPistols` | 쌍권총 | Ranged | `OPT_CRIT_DAMAGE_ADD` | 0.02 | `Skill_DualPistols_Attack` | 6×4 | 101 |

> **네 마스터리가 같은 트리(`101`)를 공유하고 있다.** 마스터리별 독립 트리가 설계지만 현재는 쌍검용 트리 하나뿐이라 전부 같은 보드를 가리킨다. 트리 데이터가 쌍검 기준이므로 **다른 무기를 들면 쓸모없는 노드가 섞여 보인다.**

### 4.3 마스터리가 소유하는 것

```
무기 장착 → Equipment.WeaponType → WeaponMastery 역참조
             ├─ 기본공격       = NormalAttackSkill
             ├─ 스킬 트리      = SkillTreeNodeGroupID
             ├─ 근접/원거리     = RangeType
             ├─ 애니메이터      = AnimControllerName
             └─ 경험치 적립처    = 이 마스터리
```

무기를 바꾸면 **스킬 구성이 통째로 바뀐다.**

### 4.4 무기 미착용 상태

| 항목 | 상태 |
|---|---|
| 기본공격 | **없다 — 공격할 수 없다** |
| 스킬 트리 | 적용되지 않는다 |
| 마스터리 경험치 | **적립되지 않고 버려진다** |
| 마스터리 레벨 보너스 | **전부 그대로 적용된다** |
| 장비 옵션 · 캐릭터 기본 스탯 | 정상 작동 |
| 애니메이터 | 기본 컨트롤러로 복귀 |

### 4.5 레벨 보너스 — 두 축이 있다

**보너스는 두 종류이며 기준이 되는 레벨이 다르다.**

| 출처 | 기준 레벨 | 적용 |
|---|---|---|
| `WeaponMastery.LevelBonusOption` | **각 무기의 마스터리 레벨** | 전 마스터리를 합산. 무기와 무관하게 항상 |
| `MasteryLevelBonus.LevelBonusOption` | **전 마스터리 레벨의 총합** | 총합에 비례하는 전역 보너스 |

```
[무기별]  Σ (마스터리i.Level × 마스터리i.LevelBonusPerLevel)
[총합]    (Σ 마스터리i.Level) × MasteryLevelBonus.LevelBonusPerLevel
```

> **이것이 무기를 바꿔도 손해가 없는 이유다.** 쌍검을 200레벨까지 키운 뒤 석궁을 들어도 쌍검이 준 공격력 보너스는 그대로 남는다. 키운 것은 사라지지 않는다.

**`MasteryLevelBonus` 테이블 (3컬럼)**

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 일련번호 |
| `LevelBonusOption` | `!Option` | `Stat` 타입만 |
| `LevelBonusPerLevel` | `!float` | 총합 레벨당 증가량 |

현재 2행 — `OPT_ATK_ADD` +2.5/레벨, `OPT_MAX_HP_ADD` +5/레벨.

> **⚠ 총합 보너스가 아직 스탯에 반영되지 않는다**
>
> `Table_MasteryLevelBonus` 를 읽는 코드는 `MasteryPresenter.buildBonusText` 하나뿐이다. **마스터리 화면에 문구로 표시만 되고 히어로 스탯에는 들어가지 않는다.** `MasteryAspect` 는 `WeaponMastery.LevelBonusOption`(무기별)만 적용한다.
>
> 설계상 두 축은 모두 유효하므로, 총합 보너스를 `MasteryAspect` 에 추가하는 작업이 남아 있다.

**`LevelBonusOption` 은 `Stat` 타입만 허용한다.** 모디파이어를 붙이면 들고 있지도 않은 무기의 스킬이 변형된다. `MasteryAspect.applyStatOption` 의 `statOnly` 가드가 이를 막는다.

## 5. 마스터리 레벨과 경험치

### 5.1 MasteryLevelExp

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 레벨 (PK) |
| `TotalExperience` | `!int` | 누적 요구 경험치 |

**현재 300레벨까지 있다.** `CharacterLevelExp` 와 같은 구조이며 **전 마스터리 공용**이다. 무기별로 나누지 않는다.

레벨은 저장하지 않고 누적 경험치에서 이분 탐색으로 파생한다. **만렙 초과분은 버린다.**

### 5.2 경험치 귀속 규칙

> **경험치 진입점은 `Account.AddExp(amount)` 하나다.**

```csharp
Account.AddExp(amount)
  ├ Loadout.AddExp(amount)          캐릭터 레벨
  └ Mastery.AddExpToCurrent(amount) 현재 장착 무기의 마스터리
```

**같은 값이 두 곳에 동시에 적립된다.** 캐릭터 경험치와 마스터리 경험치가 나뉘어 들어가는 것이 아니다.

> **`Loadout.AddExp` 를 직접 부르면 마스터리 적립이 누락된다.** 경험치를 주는 새 경로를 만들 때는 반드시 `Account.AddExp` 를 쓴다. 서버가 절대값을 내려주는 경로는 `SetExpAuthoritative(newExp)` 가 증가분만 마스터리에 적립한다.

**무기를 들지 않았으면 마스터리 경험치는 버려진다.** 캐릭터 경험치만 들어간다.

각 마스터리는 **병렬로 존재하며 리셋 개념이 없다.** 한 번이라도 든 무기만 진행도 항목이 생기고, 없으면 Lv1 / 0포인트로 취급한다.

### 5.3 레벨업 보상

마스터리 레벨업은 **스킬포인트 1점**을 준다(7장). 그 외 보상은 없다.

## 6. 스킬 트리 (SkillTreeNode)

### 6.1 보드 구조

보드 크기는 `WeaponMastery.MaxRow` × `MaxColumn` 이다 (현재 전 마스터리 6×4).

노드의 열림 조건은 **두 가지가 독립적으로 작동**한다.

| 조건 | 컬럼 | 의미 |
|---|---|---|
| 행 게이트 | `RequireTreePoint` | **이 노드보다 위쪽 행들에** 투자한 포인트 합이 값 이상 |
| 개별 선행 | `PrevNodeID` | 지정한 노드가 **만렙**에 도달 |

둘 다 있으면 둘 다 만족해야 열린다. 둘 다 비어 있으면 처음부터 열려 있다.

> **행 게이트의 기준은 "위쪽 행" 이지 트리 전체가 아니다** (`MasteryProgress.GetInvestedAboveRow`). 같은 행이나 아래 행에 투자한 포인트는 세지 않는다.
>
> 트리 전체 투자량(`TotalInvested`)은 **가용 포인트 계산용**이라 축이 다르다. 둘을 혼동하면 게이트가 의도보다 헐거워진다.

```
행 게이트   → 보드를 위에서 아래로 진행시킨다 (전체 진도)
개별 선행   → 특정 라인을 순서대로 타게 한다 (스킬 습득 → 강화)
```

### 6.2 SkillTreeNode (16컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 기본 키. 전역 일련번호 |
| `GroupID` | `!int` | 소속 보드 (`SkillTreeNodeGroupID`) |
| `Name` | `!string` | 표시 이름 |
| `Desc` | `!string` | 설명 |
| `Icon` | `!string` | 노드 아이콘 |
| `NodePos_Row` | `!int` | 세로 좌표 (1부터) |
| `NodePos_Column` | `!int` | 가로 좌표 (1부터) |
| `PrevNodeID` | `!int` | 선행 노드. 빈칸이면 조건 없음 |
| `RequireTreePoint` | `!int` | 위쪽 행 투자 요구량. 빈칸이면 0 |
| `Option` | `!Option` | **옵션 슬롯 1** |
| `BaseValue` | `!float` | 슬롯 1의 1레벨 값 |
| `PerLevelValue` | `!float` | 슬롯 1의 레벨당 증가분 |
| `MaxLevel` | `!int` | 노드 최대 레벨 = 이 노드에 넣을 수 있는 최대 포인트 |
| `Option_02` | `!Option` | **옵션 슬롯 2.** 비어 있으면 미사용 |
| `BaseValue_02` | `!float` | 슬롯 2의 1레벨 값 |
| `PerLevelValue_02` | `!float` | 슬롯 2의 레벨당 증가분 |

> **노드는 옵션을 2개까지 갖는다.** 두 슬롯은 같은 노드 레벨을 공유하되 값은 각자 계산된다. `MaxLevel` 은 노드 단위로 하나뿐이다.
>
> 슬롯 2가 필요한 대표 사례는 **"스킬을 습득하면서 동시에 그 스킬을 강화하는" 노드**다. 슬롯 1에 `SkillGrant`, 슬롯 2에 `Modifier` 를 넣으면 노드 하나로 습득 + 레벨당 피해 증가가 표현된다.
>
> 3개 이상이 필요하면 노드를 나눈다. 슬롯을 더 늘리는 것보다 보드 가독성이 낫다.

### 6.3 노드 값 계산

```
슬롯 1 = BaseValue    + PerLevelValue    × (Level - 1)
슬롯 2 = BaseValue_02 + PerLevelValue_02 × (Level - 1)
```

**1레벨 기준이다** — 노드에 1포인트를 넣으면 `BaseValue` 가 그대로 적용된다. 캐릭터 스탯과 같은 규칙이고 장비(`Val`, 0레벨 기준)와는 반대다.

`PerLevelValue` 가 0이면 레벨이 올라도 값이 변하지 않는다. `SkillGrant` 슬롯이 이 형태다 — 배웠다/안 배웠다에 중간값이 없으므로 값 자체를 쓰지 않는다.

### 6.4 노드 성격별 조합

| 노드 성격 | OptionType | BaseValue | 비고 |
|---|---|---|---|
| 스킬 습득 | `SkillGrant` | 미사용 | 슬롯 2에 강화 옵션을 함께 두는 것이 일반적 |
| 스킬 계수 강화 | `Modifier` | 사용 | `SkillModifier` 경유 |
| 효과 추가 | `Modifier`(Append) | 미사용 | 스킬에 효과를 하나 더 붙인다 |
| 순수 스탯 | `Stat` | 사용 | `StatContainer` 로 직행 |

**실제 예 — 노드 1 (쌍검 찌르기)**

```
Option    = OPT_LEARN_DualBlades_Active_01   (SkillGrant)   값 미사용
Option_02 = OPT_DMG_DualBlades_Active_01     (Modifier)     Base 0 / PerLevel 0.1
MaxLevel  = 5
```

1포인트면 스킬을 배우고 피해 증가는 0%, 5포인트면 +40%가 된다.

**실제 예 — 노드 4 (연속공격)**

```
Option    = OPT_APPEND_DualBlades_AtkSpeedBuff  (Modifier, Append)  값 미사용
Option_02 = OPT_ATKSPEED_DualBlades_Buff        (Modifier)  Base 0.1 / PerLevel 0.0125
PrevNodeID = 1 / RequireTreePoint = 5 / MaxLevel = 5
```

슬롯 1이 쌍검 찌르기에 공속 버프 효과를 **추가**하고, 슬롯 2가 그 버프의 수치를 키운다.

### 6.5 투자와 회수

| 동작 | API | 결과 |
|---|---|---|
| 1포인트 투자 | `MasteryBook.TryInvest(id, nodeId)` | 노드 레벨 +1 |
| 1포인트 회수 | `MasteryBook.TryRefund(id, nodeId)` | 노드 레벨 -1 |
| 전체 초기화 | `MasteryBook.ResetTree(id)` | `NodeLevels` 를 비우고 전액 복구 |

**무료이며 상시 가능하다.** 횟수 제한도 비용도 없다. 싱글플레이이고 빌드 실험 자체가 콘텐츠다.

마스터리별로 독립이다 — 쌍검 트리를 초기화해도 룬검 트리는 그대로다.

**막힌 이유를 enum으로 돌려준다.** UI가 "왜 안 되는지"를 안내해야 하므로 성패 bool로는 부족하다.

| `InvestBlock` | 의미 |
|---|---|
| `MaxLevel` | 이미 만렙 |
| `RequireTreePoint` | 행 게이트 미달 |
| `PrevNodeNotMax` | 선행 노드가 만렙이 아님 |
| `NoPoint` | 가용 포인트 없음 |

| `RefundBlock` | 의미 |
|---|---|
| `NoLevel` | 투자한 적이 없다 |
| `NextNodeInvested` | **후속 노드에 투자가 남아 있다** |
| `RequireTreePoint` | **회수하면 다른 노드의 행 게이트가 깨진다** |

> 뒤의 두 사유는 "이 노드만 빼면 아래가 무효가 되는" 상황이다. 이때 UI는 버튼을 잠그는 대신 **트리 전체 초기화를 제안**한다.

> **투자 판정의 출처는 `GetInvestBlock` 하나다.** `TryInvest` 와 노드 팝업이 모두 이 함수만 본다. 판정을 두 벌 두면 규칙이 바뀔 때 버튼과 실제 동작이 조용히 갈라진다.

투자·회수·초기화는 **스탯 캐시와 스킬 리졸브 캐시를 모두 무효화**한다. 단, **지금 장착 중인 마스터리일 때만** 히어로를 다시 굽는다 — 다른 무기의 트리를 손봐도 현재 빌드는 변하지 않는다.

### 6.6 표시 규칙

| 대상 | 표시 |
|---|---|
| 마스터리 레벨 | `쌍검 Lv.87 / 300` |
| 전 마스터리 레벨 총합 | `총합 레벨 N / 최대` + 총합 보너스 문구 |
| 가용 포인트 | `포인트 12` |
| 노드 | `노드명 Lv.2 / 5` + 현재 값 → 다음 레벨 값 |
| 잠긴 노드 (게이트) | 회색 + `트리 포인트 15 필요` |
| 잠긴 노드 (선행) | 회색 + `{선행 노드명} 만렙 필요` |
| 지식의 서 | 보유 수 + `3 / 15 사용` |

옵션 문구는 `StatDetail.DisplayFormat` 을 사용한다.

## 7. 스킬포인트와 지식의 서

### 7.1 포인트 예산

| 출처 | ID | MaxPoint | 귀속 |
|---|---|---|---|
| 마스터리 레벨업 | `SkillPoint_Level` | 60 | 마스터리별 |
| 지식의 서 (아이템) | `SkillPoint_Item` | 15 | 마스터리별 |
| 업적 | `SkillPoint_Achievement` | 5 | **전 마스터리 공유** |

```
마스터리별 가용 포인트
  = min(마스터리 레벨, 60)                    ← 레벨분
  + 그 마스터리에 사용한 지식의 서 수          ← 아이템
  + 업적 포인트 보유량                        ← 공유, 차감되지 않음
  - Σ (그 마스터리 트리의 투자 포인트)
```

**한 마스터리 최대 예산은 80포인트다.**

> **`IsShared = TRUE` 의 정확한 의미**
>
> 업적 포인트는 마스터리별로 나눠 쓰는 것이 아니라 **모든 마스터리가 각자 전액을 사용한다.** 업적 5개를 달성했다면 쌍검에서도 5포인트, 석궁에서도 5포인트를 쓸 수 있다. 어느 트리에 썼는지 추적할 필요가 없고 무기를 바꿔도 포인트가 묶여 있지 않다.
>
> "공유"가 "나눠 쓴다"로 읽히기 쉬우므로 주의한다. 정확히는 **전역 정액 보너스**다.

> **레벨분은 60에서 멈춘다.** 마스터리 레벨 상한은 300이지만 포인트는 60레벨까지만 나온다. 이후 레벨은 `LevelBonusOption` 만 올린다.

### 7.2 SkillPoint 테이블 (5컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!SkillPoint` | 기본 키 |
| `MaxPoint` | `!int` | 이 종류로 얻을 수 있는 최대 포인트 |
| `Desc` | `!string` | 설명 |
| `IsShared` | `!bool` | TRUE면 전 마스터리가 각자 전액 사용 |
| `SourceType` | `!SkillPointSourceType` | 지급 경로 구분 |

### 7.3 지식의 서

`Item` `1030300001` / `MainCategory = Consumable` / `SubCategory = SkillBook` / `Grade = Mythic`

```
Consumable  1030300001  SkillPoint / SkillPoint_Item / 1
                          ↓
SkillPoint  SkillPoint_Item  MaxPoint 15  SourceType Item
```

- **대상 마스터리는 열려 있는 스킬 트리 화면이 결정한다.** 테이블에 없다. 지정이 없으면 현재 장착 무기로 폴백하고, 무기를 들지 않았으면 실패한다.
- `MaxPoint` 상한은 런타임 카운터(`ItemPointUsed`)가 막는다.
- **효과를 먼저 굴리고 성공했을 때만 아이템을 차감한다.** 상한에 막혔는데 아이템이 사라지면 복구할 수 없다.
- 지급량은 `Consumable.EffectParam_2` 가 정한다. 상위 서적(3포인트)을 만들 수 있는 구조다.

### 7.4 업적 포인트

**업적 시스템은 미구현이다.** `MasteryBook.SetAchievementPoint(value)` 인터페이스만 열려 있고 호출하는 곳이 없다.

## 8. 저장 데이터 및 계산 순서

### 8.1 저장 데이터

```
CharacterLevel     int
CharacterTotalExp  int
EquippedWeaponUID  long                    ← 장착 무기 인스턴스

MasteryProgress    Dictionary<WeaponMastery, {
                       TotalExp      int
                       ItemPointUsed int                  ← 지식의 서 사용 횟수 (0~15)
                       NodeLevels    Dictionary<int,int>  ← NodeID → 투자 레벨
                   }>

AchievementPoint   int                     ← 전역 (0~5)
```

- `MasteryProgress` 는 **한 번이라도 든 무기만** 항목이 생긴다.
- `NodeLevels` 에는 **투자한 노드만** 넣는다. 0레벨 노드는 키를 두지 않는다.
- **레벨은 저장하지 않는다.** 누적 경험치에서 파생한다.

### 8.2 저장하지 않고 파생시키는 값

| 값 | 계산 |
|---|---|
| 마스터리 레벨 | `MasteryLevelExp` 이분 탐색 |
| 현재 마스터리 | 장착 무기의 `Equipment.WeaponType` → 역참조 |
| 기본공격 · 트리 · RangeType · 애니메이터 | 현재 마스터리 행 조회 |
| 레벨 기반 포인트 | `min(Level, 60)` |
| 가용 포인트 | 7.1절 식 |
| `LevelBonusOption` 총합 | 전 마스터리 Level × `LevelBonusPerLevel` |
| 노드 해금 여부 | `GetInvestedAboveRow` 와 `PrevNodeID` 의 만렙 여부 |
| 보유 스킬 목록 | 평타 + 트리에서 `SkillGrant` 로 습득한 것 |
| 캐릭터 기본 스탯 | `CharacterStat` + `CharacterLevel` |

### 8.3 최종 스탯 계산 순서

```
[1] 기본값        CharacterStat (캐릭터 레벨)      → StatDetail_*_Base
[2] 마스터리 보너스 전 마스터리 LevelBonusOption    → Option   ★ 무기 무관, 항상 적용
[3] 스킬 트리      현재 마스터리의 NodeLevels       → Option   ★ 무기 교체 시 통째로 교체
[4] 장비          EquipOption 기본 · 해금 옵션      → Option
[5] 버프          SkillEffect (StatChange)        → StatDetail
```

> **합성식과 클램프는 `기반테이블_설계.md` 8장이 소유한다.** 이 절은 [2]와 [3]이 무엇을 공급하는지만 서술한다.

[2]와 [3]의 차이가 이 시스템의 핵심이다. **마스터리 보너스는 누적되어 영구히 남고, 트리 투자는 그 무기를 들었을 때만 작동한다.**

`Modifier` 타입 옵션은 이 식에 들어가지 않고 스킬 리졸브 파이프라인으로 전달된다 (`스킬시스템_설계.md` 11장).

**`MasteryAspect` 가 [2]와 [3]을 모두 담당하며 source 태그는 `"Mastery"` 하나다.** 무기 교체 시 `RemoveAllFromSource("Mastery")` 로 통째로 걷어내고 다시 붙인다.

### 8.4 캐시 무효화

| 이벤트 | 스탯 캐시 | 스킬 리졸브 캐시 |
|---|---|---|
| 무기 교체 | ○ | ○ (트리·평타가 통째로 바뀐다) |
| 노드 투자 / 회수 | ○ | ○ |
| 트리 초기화 | ○ | ○ |
| 지식의 서 사용 | ○ | ○ (가용 포인트가 늘어난다) |
| 마스터리 레벨업 | ○ | ✕ (`LevelBonusOption` 만 변함) |
| 캐릭터 레벨업 | ○ | ✕ |
| 장비 착용 / 해제 | ○ | ○ |
| **스탯 버프 부여 / 만료** | **○** | ✕ |
| 구조 변경 버프 (모디파이어 동반) | ○ | ○ |

> **스탯 버프는 반드시 스탯 캐시를 무효화한다**
>
> `StatChange` 효과는 모든 `StatDetail` 을 대상으로 할 수 있다. 스탯 캐시를 갱신하지 않으면 최대 체력·방어력·이동속도를 바꾸는 버프가 **아무 효과도 내지 않는다.**
>
> 스킬 문서 11.4의 시전 시점 스냅샷은 `Atk` / `CritRate` / `CritDamage` 만 담는다. 그것은 이미 발사된 투사체의 데미지가 흔들리지 않게 하는 장치이지 스탯 반영을 대체하지 않는다.

두 캐시를 분리해 두면 레벨업마다 리졸브를 다시 돌 필요가 없다.

| 9 | `PrevNodeID` 순환 참조 | 오류 |
| 10 | `PrevNodeID` 가 자기보다 아래 행을 가리키는가 | 경고 (게이트와 모순) |
| 11 | `Option` 슬롯이 비었는데 `BaseValue` 에 값이 있는가 | 경고 (오타 탐지) |
| 12 | `MaxLevel` 이 0 이하 | 오류 |
| 13 | **행 게이트 데드락** — `RequireTreePoint` 가 위쪽 행들의 총 용량을 초과 | 오류 |
| 14 | 보드 총 용량이 예산(80)보다 작은가 | 경고 (빌드 선택이 발생하지 않는다) |
| 15 | `SkillGrant` 노드가 가리키는 스킬이 실존하는가 | 오류 |
| 16 | `Modifier` 노드의 대상 스킬을 **이 트리에서 습득 가능한가** | 경고 |
| 17 | 트리 노드의 피해 옵션이 마스터리 `RangeType` 과 맞는가 | 경고 (근접 트리의 원거리 옵션은 죽은 투자) |
| 18 | `SkillPoint.SourceType` 이 비어 있는가 | 경고 |

### 9.1 행 게이트 데드락 계산

```
행 R 의 게이트가 유효하려면
  RequireTreePoint(R) ≤ Σ MaxLevel(1행 ~ R-1행 노드 전체)
```

**현재 트리(101) 검산**

| 행 | 노드 수 | 행 용량 | 위쪽 누적 | 게이트 | 판정 |
|---|---|---|---|---|---|
| 1 | 3 | 13 | ‒ | 0 | OK |
| 2 | 3 | 13 | 13 | 5 | OK |
| 3 | 3 | 13 | 26 | 15 | OK |
| 4 | 3 | 11 | 39 | 25 | OK |
| 5 | 4 | 16 | 50 | 40 | OK |
| 6 | 2 | 8 | 66 | 55 | OK |

**보드 총 용량 74 < 예산 80.** 데드락은 없지만 **모든 노드를 만렙까지 찍고도 6포인트가 남는다** — 빌드 선택이 발생하지 않는 상태다. 실제 데이터에서는 총 용량을 예산의 1.5~2배(120~160)로 잡는다.

## 10. 신규 무기 · 트리 작성 가이드

### 10.1 작성 절차

```
STEP 1  WeaponType enum 끝에 항목 추가
STEP 2  Equipment 에 무기 아이템 행 추가 (Item 행과 세트)
STEP 3  WeaponMastery 행 추가        → RangeType / 애니메이터 / 레벨 보너스
STEP 4  평타 스킬 작성                → SkillCategory = Normal
STEP 5  SkillTreeNodeGroupID 대역 확보 → 트리 노드 작성
STEP 6  노드가 참조할 Option / SkillModifier 작성
STEP 7  검증 (9장) + 실행 후 부팅 로그 확인
```

### 10.2 트리 설계 기준

| 항목 | 기준 |
|---|---|
| 보드 크기 | 6×4 (현재 전 마스터리 동일) |
| 총 용량 | 예산(80)의 1.5~2배 = **120~160** |
| 행 게이트 | 직전 행들의 누적 용량의 **50~65%** |
| 노드당 `MaxLevel` | 3~5 |
| 스킬 습득 노드 | 1행에 배치. 슬롯 2에 강화 옵션을 함께 둔다 |
| 피해 옵션 | 마스터리 `RangeType` 과 맞는 것만 |

### 10.3 노드 패턴 3종

**① 스킬 습득 + 강화 (슬롯 2개)**

```
Option    = OPT_LEARN_{스킬}     SkillGrant   값 미사용
Option_02 = OPT_DMG_{스킬}       Modifier     Base 0 / PerLevel 0.1
MaxLevel  = 5
```

**② 효과 추가 + 그 효과의 수치 (슬롯 2개)**

```
Option    = OPT_APPEND_{버프}    Modifier(Append)   값 미사용
Option_02 = OPT_{항목}_{버프}    Modifier           Base / PerLevel 사용
PrevNodeID = (습득 노드)
```

**③ 순수 스탯 (슬롯 1개)**

```
Option    = OPT_ATK_ADD 등       Stat
BaseValue / PerLevelValue 사용
```

### 10.4 작성 후 체크리스트

```
□ WeaponType ↔ WeaponMastery 가 1:1인가
□ NormalAttackSkill 의 SkillCategory 가 Normal 인가
□ AnimControllerName 이 실제 오버라이드 컨트롤러 이름인가
□ LevelBonusOption 이 OptionType = Stat 인가
□ 노드 좌표가 MaxRow × MaxColumn 안에 있고 중복이 없는가
□ 행 게이트가 위쪽 행 누적 용량을 넘지 않는가 (9.1)
□ 보드 총 용량이 예산의 1.5배 이상인가
□ PrevNodeID 가 같은 GroupID 안을 가리키는가
□ 옵션 슬롯이 비었는데 값만 들어 있지 않은가
□ 트리의 피해 옵션이 RangeType 과 맞는가
□ 부팅 로그에 MasteryCatalog / OptionCatalog 경고가 없는가
```

### 10.5 자주 하는 실수

| 실수 | 증상 |
|---|---|
| 행 게이트를 트리 전체 투자 기준으로 잡음 | 의도보다 늦게 열린다 (기준은 위쪽 행) |
| 노드 값을 0레벨 기준으로 넣음 | 1포인트 투자 시 값이 0 |
| `LevelBonusOption` 에 `Modifier` 지정 | 들고 있지도 않은 무기의 스킬이 변형 — 가드에 막혀 무시됨 |
| 새 마스터리에 `SkillTreeNodeGroupID` 를 기존 값으로 둠 | 다른 무기의 트리가 그대로 뜬다 (현재 상태) |
| `Loadout.AddExp` 직접 호출 | 마스터리 경험치가 누락된다 |

## 12. 제약 사항 및 미구현 항목

### 12.1 미구현 / 미완

| 항목 | 내용 |
|---|---|
| **총합 마스터리 레벨 보너스** | `MasteryLevelBonus` 2행이 **UI 문구로만 표시되고 스탯에 반영되지 않는다** (4.5절). `MasteryAspect` 에 적용 경로 추가 필요 |
| **마스터리별 트리** | 4종이 전부 `SkillTreeNodeGroupID = 101` 을 공유한다. 쌍검용 트리 하나뿐이다 |
| 업적 시스템 | 미구현. `SetAchievementPoint` 인터페이스만 열려 있다 |
| 추가 무기 | 4종 외 계획 없음 |
| `Dev_SkillIDs` | 개발용 임시 컬럼. 정식 전환 시 제거 대상 |

### 12.2 임시 데이터

- **`SkillTreeNode` 18개 중 실제 이름이 붙은 것은 4개**(쌍검 찌르기 / 강타 / 노드3 / 연속공격)뿐이고 나머지는 `노드N` + 더미 설명이다.
- **보드 총 용량 74가 예산 80보다 작다.** 전 노드를 만렙까지 찍고도 포인트가 남아 빌드 선택이 발생하지 않는다 (9.1).
- `LevelBonusPerLevel` 수치는 임시값이다. 300레벨 총량 기준으로 재조정이 필요하다.
- 노드 2(`강타`)의 설명이 "일반공격 5번마다 범위 데미지"인데 실제 옵션은 `OPT_DAMAGE_BONUS_ADD`(피해량 증가)다. 설명과 효과가 어긋나 있다.

### 12.3 데이터 작성 시 주의

1. `WeaponType` enum에 항목을 **중간 삽입하면 기존 장비 데이터가 어긋난다.** 신규 항목은 끝에 추가한다.
2. 노드 값은 **1레벨 기준**이다(`BaseValue + PerLevel × (Level - 1)`). 장비의 `Val` 은 0레벨 기준이므로 규칙이 반대다.
3. 노드당 옵션은 **2개까지**다. 그 이상은 노드를 나눈다.
4. 스킬 습득 슬롯은 값을 쓰지 않는다. 강화는 슬롯 2나 별도 노드로 분리한다.
5. 트리 노드에는 마스터리의 `RangeType` 과 맞는 피해 옵션만 넣는다.
6. 행 게이트는 **위쪽 행들의** 누적 용량을 넘지 않아야 하며, 50~65% 수준이 적정하다.
7. `MasteryLevelExp` 는 전 마스터리 공용이다. 무기별로 나누지 않는다.
8. 방어 상수 K가 쓰는 레벨은 **캐릭터 레벨**이다. 마스터리 레벨이 아니다.
9. 경험치를 주는 새 경로는 반드시 `Account.AddExp` 를 쓴다.
10. 비율(Ratio/Amp) 옵션은 `Atk`·`MaxHp`·`HpRegen`·`Def`·`LifeOnHit` **5개 스탯에만** 붙일 수 있다.
