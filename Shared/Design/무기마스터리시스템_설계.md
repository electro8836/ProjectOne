## 1. 개요 및 설계 원칙

### 1.1 프로젝트 전제

| 항목 | 값 |
|---|---|
| 플레이 | 싱글플레이, 단일 캐릭터 |
| 범위 | 무기 마스터리 · 레벨 해금 스킬 · 스킬 슬롯 |
| 자원 | **없음.** 마나·탄약 제약을 두지 않는다 |
| 캐릭터 레벨 | **없다.** 대표 레벨은 장착 무기의 마스터리 레벨이다 |

**직업 개념이 없다.** 캐릭터는 하나이며, **어떤 무기를 들고 있는가가 그 순간의 정체성**이 된다. 무기와 마스터리는 1:1로 대응하고, 마스터리마다 고유한 스킬 8개를 가진다.

### 1.2 성장 축

| 축 | 역할 |
|---|---|
| **아이템** | 능력치 성장의 중심 |
| **무기 마스터리** | 스킬 해금 + 레벨 보너스 스탯 |
| **정수 강화 트리** | 게임 중 얻는 재화 `정수` 로 캐릭터를 영구 강화한다. 별도 설계 (11장) |

캐릭터 기본 스탯은 고정값이며 레벨로 오르지 않는다 (3장).

### 1.3 설계 원칙

1. **무기 교체에 비용·제약·손실이 없다.** 각 마스터리의 진행도는 독립적으로 보존된다.
2. **마스터리 레벨 보너스는 무기와 무관하게 항상 적용되고, 스킬은 그 무기를 들었을 때만 작동한다.** 이 둘의 차이가 시스템의 핵심이다.
3. **스킬은 마스터리 레벨로 해금하고, 슬롯 4칸에 골라 낀다.** 같은 무기라도 어떤 4개를 끼느냐로 플레이가 달라진다.
4. **스킬 위력은 고정이다.** 해금 이후 마스터리 레벨이 올라도 스킬 자체는 강해지지 않는다. 강해지는 것은 스탯(아이템·레벨 보너스·정수)이다.
5. **레벨·해금 여부는 저장하지 않고 계산한다.** 저장하는 것은 누적 경험치와 슬롯 구성뿐이다.

## 2. Enum 정의

### 2.1 WeaponMastery (EnumTable)

`Mastery_GreatSword` / `Mastery_Blade` / `Mastery_Shuriken` / `Mastery_Rifle`

### 2.2 WeaponType

`GreatSword` / `Blade` / `Shuriken` / `Rifle`

**`WeaponMastery` 와 1:1로 대응한다.** 대응 마스터리가 없는 `WeaponType` 은 오류다.

> enum에 항목을 **중간 삽입하면 기존 장비 데이터가 어긋난다.** 신규 항목은 반드시 끝에 추가한다.

### 2.3 WeaponRangeType

`Melee` / `Ranged`

데미지 계산 [4]단계에서 `Stat_MeleeDamageBonus` / `Stat_RangeDamageBonus` 중 무엇이 적용되는지를 결정한다 (`스킬시스템_설계.md` 10.4). **장착 무기 단위로 결정되며 스킬별 구분은 없다.**

### 2.4 OptionTypes (외부 — `Option.xlsx`)

`Stat` / `SkillGrant` / `SkillLevel` / `Modifier`. 정의는 `기반테이블_설계.md` 6장이 소유한다.

## 3. 캐릭터 기본 스탯

### 3.1 CharacterStat

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 기본 키(일련번호) |
| `StatDetailID` | `!StatDetail` | 대상 스탯. 반드시 `_Base` 계열 |
| `BaseValue` | `!float` | 기본값. **레벨 성장이 없으므로 이 값이 그대로 최종 기본값이다** |

**캐릭터는 1종이므로 그룹 키가 없다.** (몬스터는 `MonsterStat.GroupID` 로 묶인다)

현재 데이터 10행은 `기반테이블_설계.md` 4.2절에 있다.

> **캐릭터 레벨이 없다.** 레벨당 스탯 성장(`PerLevel`)도, 캐릭터 경험치 곡선(`CharacterLevelExp`)도 없다. 몬스터는 여전히 레벨과 `PerLevel` 성장을 쓴다 (`몬스터시스템_설계.md`).

### 3.2 방어 상수 K의 기준

스킬 문서 10.3절의 방어 공식 `K = 50 + (Level × 20)` 이 쓰는 레벨은 **전투에 낀 몬스터의 레벨**이다. 플레이어 쪽에는 레벨이 없다.

| 공격 → 피격 | 기준 레벨 |
|---|---|
| 몬스터 → 플레이어 | 공격한 몬스터의 레벨 |
| 플레이어 · 소환물 → 몬스터 | 맞는 몬스터의 레벨 |

**마스터리 레벨은 기준이 될 수 없다.** 무기별로 다르므로 무기를 바꾸는 것만으로 K가 변한다.

### 3.3 레벨 표시

**대표 레벨은 장착 무기의 마스터리 레벨이다.** 마을 HUD · 히어로 정보 · 장비창 · 랭킹 프로필이 이 값을 표시한다. 무기를 들지 않았으면 레벨을 표시하지 않는다.

강함의 척도는 레벨이 아니라 **전투력**이다 (`전투력시스템_설계.md`).

## 4. WeaponMastery — 무기 마스터리

### 4.1 컬럼 정의 (8컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!WeaponMastery` | 기본 키. `Mastery_` 접두 |
| `Name` | `!string` | 표시명 |
| `Icon` | `!string` | 마스터리 아이콘 |
| `WeaponType` | `!WeaponType` | 대응 무기 종류. **마스터리마다 유일** |
| `RangeType` | `!WeaponRangeType` | 근접 / 원거리 |
| `LevelBonusOption` | `!Option` | 이 마스터리 레벨당 보너스. **`Stat` 타입만 허용** |
| `LevelBonusPerLevel` | `!float` | 레벨당 증가량 |
| `Dev_SkillIDs` | `!Skill[]` | **개발용.** 해금 레벨과 무관하게 강제로 보유시킬 스킬 목록 |

> **`Dev_SkillIDs` 는 정식 데이터가 아니다.** 해금 없이 스킬을 테스트하기 위한 개발 편의 컬럼이며 현재 전 행이 비어 있다. 정식 전환 시 제거 대상이다.

### 4.2 현재 4종

| ID | 무기 | RangeType | LevelBonusOption | PerLevel |
|---|---|---|---|---|
| `Mastery_GreatSword` | 대검 | Melee | `OPT_ATK_ADD` | 1 |
| `Mastery_Blade` | 태도 | Melee | `OPT_ATK_SPEED_ADD` | 0.001 |
| `Mastery_Shuriken` | 수리검 | Ranged | `OPT_CRIT_RATE_ADD` | 0.001 |
| `Mastery_Rifle` | 소총 | Ranged | `OPT_CRIT_DAMAGE_ADD` | 0.02 |

### 4.3 마스터리가 소유하는 것

```
무기 장착 ─┬─ 무기 행(Equipment)
           │    ├─ 기본공격       = NormalAttackSkill
           │    └─ 애니메이터      = AnimControllerName
           └─ Equipment.WeaponType → WeaponMastery 역참조
                ├─ 스킬 8개       = MasterySkill (해금 레벨)
                ├─ 스킬 슬롯 4칸   = 이 마스터리의 슬롯 구성
                ├─ 근접/원거리     = RangeType
                └─ 경험치 적립처    = 이 마스터리
```

무기를 바꾸면 **스킬 구성이 통째로 바뀐다.** 슬롯 구성은 마스터리마다 따로 저장되므로, 대검으로 돌아오면 대검에 끼워 둔 4개가 그대로 돌아온다.

**평타와 애니메이터는 마스터리가 아니라 무기 행이 갖는다.** 같은 마스터리 안에서도 무기마다 평타 판정이 다를 수 있다(예: 소총 마스터리의 저격총은 투사체, 레이저총은 즉발 직선 범위). 마스터리당 평타 판정은 2종까지 두고, 나머지 무기는 외형·스탯만 다르다. 무기 행의 두 값은 마스터리와 무관하게 무기마다 채운다.

| 무기 ID | WeaponType | `NormalAttackSkill` | `AnimControllerName` |
|---|---|---|---|
| `1010101001` | GreatSword | `Skill_GreatSword_Attack` | `AOC_Hero_GreatSword` |
| `1010101002` | Blade | `Skill_Blade_Attack` | `AOC_Hero_Blade` |
| `1010101003` | Shuriken | `Skill_Shuriken_Attack` | `AOC_Hero_Shuriken` |
| `1010101004` | Rifle | `Skill_Rifle_Attack` | `AOC_Hero_Rifle` |

### 4.4 무기 미착용 상태

| 항목 | 상태 |
|---|---|
| 기본공격 | **없다 — 공격할 수 없다** |
| 스킬 | 적용되지 않는다 |
| 마스터리 경험치 | **적립되지 않고 버려진다** |
| 마스터리 레벨 보너스 | **전부 그대로 적용된다** |
| 장비 옵션 · 캐릭터 기본 스탯 | 정상 작동 |
| 레벨 표시 | 없음 |
| 애니메이터 | 기본 컨트롤러로 복귀 |

### 4.5 레벨 보너스 — 두 축이 있다

**보너스는 두 종류이며 기준이 되는 레벨이 다르다.**

| 출처 | 기준 레벨 | 적용 |
|---|---|---|
| `WeaponMastery.LevelBonusOption` | **각 무기의 마스터리 레벨** | 전 마스터리를 합산. 무기와 무관하게 항상 |
| `MasteryLevelBonus.LevelBonusOption` | **전 마스터리 레벨의 총합** (현재 최대 400) | 총합에 비례하는 전역 보너스 |

```
[무기별]  Σ (마스터리i.Level × 마스터리i.LevelBonusPerLevel)
[총합]    (Σ 마스터리i.Level) × MasteryLevelBonus.LevelBonusPerLevel
```

> **이것이 무기를 바꿔도 손해가 없는 이유다.** 대검을 100레벨까지 키운 뒤 수리검을 들어도 대검이 준 공격력 보너스는 그대로 남는다. 키운 것은 사라지지 않는다.

**`MasteryLevelBonus` 테이블 (3컬럼)**

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 일련번호 |
| `LevelBonusOption` | `!Option` | `Stat` 타입만 |
| `LevelBonusPerLevel` | `!float` | 총합 레벨당 증가량 |

현재 2행 — `OPT_ATK_ADD` +2.5/레벨, `OPT_MAX_HP_ADD` +5/레벨.

두 축 모두 `MasteryAspect` 가 스탯에 적용한다. 총합 보너스는 서버 전투력 계산(`BattlePowerRules`)에도 같은 식으로 들어간다.

**`LevelBonusOption` 은 `Stat` 타입만 허용한다.** 모디파이어를 붙이면 들고 있지도 않은 무기의 스킬이 변형된다. `MasteryAspect.applyStatOption` 의 `statOnly` 가드가 이를 막는다.

## 5. 마스터리 레벨과 경험치

### 5.1 MasteryLevelExp

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 레벨 (PK) |
| `TotalExperience` | `!int` | 해당 레벨에 도달하기 위한 **누적** 경험치 |

```
다음 레벨 요구량 = MasteryLevelExp[Level + 1].TotalExperience
                 - MasteryLevelExp[Level].TotalExperience
```

**만렙은 100이다.** 테이블의 마지막 행이 만렙이며 **전 마스터리 공용**이다. 무기별로 나누지 않는다.

`ID = 1` 행의 `TotalExperience` 는 0이다. 레벨은 저장하지 않고 누적 경험치에서 **이분 탐색 한 번**으로 파생한다 (공유 `MasteryRules` — 클라 `MasteryCatalog` 와 서버가 같은 계산을 쓴다). **만렙 초과분은 버린다.**

> **만렙은 확장을 전제로 한다.** 만렙을 올릴 때는 `MasteryLevelExp` 에 행을 이어 붙이고, 새 구간에서 해금되는 스킬을 `MasterySkill` 에 추가한다 (11장).

### 5.2 경험치 귀속 규칙

> **경험치 진입점은 `Account.AddExp(amount)` 하나다.**

```csharp
Account.AddExp(amount)
  └ Mastery.AddExpToCurrent(amount)   현재 장착 무기의 마스터리
```

서버가 절대값을 내려주는 경로는 서버 값으로 덮어쓴다. 서버는 필드 처치 정산(`FieldSettle`)·던전 클리어(`DungeonClear`)에서 그 시점 장착 무기의 마스터리에 같은 값을 적립한다.

**무기를 들지 않았으면 경험치는 버려진다.**

각 마스터리는 **병렬로 존재하며 리셋 개념이 없다.** 한 번이라도 든 무기만 진행도 항목이 생기고, 없으면 Lv1 로 취급한다.

### 5.3 레벨업 보상

| 보상 | 내용 |
|---|---|
| 레벨 보너스 스탯 | 4.5절의 두 축이 레벨만큼 오른다 |
| 스킬 해금 | 해금 레벨에 도달한 스킬을 얻는다 (6장) |

## 6. 스킬 해금 (MasterySkill)

### 6.1 구조

**마스터리마다 스킬 8개가 정해져 있고, 마스터리 레벨에 도달하면 하나씩 해금된다.** 포인트를 쓰거나 고르는 단계가 없다. 같은 무기라면 모든 유저의 해금 순서가 같다.

**평타는 해금 대상이 아니다.** 무기 행의 `NormalAttackSkill` 이며 무기를 들면 항상 있다.

### 6.2 MasterySkill (4컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 기본 키. 전역 일련번호 |
| `WeaponMastery` | `!WeaponMastery` | 소속 마스터리 |
| `UnlockLevel` | `!int` | 해금 마스터리 레벨 (1 ~ 만렙) |
| `SkillID` | `!Skill` | 해금되는 스킬 |

해금 목록의 표시 순서는 `UnlockLevel` 오름차순이다.

### 6.3 해금 레벨 기준 `가안`

| 순서 | 해금 레벨 | 의미 |
|---|---|---|
| 1 | 1 | 처음 무기를 들면 바로 배운다 |
| 2 | 5 | |
| 3 | 10 | |
| 4 | 20 | **슬롯 4칸이 다 찬다** |
| 5 | 35 | 이때부터 "무엇을 뺄지" 선택이 생긴다 |
| 6 | 50 | |
| 7 | 75 | |
| 8 | 100 | 만렙에 마지막 스킬 |

**앞쪽은 촘촘하게, 뒤쪽은 넓게 둔다.** 슬롯이 비어 있는 기간이 길면 전투가 단조롭다. 슬롯이 다 찬 뒤의 해금은 하나하나가 "세트를 바꿀까"를 고민하게 하는 이벤트다.

### 6.4 스킬 위력

**스킬 위력은 고정이다.** 스킬 행의 계수가 그대로 쓰이며 마스터리 레벨·투자에 따른 성장이 없다.

스킬을 변형하는 `Modifier` 옵션은 장비 옵션에서만 온다 (`스킬시스템_설계.md` 11장).

## 7. 스킬 슬롯

### 7.1 규칙

| 항목 | 규칙 |
|---|---|
| 슬롯 수 | **4칸** |
| 대상 | 해금한 스킬 8개 전부 (액티브·패시브 구분 없이 1칸씩) |
| 평타 | 슬롯 밖. 항상 붙어 있다 |
| 단위 | **마스터리별로 따로** 저장한다 |
| 중복 | 같은 스킬을 두 칸에 낄 수 없다 |
| 빈 칸 | 허용한다 |
| 작동 범위 | **슬롯에 낀 스킬만** 히어로에 등록된다. 해금했어도 슬롯 밖이면 작동하지 않는다 |
| 비용 | 없음 |

### 7.2 교체 가능 장소

| 장소 | 교체 |
|---|---|
| 마을 | 가능 |
| 필드 | 가능 |
| 던전 | **불가** — 입장 시점의 구성으로 끝까지 싸운다 |

던전 안에서는 마스터리 화면의 슬롯 조작을 막고 이유를 안내한다.

### 7.3 해금 시 자동 장착

새 스킬이 해금될 때 그 마스터리에 빈 칸이 있으면 **앞쪽 빈 칸에 자동으로 넣는다.** 빈 칸이 없으면 넣지 않는다 — 이미 짜 둔 세트를 건드리지 않는다.

### 7.4 반영과 저장

- 슬롯을 바꾸면 **지금 장착 중인 마스터리일 때만** 히어로의 스킬 등록을 다시 굽는다. 다른 무기의 슬롯을 손봐도 현재 빌드는 변하지 않는다.
- **조작마다 서버에 보내지 않는다.** 바뀐 마스터리의 슬롯만 모아 화면 닫기·일시정지·종료 때 한 번에 보낸다 (`SaveMasterySlots`).
- 서버는 조작 과정이 아니라 **슬롯의 최종 상태**를 검증한다 (`MasteryRules.ValidateSlots`). 실패하면 전부 거절하고 클라는 바뀐 목록을 되살려 다음 기회에 다시 보낸다.

| 검증 | 실패 조건 |
|---|---|
| 칸 수 | 4칸 초과 |
| 소속 | 그 마스터리의 `MasterySkill` 에 없는 스킬 |
| 해금 | **서버의** 누적 경험치로 계산한 레벨이 `UnlockLevel` 미만 |
| 중복 | 같은 스킬이 두 칸 이상 |

> 미정산 경험치로 해금한 스킬을 끼운 경우 첫 전송은 거절될 수 있다. 정산 뒤 재전송에서 통과한다.

### 7.5 표시 규칙

| 대상 | 표시 |
|---|---|
| 마스터리 레벨 | `대검 Lv.87 / 100` |
| 전 마스터리 레벨 총합 | `총합 레벨 N / 최대` + 총합 보너스 문구 |
| 해금 목록 | 8개를 `UnlockLevel` 순으로. 잠긴 스킬은 회색 + `Lv.35 해금` |
| 슬롯 | 4칸. 빈 칸은 `비어 있음` |
| 다음 해금 | `다음 스킬까지 Lv.N` |

## 8. 저장 데이터 및 계산 순서

### 8.1 저장 데이터

서버가 보관한다. 마스터리는 `MasteryDto`, 장착은 `LoadoutDto` 로 직렬화된다 (`뒤끝서버시스템_설계.md` 3장).

```
EquippedWeaponUID  long                    ← 장착 무기 인스턴스

MasteryProgress    Dictionary<WeaponMastery, {
                       TotalExp    int
                       SkillSlots  Skill[4]     ← 빈 칸은 None
                   }>
```

- `MasteryProgress` 는 **한 번이라도 든 무기만** 항목이 생긴다.
- **레벨은 저장값이 아니라 파생값이다.** 클라는 누적 경험치에서 계산한다. DTO 의 `level` 필드는 서버가 경험치를 바꿀 때 함께 써 두는 콘솔 표시용 사본이며 클라는 읽지 않는다.

### 8.2 저장하지 않고 파생시키는 값

| 값 | 계산 |
|---|---|
| 마스터리 레벨 | `MasteryLevelExp` 이분 탐색 |
| 현재 마스터리 | 장착 무기의 `Equipment.WeaponType` → 역참조 |
| 기본공격 · 애니메이터 | 장착 무기의 `Equipment` 행 조회 |
| RangeType | 현재 마스터리 행 조회 |
| 해금한 스킬 목록 | 그 마스터리의 `MasterySkill` 중 `UnlockLevel ≤ 레벨` |
| 보유 스킬 목록 | 평타 + 현재 마스터리의 슬롯 4칸 |
| `LevelBonusOption` 총합 | 전 마스터리 Level × `LevelBonusPerLevel` |
| 대표 레벨 | 장착 무기의 마스터리 레벨 |

### 8.3 최종 스탯 계산 순서

```
[1] 기본값          CharacterStat.BaseValue (고정)  → StatDetail_*_Base
[2] 마스터리 보너스   전 마스터리 LevelBonusOption    → Option   ★ 무기 무관, 항상 적용
[3] 장비            EquipOption 기본 · 해금 옵션      → Option
[4] 펫              Pet 보유 효과                    → Option
[5] 버프            SkillEffect (StatChange)        → StatDetail
```

> **합성식과 클램프는 `기반테이블_설계.md` 8장이 소유한다.** 이 절은 [1]과 [2]가 무엇을 공급하는지만 서술한다.

정수 강화 트리가 들어오면 [2] 다음에 단계가 하나 추가된다 (11장).

**`MasteryAspect` 가 [2]와 슬롯 스킬 등록을 담당하며 source 태그는 `"Mastery"` 하나다.** 무기 교체 시 `RemoveAllFromSource("Mastery")` 로 통째로 걷어내고 다시 붙인다.

### 8.4 캐시 무효화

| 이벤트 | 스탯 캐시 | 스킬 리졸브 캐시 |
|---|---|---|
| 무기 교체 | ○ | ○ (슬롯·평타가 통째로 바뀐다) |
| 슬롯 변경 (현재 마스터리) | ○ (패시브 스킬이 바뀔 수 있다) | ○ |
| 마스터리 레벨업 | ○ | ✕ (`LevelBonusOption` 만 변함. 자동 장착이 일어나면 슬롯 변경으로 처리) |
| 장비 착용 / 해제 | ○ | ○ |
| **스탯 버프 부여 / 만료** | **○** | ✕ |
| 구조 변경 버프 (모디파이어 동반) | ○ | ○ |

> **스탯 버프는 반드시 스탯 캐시를 무효화한다**
>
> `StatChange` 효과는 모든 `StatDetail` 을 대상으로 할 수 있다. 스탯 캐시를 갱신하지 않으면 최대 체력·방어력·이동속도를 바꾸는 버프가 **아무 효과도 내지 않는다.**
>
> 스킬 문서 11.4의 시전 시점 스냅샷은 `Atk` / `CritRate` / `CritDamage` 만 담는다. 그것은 이미 발사된 투사체의 데미지가 흔들리지 않게 하는 장치이지 스탯 반영을 대체하지 않는다.

두 캐시를 분리해 두면 레벨업마다 리졸브를 다시 돌 필요가 없다.

## 10. 신규 무기 작성 가이드

### 10.1 작성 절차

```
STEP 1  WeaponType enum 끝에 항목 추가
STEP 2  Equipment 에 무기 아이템 행 추가 (Item 행과 세트) → 평타 / 애니메이터
STEP 3  WeaponMastery 행 추가         → RangeType / 레벨 보너스
STEP 4  평타 스킬 작성                 → SkillCategory = Normal
STEP 5  스킬 8개 작성 → MasterySkill 에 해금 레벨과 함께 등록
STEP 6  검증 (9장) + 실행 후 부팅 로그 확인
```

### 10.2 스킬 구성 기준

| 항목 | 기준 |
|---|---|
| 스킬 수 | 8개 |
| 해금 레벨 | 6.3절 기준 (첫 스킬 1레벨, 마지막 스킬 만렙) |
| 역할 분배 | 광역 · 단일 · 생존 · 폭주(쿨타임 궁극기) 등이 겹치지 않게. **모두가 반드시 끼는 스킬이 생기면 실제 선택지가 줄어든다** |
| 피해 옵션 | 마스터리 `RangeType` 과 맞는 것만 |

### 10.3 작성 후 체크리스트

```
□ WeaponType ↔ WeaponMastery 가 1:1인가
□ 무기 행의 NormalAttackSkill 이 있고 SkillCategory 가 Normal 인가
□ 무기 행의 AnimControllerName 이 실제 오버라이드 컨트롤러 이름인가
□ LevelBonusOption 이 OptionType = Stat 인가
□ MasterySkill 이 8행이고 스킬 중복이 없는가
□ UnlockLevel 이 1 ~ 만렙 안이고 1레벨 스킬이 있는가
□ 부팅 로그에 MasteryCatalog / OptionCatalog 경고가 없는가
```

### 10.4 자주 하는 실수

| 실수 | 증상 |
|---|---|
| `UnlockLevel` 을 만렙보다 크게 넣음 | 영영 해금되지 않는다 |
| 평타를 `MasterySkill` 에 넣음 | 평타가 슬롯을 차지한다 — 검증에서 오류 |
| `LevelBonusOption` 에 `Modifier` 지정 | 들고 있지도 않은 무기의 스킬이 변형 — 가드에 막혀 무시됨 |
| 경험치를 주는 새 경로에서 `Account.AddExp` 를 거치지 않음 | 마스터리 경험치가 누락된다 |

## 12. 제약 사항 및 미구현 항목

### 12.1 미구현 — 이 문서의 설계가 아직 반영되지 않은 부분

| 항목 | 현재 상태 |
|---|---|
| 스킬 8개 | `MasterySkill` 은 무기별 기존 스킬로 임시 배정했다 — 대검 4개(1·5·10·20), 태도·수리검·소총 2개씩(1·5). 무기당 8개 설계는 `마스터리 스킬 디자인.md` 7장 |
| 숙련도 화면 UI | 해금 목록·슬롯 4칸 UI 는 새로 구성한다. 스크립트에는 레벨·경험치·보너스 표시만 남아 있다. 조작 API 는 `MasteryBook.TrySetSlot` / `GetSlotBlock`, 목록은 `MasteryCatalog.GetSkills` |
| 레벨 보너스 수치 | `LevelBonusPerLevel` · `MasteryLevelBonus` 를 만렙 100 기준으로 재조정해야 한다 |
| `CharacterStat.BaseValue` | 아이템 중심 성장 기준으로 재조정해야 한다 |
| 경험치 곡선 | `MasteryLevelExp` 는 기존 300레벨 곡선의 앞 100행이다 — 100레벨 도달 시간 기준으로 다시 짠다 |

### 12.2 기타 미구현

| 항목 | 내용 |
|---|---|
| 정수 강화 트리 | 별도 설계 대기 |
| 추가 무기 | 4종 외 계획 없음 |
| `Dev_SkillIDs` | 개발용 임시 컬럼. 정식 전환 시 제거 대상 |

### 12.3 데이터 작성 시 주의

1. `WeaponType` enum에 항목을 **중간 삽입하면 기존 장비 데이터가 어긋난다.** 신규 항목은 끝에 추가한다.
2. 캐릭터 기본 스탯은 `BaseValue` 그대로다. 레벨 성장이 없다.
3. `MasteryLevelExp` 는 전 마스터리 공용이다. 무기별로 나누지 않는다.
4. `MasterySkill` 에 평타를 넣지 않는다. 평타는 무기 행이 갖는다.
5. `UnlockLevel` 은 만렙 이하여야 한다. 만렙을 확장할 때 새 스킬의 해금 레벨도 새 구간에 둔다.
6. 방어 상수 K가 쓰는 레벨은 **전투에 낀 몬스터의 레벨**이다.
7. 경험치를 주는 새 경로는 반드시 `Account.AddExp` 를 쓴다.
8. 비율(Ratio/Amp) 옵션은 `Atk`·`MaxHp`·`HpRegen`·`Def`·`LifeOnHit` **5개 스탯에만** 붙일 수 있다.
