# 펫 시스템 설계

> 2D 탑다운 방치형 핵앤슬래시 (Unity, 싱글플레이) — 펫 보유 / 장착 / 강화 / 승급
> 관련 문서: `아이템시스템_설계.md`, `기반테이블_설계.md`, `보상시스템_설계.md`, `상점시스템_설계.md`, `뒤끝서버시스템_설계.md`
> **이 문서는 현재 구현 상태를 기술한다.** 컬럼·행 수는 실제 테이블 기준, 동작 서술은 `Contents/Pet/`·`GamePlay/Unit/Pet/` 와 클라·서버 공용 규칙 `Core/Network/Shared/Pet/` 구현 기준이다.

### 1.2 핵심 규칙

> **옵션은 보유 효과이고, 장착은 모델뿐이다.**

| | 보유 | 장착 |
|---|---|---|
| 효과 | **가진 펫 전부의 옵션이 스탯에 합산된다** | 모델이 히어로를 따라다니며 드랍을 주워 준다 |
| 개수 | 종류당 1마리 (중복 보유 없음) | 동시에 1마리 |
| 담당 | `PetAspect` | `PetSpawner` |

- **펫은 개별 인스턴스가 없다.** 같은 펫을 두 마리 가질 수 없으므로 UID 를 채번하지 않고 테이블 ID 를 키로 쓴다. 상태는 **강화 레벨과 등급 둘**이면 전부 표현된다.
- **드랍을 줍는 능력은 전 펫 공용이다.** 어떤 펫을 장착하든 같다. 펫마다 다른 것은 보유 효과와 외형이다.
- **펫 ID = 아이템 ID 다.** 펫은 수집품 아이템(`MainCategory = Collection`, `SubCategory = Pet`)으로 지급되고, 지급 단계에서 인벤토리 대신 "보유"로 전환된다 (`보상시스템_설계.md` 3.2).

## 2. `Pet` — 펫 정의 (9컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | **`Item.ID` 와 동일** (`1 04 02 NNNNN`) |
| `Name` | `!string` | 표시명 |
| `Model` | `!string` | 따라다니는 모델 프리팹 주소 |
| `Image` | `!string` | 목록·카드 이미지 |
| `Grade` | `!ItemGradeType` | **최초 등급.** 이후 승급으로만 오른다 |
| `Opt_ID` | `!Option` | 보유 효과. **`Stat` 타입만 허용** |
| `Opt_Val` | `!float` | **1레벨 기준값** |
| `Opt_Step` | `!float` | 강화 레벨당 증가량 |
| `EquipText` | `!string` | 장착 효과 설명 문구 |

```
보유 효과 수치 = Opt_Val + Opt_Step × (Level - 1)
```

**1레벨 기준이다.** 캐릭터 스탯·스킬 트리 노드와 같은 규칙이고 장비(`Val`, 0레벨 기준)와는 반대다.

> **`Opt_ID` 는 `Stat` 타입만 쓴다.** 스킬 부여나 스킬 변형은 펫의 설계에 없다 — `PetAspect` 가 다른 타입을 무시한다.

**현재 6종** — 전부 `Normal` 등급으로 시작한다.

| ID | 이름 | 보유 효과 | 1레벨 | 레벨당 |
|---|---|---|---|---|
| `1040200001` | 고양이1 | `OPT_ATK_ADD` | 10 | +0.1 |
| `1040200002` | 고양이2 | `OPT_MAX_HP_ADD` | 50 | +0.1 |
| `1040200003` | 고양이3 | `OPT_DEF_ADD` | 10 | +0.05 |
| `1040200004` | 고양이4 | `OPT_ATK_SPEED_ADD` | 0.1 | +0.0001 |
| `1040200005` | 고양이5 | `OPT_MOVE_SPEED_ADD` | 0.1 | +0.0001 |
| `1040200006` | 고양이6 | `OPT_DAMAGE_BONUS_ADD` | 0.01 | +0.0025 |

## 3. 강화

### 3.1 `PetEnhance` (6컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 일련번호 |
| `Grade` | `!ItemGradeType` | 이 등급이 허용하는 최대 레벨의 기준 |
| `MaxLevel` | `!int` | 등급별 최대 레벨이자 **비용 구간의 끝** |
| `CostCurrencyID` | `!Currency` | 재화 |
| `CostCurrencyValue` | `!int` | 구간 시작 비용 |
| `CostCurrencyMult` | `!float` | 구간 안에서 레벨당 증가 배율 |

| Grade | MaxLevel | 구간 | 시작 비용 | 배율 |
|---|---|---|---|---|
| Normal | 20 | 1 ~ 20 | Gold 100 | 0.1 |
| Magic | 40 | 21 ~ 40 | Gold 5,000 | 0.08 |
| Rare | 60 | 41 ~ 60 | Gold 20,000 | 0.06 |
| Epic | 80 | 61 ~ 80 | Gold 80,000 | 0.05 |
| Legendary | 100 | 81 ~ 100 | Gold 300,000 | 0.04 |

### 3.2 이 테이블은 두 방향으로 쓰인다

| 목적 | 조회 키 |
|---|---|
| 레벨 상한 | **현재 등급** → 그 등급 행의 `MaxLevel` |
| 비용 | **현재 레벨** → `MaxLevel` 을 누적 구간표로 읽어 속한 구간 |

```
step = 현재 레벨 - (직전 구간의 MaxLevel) - 1
비용 = round( CostCurrencyValue × (1 + CostCurrencyMult × step) )
```

> **비용 구간은 등급이 아니라 현재 레벨이 정한다.** 등급을 올려도 레벨이 낮으면 싼 구간을 그대로 쓴다. 구간이 바뀌는 순간 증가분이 0으로 돌아가고 새 구간의 시작 비용이 가격을 정한다.
>
> 반올림은 `Math.Round`(은행원 반올림)다 — 클라와 서버 값이 같아야 한다.

**계산 예시** — 5레벨 → 6레벨 (Normal 구간)

```
step = 5 - 0 - 1 = 4
비용 = round(100 × (1 + 0.1 × 4)) = 140 Gold
```

### 3.3 판정과 실행

막힌 이유는 `PetEnhanceBlock` 으로 돌려준다. **버튼 잠금도 실행도 `PetBook.GetEnhanceBlock` 하나만 본다.**

| `PetEnhanceBlock` | 의미 |
|---|---|
| `NotOwned` | 미보유 |
| `MaxLevel` | 현재 등급의 최대 레벨 — 승급해야 더 올라간다 |
| `NoTable` | 이 레벨 구간의 `PetEnhance` 행이 없다 (데이터 오류) |
| `NotEnough` | 재화 부족 |

**강화는 묶음으로 보낸다.** 누를 때마다 클라가 먼저 적용하고(레벨 +1, 비용 차감), 마지막 입력 후 0.5초 동안 입력이 없으면 모은 횟수를 서버(`PetEnhance`)로 한 번에 보낸다. 서버 결과가 기대와 다르면 서버 상태로 맞추고 미리 뺀 재화를 돌려준다. 장비 강화와 같은 구조다 (`아이템시스템_설계.md` 6.1).

## 4. 승급

### 4.1 `PetPromotion` (5컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 일련번호 |
| `FromGrade` / `ToGrade` | `!ItemGradeType` | 승급 전/후 |
| `CostCurrencyID` / `CostCurrencyValue` | `!Currency` / `!int` | 비용 |

**현재 4행** — Normal→Magic 100 / Magic→Rare 200 / Rare→Epic 300 / Epic→Legendary 600 (전부 `Ruby`). `Legendary` 에서 출발하는 행이 없으므로 **펫의 최고 등급은 `Legendary`** 다.

### 4.2 규칙

- **레벨 조건이 없다.** 재화만 있으면 승급할 수 있다. 장비와 다르다(장비는 현재 등급의 레벨 상한까지 올려야 한다) — `PetPromotion` 테이블에 없는 규칙을 코드가 만들지 않는다.
- 승급하면 등급만 오르고 레벨은 유지된다. 레벨 상한이 다음 등급의 `MaxLevel` 로 확장된다.
- **비용은 전 펫 공용이다.** 펫마다 따로 두지 않고 등급 단위로 갖는다.

| `PetPromoteBlock` | 의미 |
|---|---|
| `NotOwned` | 미보유 |
| `MaxGrade` | 더 올라갈 등급이 없다 |
| `NoTable` | 승급 행이 없다 |
| `NotEnough` | 재화 부족 |

**승급은 한 번씩 서버에 요청한다** (`PetPromote`). 성공 응답의 차감량을 빼고 펫을 서버 최종 상태로 덮는다 (`PetBook.ApplyGrowthResponse`).

## 5. 보유 효과 — 스탯 반영

`PetAspect`(`IHeroAspect`, source = `"Pet"`)가 **보유한 펫 전부**를 순회하며 `Opt_ID` 를 `StatContainer.AddModifier` 로 붙인다.

- 장착 여부와 무관하다. 펫을 많이 모을수록 스탯이 오른다.
- 보유·레벨·등급이 바뀌면 `PetBook` 이 활성 히어로의 `"Pet"` 출처만 걷어내고 다시 붙인다.
- 최종 스탯 합성 순서에서의 위치는 `기반테이블_설계.md` 8장 [2].
- 서버 전투력 계산(`BattlePowerRules`)도 같은 식으로 펫 옵션을 넣는다 (`전투력시스템_설계.md`).

## 6. 장착 — 자석 펫

### 6.1 모델 수명 (`PetSpawner`)

장착한 펫의 모델을 히어로 옆에 세우고 치운다.

> **Aspect 가 아니라 별도 클래스인 이유** — Aspect 는 무상태여야 하는데 여기는 Addressable 핸들과 인스턴스를 들고 있어야 한다. 게다가 스탯 재적용은 Remove → Apply 를 연달아 부르므로, Aspect 에 넣으면 강화 한 번에 펫이 사라졌다 다시 로드되며 깜빡인다. **스탯 재적용과 모델 수명을 분리한다.**

- 장착이 바뀌었거나 히어로가 새로 만들어졌을 때 `Refresh` 를 부른다.
- **씬 전환은 생존이 아니라 재생성으로 푼다.** 인스턴스에 부모를 두지 않아 활성 씬에 속하므로 씬이 바뀌면 히어로와 함께 사라지고, 새 히어로가 만들어질 때 다시 만든다.
- 같은 펫을 그대로 쓰는데 인스턴스가 살아 있으면 주인만 새로 맞춘다.

### 6.2 동작 (`Pet`)

**`UnitBase` 가 아니다.** `UnitManager` 에 등록되지 않고 콜라이더도 없어 타겟팅·피격·유닛 충돌에서 자연히 빠진다(무적). 벽·유닛을 전부 통과한다.

| 상황 | 동작 |
|---|---|
| 평상시 | 히어로를 느슨하게 뒤따른다. 충분히 벌어져야 출발하고 주변까지 좁히면 선다(히스테리시스) |
| 멀어짐 | 거리에 따라 1배 ~ 2배속으로 따라붙는다 |
| 너무 멀어짐 | 따라잡기를 포기하고 히어로 옆으로 순간이동한다 |
| 주변에 드랍 있음 | 그쪽으로 빠르게 가서 물고, 자기 쪽으로 끌어당겨 회수한다 |

- 탐지 반경은 **히어로 기준**, 획득 반경은 **펫 기준**이다. 둘 다 펫 프리팹의 고정값이며 캐릭터 스탯(`Stat_PickupRange`)과 무관하다.
- **보상 드랍만 줍는다.** 회복 오브·전투 룬은 대상이 아니다. 히어로 자석이 먼저 문 드랍도 건너뛴다.
- 한번 문 드랍은 히어로가 멀어져 탐지 원을 벗어나도 끝까지 끌어온다.
- **인벤토리가 가득 차 주울 수 없는 장비 드랍은 쫓지 않고** `InventoryFullEvent` 로 알리기만 한다.

### 6.3 장착 저장

장착 변경은 로컬에 먼저 반영하고 dirty 로 표시했다가, 화면을 닫을 때 외형 저장(`SaveAppearance` — 펫 장착 + 코스튬 착용)으로 한 번에 보낸다.

## 8. 저장 데이터

```
pets            List<{ petId, level, grade }>     ← 보유한 펫만. 보유 = 최소 1레벨
equippedPetId   int                               ← 0 = 미장착
```

서버(`USER_PET`)가 보관한다 (`PetDto`).

- **미보유 펫은 항목 자체가 없다.**
- 최대 레벨·옵션 수치·비용은 저장하지 않고 전부 테이블에서 계산한다.
- 로드할 때 테이블에 없는 펫은 버리고, 보유하지 않은 펫이 장착으로 남아 있으면 해제한다(데이터 불일치 방어).

## 9. 참조 관계

```
Item.ID ──(동일 ID)──→ Pet.ID          ★ MainCategory=Collection, SubCategory=Pet

Pet.Opt_ID                  →  Option.ID   (Stat 타입)
Pet.Grade                   →  ItemGradeType
PetEnhance.CostCurrencyID   →  Currency.ID
PetPromotion.CostCurrencyID →  Currency.ID

Pet.ID   ←  Reward.TargetID (RewardType=Item)   ←  ShopGoods / Monster.RewardGroupID
```

## 10. 검증 규칙

| # | 항목 | 분류 |
|---|---|---|
| 1 | `Pet.ID` 가 `Item` 에 존재하고 `SubCategory = Pet` 인가 | 오류 |
| 2 | `SubCategory = Pet` 인 `Item` 에 `Pet` 행이 있는가 | 오류 |
| 3 | `Opt_ID` 가 `OptionType = Stat` 인가 | 오류 (다른 타입은 조용히 무시된다) |
| 4 | `Pet.Grade` 에 해당하는 `PetEnhance` 행이 있는가 | 오류 (최대 레벨 0 — 강화 불가) |
| 5 | `PetEnhance.MaxLevel` 이 등급 순으로 증가하는가 | 오류 (비용 구간이 뒤집힌다) |
| 6 | `PetPromotion` 의 `FromGrade` 가 중복되는가 | 오류 |
| 7 | `Pet.Model` 주소가 어드레서블에 등록돼 있는가 | 런타임 로드 실패로 드러남 |
| 8 | 구간 경계에서 비용이 역전되는가 (이전 구간 최대 > 다음 구간 시작) | 경고 |

## 11. 미결 / 다음 작업

- **펫 데이터가 임시다** — 이름이 `고양이1` ~ `고양이6` 이고 `EquipText` 가 전부 같은 문구다. 등급도 전부 `Normal` 로 시작한다.
- **`Mythic` 등급이 없다** — `PetEnhance` / `PetPromotion` 이 `Legendary` 에서 끝난다.
- **자석 능력에 차이가 없다** — 탐지·획득 반경이 프리팹 고정값이라 펫마다, 레벨마다 달라지지 않는다. 차등을 두려면 `Pet` 에 컬럼이 필요하다.
- **획득 경로가 둘뿐이다** — 상점과 필드보스 1종.
