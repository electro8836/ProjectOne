# 퀘스트 시스템 설계

> 2D 탑다운 방치형 핵앤슬래시 (Unity, 싱글플레이) — 퀘스트 및 NPC 시스템
> 관련 문서: `맵시스템_설계.md`, `몬스터시스템_설계.md`, `보상시스템_설계.md`, `뒤끝서버시스템_설계.md`
> **이 문서는 현재 구현 상태를 기술한다.** 컬럼·행 수는 실제 테이블 기준, 동작 서술은 `Contents/Quest/`·`GamePlay/Npc/` 와 클라·서버 공용 규칙 `Core/Network/Shared/Quest/QuestRules.cs` 구현 기준이다.

---

## 1. 개요

### 1.1 구성 요소

| 대상 | 파일 | 시트 | 현재 행 수 |
|---|---|---|---|
| 퀘스트 | `Quest.xlsx` | `Quest` | 20 |
| NPC | `Npc.xlsx` | `Npc` | 4 |
| | | `NpcSpawn` | 4 |
| | | `NpcDialog` | 4 |

| 런타임 | 파일 |
|---|---|
| 퀘스트 도메인 모델 | `Contents/Quest/QuestBook.cs` |
| 파라미터 굽기 · 체인 · 정합성 검증 | `Contents/Quest/QuestCatalog.cs` |
| 파라미터 해석 · 체인 규칙 (클라·서버 공용) | `Core/Network/Shared/Quest/QuestRules.cs` |
| 진행도 1건 | `Contents/Quest/QuestProgress.cs` |
| 이벤트 → 진행도 반영 · 자동 완료 | `Contents/Quest/QuestTracker.cs` |
| 저장 DTO | `Core/Network/Shared/Dto/QuestDto.cs` |
| HUD 퀘스트 패널 / 목록 팝업 | `UI/HUD/QuestInfo.cs`, `UI/Popup/QuestListPopupPresenter.cs` |
| NPC 배치 · 상호작용 | `GamePlay/Npc/NpcSpawner.cs`, `NpcUnit.cs`, `NpcProximityTrigger.cs` |

### 1.2 핵심 규칙

- **진행 중 퀘스트는 항상 1개다.** 메인·서브 구분이 없고, 수락 절차도 없다 — 앞 퀘스트를 완료하면 다음 퀘스트가 자동으로 열린다.
- **ID 오름차순이 곧 진행 순서다.** 선행 퀘스트 컬럼을 두지 않는다.
- **포기할 수 없고 반복도 없다.** 한 줄 체인을 끝까지 따라간다.
- 마지막 퀘스트까지 다 깨면 진행 중 퀘스트가 없는 상태로 남고, HUD 패널을 숨긴다.
- 일일/주간 반복 콘텐츠는 퀘스트가 아니라 별도 시스템(출석·히어로패스)이 맡는다. (본 문서 범위 밖)

> **퀘스트는 필드 진행의 관문이다.** `Field.ReqQuestID` 가 "이 퀘스트를 깨야 이 필드가 열린다"를 정한다. 현재 퀘스트 20개가 액트 1·2의 필드 20개에 하나씩 대응한다 (`맵시스템_설계.md` 6.1).

### 1.3 목표 하나 원칙

퀘스트 하나는 **목표를 하나만** 갖는다. 조건 2개 이상이 필요해지는 시점에 슬롯을 확장한다.

## 2. Enum

```
!Enum   QuestCompleteType
        Auto            자동으로 완료
        UI              UI에서 완료 (플레이어가 수령 버튼을 누른다)

!Enum   QuestTargetType
        MonsterKill     일반 몬스터 처치 (그 맵에서 어떤 몬스터든)
        BossKill        보스 몬스터 처치
        DungeonClear    던전 클리어
        ReachLevel      레벨 달성
        EliteKill       엘리트 몬스터 처치
```

> **enum 값 규칙**: 컨버터가 코드 생성 시 `None = 0`을 자동으로 붙인다. 실제 값은 **1부터** 시작하고, 테이블의 빈칸은 `None`으로 해석된다.

## 3. Quest 테이블 (8컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| ID | !int | **진행 순서 그 자체다** (3.1) |
| Name | !string | |
| Desc | !string | 설명. HUD 는 이 뒤에 진행도 `(12/50)` 를 붙여 보여준다 |
| CompleteType | !QuestCompleteType | 비어 있으면 영원히 완료되지 않는다 |
| QuestTargetType | !QuestTargetType | 판별 컬럼 |
| QuestParam_1 | !string | 목표 타입별 파라미터. **3.2 참조** |
| QuestParam_2 | !string | |
| RewardGroupID | !int | → `Reward.GroupID` |

**경험치 보상 컬럼이 없다.** 퀘스트 보상은 보상 그룹이 전부이며 고정값이다.

### 3.1 ID 규칙

- **1부터 연속으로 부여한다.** 다음 퀘스트는 "클리어한 마지막 ID 보다 큰 것 중 가장 작은 ID"다 (`QuestRules.GetNextQuestId`).
- 저장하는 것이 `ClearedQuestId` 하나뿐이므로 **이미 지나간 ID 보다 작은 번호를 나중에 추가하면 영영 스킵된다.** 출시 후 퀘스트는 뒤에만 덧붙인다 (`테이블규약_설계.md` 6.3).

### 3.2 QuestParam — 목표 파라미터

목표 타입마다 필요한 값의 개수와 종류가 다르므로, **타입별 전용 컬럼을 두지 않고 자유 파라미터 슬롯 2개**를 쓴다. `SkillEffect.EffectParam_1~5` 와 같은 방식이다.

전부 `!string` 이며, 공유 규칙 `QuestRules.TryParseTarget` 이 `QuestTargetType` 에 따라 해석한다. **서버도 같은 코드로 해석한다.** 클라는 판정 때마다 문자열을 파싱하지 않도록 `QuestCatalog.Build()` 시점에 강타입으로 굽는다 (`BakedQuest`).

> **파라미터 순서 규칙 — 필수는 앞, 선택은 뒤**
>
> 중간에 빈칸이 생기지 않게 배치한다.

| QuestTargetType | QuestParam_1 (필수) | QuestParam_2 | 판정 |
|---|---|---|---|
| `MonsterKill` | `Map.ID` | 처치 수량 | 그 맵에서 잡은 수 누적 (등급 무관) |
| `EliteKill` | `Map.ID` | 처치 수량 | 그 맵에서 잡은 **엘리트** 수 누적 |
| `BossKill` | `Map.ID` | — | 그 맵에서 **보스** 1마리 처치 |
| `DungeonClear` | `Dungeon` | Stage (비면 1) | 최고 클리어 단계 **이상** |
| `ReachLevel` | 히어로 레벨 | — | **이상** |

**타입 간 공통 의미를 부여하지 않는다.** 슬롯의 뜻은 위 표가 전부이며, 이 표를 벗어난 해석은 없다.

**`QuestParamDef` 시트는 만들지 않는다.** `SkillParamDef` 가 존재하는 이유는 `SkillModifier` 가 `ParamKey` 를 문자열로 지목해 런타임에 값을 바꾸기 때문이다. 퀘스트에는 모디파이어가 없고 타입도 5개뿐이라, 해석 코드에 케이스를 두고 위 표를 문서로 고정하는 편이 관리 대상이 적다.

### 3.3 파라미터별 세부 규칙

**처치 목표는 몬스터가 아니라 "어디서 잡았는가"를 본다.**

몬스터는 지역별로 ID를 복제하지 않는다. 고블린 전사는 1종이고 레벨만 스폰이 결정한다. 그래서 처치 목표는 몬스터 ID 가 아니라 **맵**을 지목하고, 등급은 목표 타입(`MonsterKill` / `EliteKill` / `BossKill`)이 가른다.

- 처치 위치는 **사망 좌표로 역산**한다. 필드 맵이 10000 간격 격자로 배치되므로 좌표만으로 맵이 확정된다 (`맵시스템_설계.md` 7.2).
- 몬스터 등급은 이벤트에 실리지 않아 `Monster.MonsterType` 을 테이블로 역조회한다.
- `MapType` 은 제한하지 않는다. 던전 맵을 지정하면 던전 한정 처치 퀘스트가 된다.

**기타**

- `DungeonClear` 의 판정 근거는 서버가 소유하는 **던전별 최고 클리어 단계**다 (`맵시스템_설계.md` 8.2절).
- 진행도 분모는 `MonsterKill` / `EliteKill` 이 처치 수량, `ReachLevel` 이 목표 레벨이고, `BossKill` / `DungeonClear` 는 1이다 (`QuestRules.GetRequiredCount`).

## 4. 진행 판정

### 4.1 체인

```
다음 퀘스트 = ID > ClearedQuestId 인 것 중 가장 작은 ID
```

- 진행 중 퀘스트가 없으면 `QuestBook.RefreshCurrent` 가 체인에서 다음 것을 연다. 로그인 직후와 완료 직후에 부른다.
- **체인은 완료 응답에서만 전진한다.** NPC 등장 조건과 필드 해금도 이 값(`ClearedQuestId`)을 본다.
- 목표 파라미터 해석에 실패한 퀘스트는 진행 대상에서 빠진다. 부팅 로그에 경고가 남는다.

### 4.2 진행도 갱신

`QuestTracker`(영속 `MonoSingleton`)가 게임 이벤트를 진행도로 옮긴다.

| 이벤트 | 반영 |
|---|---|
| `MonsterKillEvent` | 처치 카운터 +1 (맵·등급이 목표와 맞을 때) |
| `CharacterChangeEvent` | `ReachLevel` 재평가 (레벨업 전용 이벤트가 없다) |
| `DungeonStageClearedEvent` | `DungeonClear` 재평가 |

진행도가 바뀌면 `QuestChangeEvent` 를 발행한다. **HUD 와 목록 팝업은 이 이벤트로만 갱신한다** — 폴링하지 않는다.

### 4.3 완료

| CompleteType | 완료 시점 |
|---|---|
| `Auto` | 목표를 달성하는 즉시 `QuestTracker` 가 완료를 요청한다 |
| `UI` | 플레이어가 HUD 패널(`QuestInfo`)이나 목록 팝업의 보상 칸을 눌러 수령한다 |

**완료는 서버 권위다.** `QuestBook.TryComplete` 는 목표를 달성했으면 요청(`QuestComplete`)만 보내고, 보상 지급과 체인 전진은 응답에서 한다. 서버가 같은 `QuestRules` 로 목표를 다시 확인하고 보상을 굴려 지급한다 — 퀘스트 보상은 고정값이라 결과를 그대로 반영한다.

- 응답 전 재요청(자동 완료 재판정·연타)은 요청 중 표시로 막는다.
- 실패하면 그대로 둔다. 다음 판정(처치·레벨업·던전 클리어·수령 버튼)에서 다시 요청한다.

### 4.4 저장 데이터

```
ClearedQuestId   (int)   — 클리어한 마지막 퀘스트 ID. 다음 퀘스트 해금·필드 해금·NPC 등장 조건의 유일한 근거
Current          (QuestProgress: questId + counter)   — 진행 중 1개. questId 가 0이면 진행 중이 아니다
```

진행 중 퀘스트가 항상 1개이고 ID 오름차순이 곧 체인이라, **이 둘만 있으면 상태가 전부 복원된다.** 서버가 보관한다 (`QuestDto`).

> **진행 상태를 저장하는 목표는 처치 3종뿐이다**
>
> `QuestProgress.counter` 를 쓰는 것은 `MonsterKill` / `EliteKill` / `BossKill` 이고, `DungeonClear` / `ReachLevel` 은 **판정할 때마다 현재 상태를 재평가**한다.
>
> 부수 효과가 있다. **조건을 이미 충족한 상태로 퀘스트가 열리면 즉시 달성된다.** 이미 30레벨이면 "20레벨 달성" 퀘스트는 열리는 순간 완료 가능 상태가 된다. 이것은 의도된 동작이다.

**처치 카운터는 매번 서버에 보내지 않는다.** 로컬에서 세고 dirty 로 표시했다가 앱 일시정지·종료 때 `SaveQuestProgress` 로 보낸다. 서버는 이 카운터를 클라 값으로 받는다.

### 4.5 표시

- **HUD 패널(`QuestInfo`)** — 진행 중 퀘스트 1개를 `설명 (분자/분모)` 로 보여준다. 목표를 달성하면 강조색으로 바뀌고, `UI` 완료형이면 누르면 수령한다.
- **목록 팝업(`QuestListPopup`)** — 체인 전체를 깔고 각 칸의 상태를 정한다. "깼는가"는 `ClearedQuestId` 와의 대소 비교 하나로 끝난다 — 수령 플래그가 따로 없다. "수령 대기"는 진행 중 퀘스트가 `UI` 완료형이고 목표를 달성했을 때뿐이다.
- 잠긴 필드 포털에 다가가면 해금 조건인 퀘스트 이름을 안내한다 (`맵시스템_설계.md` 6.1).

### 5.2 Npc — 마스터 데이터

| 컬럼 | 타입 | 설명 |
|---|---|---|
| ID | !int | 단순 순번 (맵 정보를 섞지 않는다) |
| Name | !string | |
| Title | !string | 직함. 이름 위 표시용, 빈값 허용 |
| NpcType | !NpcType | 상호작용 시 열리는 기능 |
| FunctionID | !int | 타입별 참조 (ShopID 등). **현재 미사용** |
| PrefabName | !string | 배치 프리팹 주소. 비어 있으면 그 NPC 는 뜨지 않는다 |
| Portrait | !string | 대화창 초상화. **현재 미사용** |

**NPC 는 `UnitBase` 파생이 아니다** (`NpcUnit`). 스탯도 전투도 AI 도 없으므로 유닛 시뮬레이션 루프에 싣지 않는다.

| NpcType | 상호작용 |
|---|---|
| `Shop` / `Blacksmith` | 클릭하면 대응 기능 화면(상점 · 제작)을 연다 (`UIScreenCatalog`) |
| `Portal` | **가까이 가기만 하면** 액트·필드 목록을 연다 (`NpcProximityTrigger`). 클릭을 타지 않는다 |
| `Storage` | 대응 화면이 연결되어 있지 않다 |

**퀘스트는 NPC 를 거치지 않는다.** 수락·완료 담당 NPC 개념이 없다 (1.2).

### 5.3 NpcSpawn — 배치

| 컬럼 | 타입 | 설명 |
|---|---|---|
| ID | !int | |
| NpcID | !int | → `Npc.ID` |
| MapID | !int | → `Map.ID` |
| SpawnPointID | !int | 씬 마커 ID. **맵 내에서만 유니크** |
| SpawnStartQuestID | !int | 이 퀘스트 클리어 후 등장. None이면 항상 |
| UseSpawnEnd | !bool | TRUE일 때만 `SpawnEndQuestID` 를 판정한다 |
| SpawnEndQuestID | !int | 이 퀘스트 클리어 후 소멸 |

> **`UseSpawnEnd` 가 필요한 이유**
>
> 판정식이 `ClearedQuestId >= SpawnEndQuestID` 인데 빈칸은 `None`(0)이므로 이 식이 **항상 참**이 된다. 별도 플래그 없이 "빈칸이면 계속 등장"을 표현하면 코드에서 0을 특수 분기해야 하고, 그 한 줄을 빠뜨리면 **모든 NPC가 에러 없이 사라진다.**
>
> `SpawnStartQuestID` 는 반대로 `ClearedQuestId >= 0` 이 항상 참이라 "빈칸이면 항상 등장"이 자연스럽게 성립한다. 대칭은 깨지지만 컬럼을 하나 아끼는 쪽을 택했다.

**배치 방식 — 하이브리드**

씬에는 `SpawnPoint` 마커만 배치하고 `SpawnPointID`를 부여한다. 테이블은 `MapID + SpawnPointID + NpcID + 등장 조건`만 관리한다.

- 좌표는 씬 에디터에서 눈으로, 등장 조건은 테이블에서 관리한다.
- 실질 키는 `(MapID, SpawnPointID)` 복합키다.
- 마커는 위치만 담당한다. 여러 NPC가 조건부로 같은 자리를 나눠 쓸 수 있다.
- **위험**: 씬에서 마커를 지우면 테이블은 멀쩡한데 NPC만 조용히 안 나온다. `NpcSpawner` 가 마커를 못 찾으면 경고 로그를 남긴다.
- 등장 조건은 **퀘스트 진행도**(`QuestCatalog.IsSpawnActive`)로 판정하며, 퀘스트 상태가 바뀔 때 `NpcSpawner` 가 전 NPC를 재평가한다. 매 프레임 순회하지 않는다.

**방향(FlipX)은 테이블에 두지 않는다.** 모든 NPC가 동일하게 처리되므로 코드에서 좌우만 전환한다.

### 5.4 NpcDialog — 대사

> **대사 시스템은 아직 구현되지 않았다.** `NpcDialog` 테이블과 `DialogTriggerType` enum 은 있으나 읽는 코드가 없다. 아래는 테이블 구조와, 구현할 때 따를 규칙이다. 퀘스트가 NPC 를 거치지 않게 되면서 `QuestAccept` / `QuestProgress` / `QuestComplete` 트리거는 쓸 곳이 없어졌다 — 대사를 붙일 때 다시 정한다.

| 컬럼 | 타입 | 설명 |
|---|---|---|
| ID | !int | |
| NpcID | !int | |
| QuestID | !int | **0이면 퀘스트 무관 기본 대사** |
| TriggerType | !DialogTriggerType | |
| Text | !string | 대사 전문 |

**참조 컬럼을 두지 않는 구조**

`Npc`나 `Quest`에 `DialogID`를 두지 않고, `NpcDialog`가 `NpcID + QuestID + TriggerType`을 직접 갖는다. 로딩 시 `Dictionary<(NpcID, QuestID, Trigger), string>`을 만들면 조회는 O(1)이고, 퀘스트 테이블에 대사용 컬럼이 늘어나지 않는다.

**대사 줄 나누기**

`LineIndex`를 두지 않고 **`Text` 한 셀에 전체 대사**를 넣는다. 코드에서 구분자로 Split해 페이지 단위로 넘긴다.

- 구분자는 `|` 같은 **명시적 문자**를 쓴다. 셀 내 줄바꿈(Alt+Enter)은 컨버터에서 행이 깨질 위험이 있어 피한다.
- 자동 줄바꿈에만 맡기면 페이지 나누는 지점을 기획에서 제어할 수 없다.
- 줄 단위 부가 정보(화자 교체, 표정, 연출)나 대사 선택지는 지원하지 않는다.

### 5.5 상호작용 우선순위

현재 NPC 상호작용은 **`NpcType` 기능 화면을 여는 것 하나**다 (5.2). 퀘스트 대사·퀘스트 마커(느낌표/물음표)는 없다.

대사 시스템을 붙이면 `Default` 대사와 기능 화면의 순서를 여기에 정한다.

## 6. 검증 규칙

### Quest

`QuestCatalog.Build()` 가 부팅 시 검사하고 경고 로그를 남긴다.

- `CompleteType` 이 비어 있음 (경고 — 수령 방식이 없어 영원히 완료되지 않는다)
- 목표 파라미터를 `QuestTargetType` 으로 해석하지 못함 (경고 — 진행 대상에서 빠진다)

| TargetType | 검증 |
|---|---|
| `MonsterKill` / `EliteKill` | P1이 `Map` 에 존재 / P2가 1 이상 정수 |
| `BossKill` | P1이 `Map` 에 존재 |
| `DungeonClear` | P1이 `Dungeon` 에 존재 / P2는 비었거나 1 이상 정수 |
| `ReachLevel` | P1이 1 이상 정수 |

- `RewardGroupID` 가 있는데 그 그룹에 `Reward` 행이 없음 (경고)
- **정의되지 않은 파라미터 슬롯에 값이 있으면 경고** — 자유 형식 컬럼에서 오타를 잡는 유일한 장치다. (현재 코드는 검사하지 않는다)
- 목표 맵에 그 등급의 몬스터가 스폰되지 않으면 완료 불가 퀘스트다 (현재 코드는 검사하지 않는다)

### Npc

- `NpcSpawn.NpcID` 가 `Npc` 에, `MapID` 가 `Map` 에 존재 (경고)
- `UseSpawnEnd=TRUE`인데 `SpawnEndQuestID`가 비면 경고 (즉시 사라진다) / `FALSE`인데 값이 있으면 경고 (무시된다)
- `NpcSpawn`의 `(MapID, SpawnPointID)` 마커 실존 여부는 엑셀 컨버터가 검증하지 못한다. `NpcSpawner` 가 마커를 못 찾으면 런타임 경고를 남긴다.
- `Npc.PrefabName` 이 비면 그 배치를 건너뛰고 경고를 남긴다.

## 7. 참조 관계

```
Quest.QuestParam_1~2   (전부 !string, 타입별 파싱 — QuestRules)
  ├ MonsterKill / EliteKill → P1 Map.ID / P2 수량
  ├ BossKill                → P1 Map.ID
  ├ DungeonClear            → P1 Dungeon / P2 Stage
  └ ReachLevel              → P1 레벨
Quest.RewardGroupID       → Reward.GroupID

Quest.ID                  ←  Field.ReqQuestID            (필드 해금)
                          ←  NpcSpawn.SpawnStartQuestID / SpawnEndQuestID

NpcSpawn.NpcID            → Npc.ID
NpcSpawn.MapID            → Map.ID
NpcDialog.NpcID           → Npc.ID
NpcDialog.QuestID         → Quest.ID (0 = 없음)
```

## 8. 미결 / 다음 작업

### 8.1 데이터가 규칙과 어긋나 있다 — 수정 필요

**`NpcSpawn` 에 즉시 소멸 조합이 있다.** ID 2(대장장이)가 `UseSpawnEnd = TRUE` 인데 `SpawnEndQuestID = 0` 이다. 판정식이 `ClearedQuestId >= 0` 이라 항상 참이 되어 등장 조건을 통과하지 못한다. 6장 검증 규칙이 경고로 잡는 사례가 실제로 데이터에 들어가 있다.

**`NpcDialog` 가 존재하지 않는 퀘스트를 가리킨다.** 3행이 `QuestID = 2000010` 을 지정하는데 퀘스트 ID 는 `1` ~ `20` 뿐이다. 구 스키마의 잔재이며, 대사 시스템이 미구현이라 동작에는 영향이 없다.

**`SpawnPointID` 가 대부분 0이다.** 포탈관리인(ID 4)만 `4` 를 갖고 상인·대장장이·창고지기는 0이다.

### 8.2 비어 있는 데이터

- **액트 3~5 퀘스트가 없다.** 퀘스트 20개가 액트 1·2 필드에만 대응한다.
- **퀘스트 구성이 한 가지 패턴이다.** 필드마다 "몬스터 50마리 → … → 엘리트 5마리 → 보스" 로 같고, 액트 2는 액트 1의 보상 그룹(`6001` ~ `6010`)을 그대로 다시 쓴다. `DungeonClear` / `ReachLevel` 목표는 데이터가 없다.
- **`Npc.PrefabName` 이 포탈관리인만 채워져 있다.** 상인·대장장이·창고지기는 배치되지 않는다.
- **`Npc.FunctionID` / `Portrait` 가 전부 비어 있다.**

### 8.3 그 외

- **대사 시스템 미구현** — `NpcDialog` 를 읽는 코드가 없다 (5.4).
- **창고 NPC 미연결** — `NpcType = Storage` 에 대응 화면이 없다. 보관함은 현재 장비 화면에서 연다.
- **로컬라이징** — `Name` / `Desc` / `Text` 를 직접 텍스트로 두었다. 다국어가 필요해지면 키 방식으로 전환한다.
