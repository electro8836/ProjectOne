# 퀘스트 시스템 설계

> 2D 탑다운 방치형 핵앤슬래시 (Unity, 싱글플레이) — 퀘스트 및 NPC 시스템
> 관련 문서: `맵시스템_설계.md`, `몬스터시스템_설계.md`, `보상시스템_설계.md`, `아이템시스템_설계.md`
> **이 문서는 현재 구현 상태를 기술한다.** 컬럼·행 수는 실제 테이블 기준, 동작 서술은 `Contents/Quest/`·`GamePlay/Npc/` 구현 기준이다.

## 1. 개요

### 1.1 구성 요소

|---|---|---|---|
| 퀘스트 | `Quest.xlsx` | `Quest` | 11 |
| NPC | `Npc.xlsx` | `Npc` | 4 |
| | | `NpcSpawn` | 4 |
| | | `NpcDialog` | 4 |

| 런타임 | 파일 |
|---|---|
| 퀘스트 도메인 모델 | `Contents/Quest/QuestBook.cs` |

| NPC 배치 | `GamePlay/Npc/NpcSpawner.cs` |

### 1.2 핵심 규칙

- **메인 퀘스트**는 항상 화면에 표시된다. 동시에 1개만 진행한다.
- **서브 퀘스트**는 없을 수도 있고, **최대 2개까지 동시 수주** 가능하다.
- 메인 퀘스트는 **선형 체인**이며 `ReqQuestID`로 연결된다.
- 메인 퀘스트는 **포기 불가**, 서브 퀘스트만 포기 가능하다.
- 서브 퀘스트는 **무한 반복** 가능하다. 반복 횟수 제한이나 초기화 주기는 없다.
- 일일/주간 반복 콘텐츠는 퀘스트가 아니라 **별도 '미션' 시스템**으로 처리한다. (본 문서 범위 밖)

### 1.3 목표 하나 원칙

퀘스트 하나는 **목표를 하나만** 갖는다. 조건 2개 이상이 필요해지는 시점에 슬롯을 확장한다.

## 2. Enum

```
!Enum   QuestCategory
        Main            메인 퀘스트
        Sub             서브 퀘스트

!Enum   QuestAcceptType
        Auto            자동으로 시작
        Npc             NPC 대화
        UI              UI에서 시작

!Enum   QuestCompleteType
        Auto            자동으로 완료
        Npc             NPC 대화
        UI              UI에서 완료

!Enum   QuestTargetType
        KillMonster     몬스터 처치
        EquipItemGrade  등급 아이템 장착
        EquipItemLevel  레벨 아이템 장착
        Talk            대화
        DungeonClear    던전 클리어
        ReachLevel      레벨 달성
```

> **enum 값 규칙**: 컨버터가 코드 생성 시 `None = 0`을 자동으로 붙인다. 실제 값은 **1부터** 시작하고, 테이블의 빈칸은 `None`으로 해석된다.

| ReqLevel | !int | 수락 요구 레벨 |

| QuestParam_1 | !string | 목표 타입별 파라미터. **3.2 참조** |
| QuestParam_2 | !string | |
| QuestParam_3 | !string | |
| RewardExp | !int | 경험치 보상 |
| RewardGroupID | !int | → `Reward.GroupID` |

### 3.1 ID 규칙

- **메인 퀘스트는 10 단위로 증가** (1000010, 1000020, 1000030…)
  ID가 곧 진행 순서 데이터이므로 중간 삽입 여유를 남긴다. 연속 부여 금지.
- 서브 퀘스트는 순서 개념이 없으므로 연속 부여 가능 (2000010, 2000020…)

### 3.2 QuestParam — 목표 파라미터

목표 타입마다 필요한 값의 개수와 종류가 다르므로, **타입별 전용 컬럼을 두지 않고 자유 파라미터 슬롯 3개**를 쓴다. `SkillEffect.EffectParam_1~5` 와 같은 방식이다.

전부 `!string` 이며, 컨버터가 `QuestTargetType` 에 따라 파싱·검증한다.

> **파라미터 순서 규칙 — 필수는 앞, 선택은 뒤**
>
> 중간에 빈칸이 생기지 않게 배치한다. 선택 항목을 앞에 두면 가장 흔한 목표 타입에서 첫 칸이 자주 비어 한 칸씩 밀려 적는 사고가 난다.

| QuestTargetType | QuestParam_1 (필수) | QuestParam_2 | QuestParam_3 | 판정 |
|---|---|---|---|---|
| `KillMonster` | `Monster.ID` | 처치 수량 | `Map.ID` — None이면 지역 무관 | 카운트 누적 |
| `EquipItemGrade` | `ItemGradeType` | `EquipSlotTypes` — None이면 전체 | — | **이상** |
| `EquipItemLevel` | 장비 레벨 | `EquipSlotTypes` — None이면 전체 | — | **이상** |
| `Talk` | `Npc.ID` | — | — | 대화 시 달성 |
| `DungeonClear` | `Dungeon` | Stage | — | **이상** |
| `ReachLevel` | 레벨 | — | — | **이상** |

**타입 간 공통 의미를 부여하지 않는다.** `SkillParamDef` 에서 `Damage` 의 1번 슬롯이 `Ratio` 이고 `Buff` 의 1번 슬롯이 `RefID` 인 것과 같다. 슬롯의 뜻은 위 표가 전부이며, 이 표를 벗어난 해석은 없다.

**`QuestParamDef` 시트는 만들지 않는다.** `SkillParamDef` 가 존재하는 이유는 `SkillModifier` 가 `ParamKey` 를 문자열로 지목해 런타임에 값을 바꾸기 때문이다. 퀘스트에는 모디파이어가 없고 타입도 6개뿐이라, 컨버터에 6개 케이스를 하드코딩하고 위 표를 문서로 고정하는 편이 관리 대상이 적다.

### 3.3 파라미터별 세부 규칙

**지역 한정 (`KillMonster` / `QuestParam_3`)**

몬스터는 지역별로 ID를 복제하지 않는다. 해골전사는 1종이고 레벨만 스폰이 결정한다. 따라서 `KillMonster` 목표에 지역 개념을 넣으려면 별도 파라미터가 필요하다.

| 값 | 판정 |
|---|---|
| None | **지역 무관.** 어디서 잡아도 카운트된다 |
| `Map.ID` | 해당 맵에서 처치한 것만 카운트 |

`QuestParam_3` 를 채웠으면 `Desc` 의 지역 안내와 실제 판정이 일치한다. 비운 채로 `Desc` 에만 지역명을 적으면 **표시와 판정이 어긋나므로** 둘 중 하나로 맞춘다.

`MapType` 은 제한하지 않는다. 던전 씬을 지정하면 던전 한정 킬 퀘스트가 된다.

**슬롯 한정 (`EquipItemGrade` / `EquipItemLevel` / `QuestParam_2`)**

| 값 | 판정 |
|---|---|
| None | **슬롯 무관.** 어느 슬롯이든 1개 충족하면 달성 |
| `EquipSlotTypes` | 해당 슬롯의 장비만 판정 |

- 장비 조건은 **항상 "이상"** 이다.
- **장착 시점뿐 아니라 이미 착용 중인 장비도 판정**해야 한다. 그렇지 않으면 조건을 이미 만족한 플레이어가 장비를 벗었다 껴야 한다.

**기타**

- `DungeonClear` 는 `(Dungeon, Stage)` 조합으로 `DungeonStage` 를 조회한다. 판정 근거는 저장 데이터의 **던전별 최고 클리어 단계**다 (`맵시스템_설계.md` 8.2절).
- 진행도 분모는 `KillMonster` 만 `QuestParam_2` 이고, 나머지는 전부 조건 충족형(0/1)이다.

## 4. 진행 판정

### 4.1 활성화 조건

메인·서브 모두 동일한 식을 쓴다.

```
ClearedMainQuestID >= ReqQuestID  AND  PlayerLevel >= ReqLevel
```

- 메인 퀘스트는 직전 퀘스트를 가리키므로 등호로 성립한다.
- 서브 퀘스트는 "메인 N 이상 클리어"라는 이상 조건으로 성립한다.
- **`ReqQuestID`가 빈 Main 퀘스트가 시작 퀘스트**다.

### 4.2 ReqLevel 미달

메인 퀘스트가 항상 표시되므로, 선행 퀘스트는 깼지만 레벨이 모자란 경우 **`ReqLevel` 값을 이용해 "레벨 부족" 안내를 UI에 표시**한다.

### 4.3 마지막 메인 퀘스트

`ReqQuestID`로 자신을 가리키는 Main 퀘스트가 없으면 마지막이다. 완료 후 상시 표시 영역에 완료 문구를 표시한다.

### 4.4 저장 데이터

```
ClearedMainQuestID   (int)   — 클리어한 마지막 메인 퀘스트 ID
진행 중 메인 퀘스트 진행도    (QuestProgress: questId + counter)
진행 중 서브 퀘스트 (최대 2개)
```

반복 서브 퀘스트는 **클리어 이력을 저장하지 않으므로** 세이브 데이터가 늘어나지 않는다.

> **진행 상태를 저장하는 목표는 `KillMonster` 하나뿐이다**
>
> `QuestProgress.counter` 를 쓰는 것은 처치 수 누적뿐이고, 나머지 5종은 **판정할 때마다 현재 상태를 재평가**한다(0/1).
>
> 부수 효과가 있다. **조건을 이미 충족한 상태로 수주하면 즉시 달성된다.** Rare 장비를 이미 끼고 있으면 `EquipItemGrade` 퀘스트는 수주하는 순간 완료 가능 상태가 된다. 이것은 의도된 동작이다 — 그렇지 않으면 장비를 벗었다 다시 껴야 한다.

### 4.5 기타 규칙

- 서브 퀘스트 슬롯 2개가 찬 상태에서 NPC와 대화하면 **수락 불가 안내**를 띄운다. 수락형이 `Npc`라 플레이어가 직접 고르는 구조이므로 우선순위 로직은 불필요하다.
- 반복 서브 퀘스트 재수락 시 **진행도는 0부터** 시작한다.
- 퀘스트를 포기하면 진행도를 초기화한다. (서브만 가능)
- `QuestTargetType=Talk`이고 대상 NPC가 완료 담당 NPC와 같으면 대화 한 번에 목표 달성과 완료가 연달아 일어난다. **목표 갱신 → 완료 판정 순서**를 지킨다.

## 5. NPC 테이블

### 5.1 Enum

```
!Enum   NpcType
        Shop            상인
        Blacksmith      대장간
        Storage         창고
        Portal          포탈 (이동 UI를 띄움)

!Enum   DialogTriggerType
        Default         퀘스트 무관 기본 대사
        QuestAccept     수락 전 (퀘스트 설명)
        QuestProgress   진행 중, 목표 미달
        QuestComplete   완료 처리 대화
```

### 5.2 Npc — 마스터 데이터

| 컬럼 | 타입 | 설명 |
|---|---|---|
| ID | !int | 단순 순번 (맵 정보를 섞지 않는다) |
| Name | !string | |
| Title | !string | 직함. 이름 위 표시용, 빈값 허용 |
| NpcType | !NpcType | 상호작용 시 열리는 기능 |
| FunctionID | !int | 타입별 참조 (ShopID 등) |
| PrefabName | !string | 필드 배치 프리팹 |
| Portrait | !string | 대화창 초상화 |

**퀘스트 기능은 `NpcType`에 넣지 않는다.** 하나의 NPC가 퀘스트도 주고 상점도 여는 경우가 흔하므로 단일 타입으로 표현할 수 없다. 퀘스트 보유 여부는 `AcceptNpcID` / `CompleteNpcID`를 로딩 시 역인덱스로 만들어 판정한다.

### 5.3 NpcSpawn — 배치

| 컬럼 | 타입 | 설명 |
|---|---|---|
| ID | !int | |
| NpcID | !int | → `Npc.ID` |
| MapID | !int | → `Map.ID` |
| SpawnPointID | !int | 씬 마커 ID. **맵 내에서만 유니크** |
| SpawnStartQuestID | !int | 이 메인퀘 클리어 후 등장. None이면 항상 |
| UseSpawnEnd | !bool | TRUE일 때만 `SpawnEndQuestID` 를 판정한다 |
| SpawnEndQuestID | !int | 이 메인퀘 클리어 후 소멸 |

> **`UseSpawnEnd` 가 필요한 이유**
>
> 판정식이 `ClearedMainQuestID >= SpawnEndQuestID` 인데 빈칸은 `None`(0)이므로 이 식이 **항상 참**이 된다. 별도 플래그 없이 "빈칸이면 계속 등장"을 표현하면 코드에서 0을 특수 분기해야 하고, 그 한 줄을 빠뜨리면 **모든 NPC가 에러 없이 사라진다.**
>
> `SpawnStartQuestID` 는 반대로 `ClearedMainQuestID >= 0` 이 항상 참이라 "빈칸이면 항상 등장"이 자연스럽게 성립한다. 대칭은 깨지지만 컬럼을 하나 아끼는 쪽을 택했다.

**배치 방식 — 하이브리드**

씬에는 `SpawnPoint` 마커만 배치하고 `SpawnPointID`를 부여한다. 테이블은 `MapID + SpawnPointID + NpcID + 등장 조건`만 관리한다.

- 좌표는 씬 에디터에서 눈으로, 등장 조건은 테이블에서 관리한다.
- 실질 키는 `(MapID, SpawnPointID)` 복합키다.
- 마커는 위치만 담당한다. 여러 NPC가 조건부로 같은 자리를 나눠 쓸 수 있다.
- **위험**: 씬에서 마커를 지우면 테이블은 멀쩡한데 NPC만 조용히 안 나온다. `NpcSpawner` 가 마커를 못 찾으면 경고 로그를 남긴다.
- 등장 조건은 **메인 퀘스트 진행도**로 판정하며, 퀘스트 상태가 바뀔 때 `NpcSpawner.Refresh()` 가 전 NPC를 재평가한다. 매 프레임 순회하지 않는다.

**방향(FlipX)은 테이블에 두지 않는다.** 모든 NPC가 동일하게 처리되므로 코드에서 좌우만 전환한다.

### 5.4 NpcDialog — 대사

| 컬럼 | 타입 | 설명 |
|---|---|---|
| ID | !int | |
| NpcID | !int | |
| QuestID | !int | **0이면 퀘스트 무관 기본 대사** |
| TriggerType | !DialogTriggerType | |
| Text | !string | 대사 전문 |

**참조 컬럼을 두지 않는 구조**

`Npc`나 `Quest`에 `DialogID`를 두지 않고, `NpcDialog`가 `NpcID + QuestID + TriggerType`을 직접 갖는다. 로딩 시 `Dictionary<(NpcID, QuestID, Trigger), string>`을 만들면 조회는 O(1)이고, 퀘스트 테이블에 대사용 컬럼이 늘어나지 않는다.

**대사 줄 나누기**

`LineIndex`를 두지 않고 **`Text` 한 셀에 전체 대사**를 넣는다. 코드에서 구분자로 Split해 페이지 단위로 넘긴다.

- 구분자는 `|` 같은 **명시적 문자**를 쓴다. 셀 내 줄바꿈(Alt+Enter)은 컨버터에서 행이 깨질 위험이 있어 피한다.
- 자동 줄바꿈에만 맡기면 페이지 나누는 지점을 기획에서 제어할 수 없다.
- 줄 단위 부가 정보(화자 교체, 표정, 연출)나 대사 선택지는 지원하지 않는다.

### 5.5 상호작용 우선순위

```
1. 완료 가능한 퀘스트 있음  → QuestComplete
2. 수락 가능한 퀘스트 있음  → QuestAccept
3. 진행 중 퀘스트 있음      → QuestProgress
4. 그 외                    → NpcType 기능 UI 또는 Default
```

**폴백 규칙**

| 상황 | 대사 |
|---|---|
| 목표 달성 + 완료 담당 NPC | `QuestComplete` |
| 목표 달성 + 그 외 NPC | `Default` |
| 퀘스트 완료 후 | `Default` |
| 해당 QuestID 대사가 없음 | `Default` |

목표 달성 후 완료 담당이 아닌 NPC가 "아직 남았다"고 말하는 것을 막기 위한 규칙이다. 별도 트리거(`QuestReady`)를 만드는 대신 폴백으로 처리한다.

**퀘스트 마커(느낌표/물음표)** 도 위 판정을 그대로 쓴다. 퀘스트 상태 변경 이벤트가 올 때만 갱신하고 매 프레임 순회하지 않는다.

## 6. 검증 규칙

### Quest

- `ReqQuestID`는 `Category=Main`인 퀘스트 ID만 허용
- `ReqQuestID`가 빈 Main 퀘스트는 **정확히 1개**
- **두 Main 퀘스트가 같은 `ReqQuestID`를 가지면 오류** — 체인이 분기하면 선형 진행이 깨진다. `NextQuestID`를 두지 않으므로 이 검증이 체인 무결성을 담보하는 유일한 장치다.
- `IsRepeatable=TRUE`는 Sub만 허용
- `AcceptType=Npc` → `AcceptNpcID` 필수 / `CompleteType=Npc` → `CompleteNpcID` 필수
- `QuestTargetType` 별 파라미터 검증 (3.2 표 기준)

| TargetType | 검증 |
|---|---|
| `KillMonster` | P1이 `Monster`에 존재 / P2가 1 이상 정수 / P3는 비었거나 `Map.ID` 존재 |
| `EquipItemGrade` | P1이 `ItemGradeType` 존재 / P2는 비었거나 `EquipSlotTypes` 존재 |
| `EquipItemLevel` | P1이 1 이상 정수 / P2는 비었거나 `EquipSlotTypes` 존재 |
| `Talk` | P1이 `Npc`에 존재 |
| `DungeonClear` | P1이 `Dungeon`에 존재 / `(P1, P2)`가 `DungeonStage`에 존재 |
| `ReachLevel` | P1이 `CharacterLevelExp` 범위 내 |

- **정의되지 않은 파라미터 슬롯에 값이 있으면 경고** — 자유 형식 컬럼에서 오타를 잡는 유일한 장치다. 한 칸 밀려 적은 데이터가 여기서 걸린다.
- `KillMonster`의 P1이 어느 `MonsterSpawn`에도 없으면 경고 (완료 불가 퀘스트)

### Npc

- `NpcSpawn`의 `(MapID, SpawnPointID)` 실존 여부는 **빌드 전 씬 순회 툴**이 검증한다. 엑셀 컨버터는 씬을 읽지 않는다.
- `UseSpawnEnd=TRUE`인데 `SpawnEndQuestID`가 비면 오류 / `FALSE`인데 값이 있으면 경고
- `NpcDialog.QuestID`가 있으면, 그 NPC가 해당 퀘스트의 Accept/Complete NPC이거나 Talk 대상이어야 함
- `CompleteType≠Npc`인 퀘스트에 `QuestComplete` 대사가 있으면 경고 (영원히 표시되지 않음)

```
Quest.AcceptNpcID         → Npc.ID
Quest.CompleteNpcID       → Npc.ID

  └ ReachLevel            → P1 레벨

NpcSpawn.MapID            → Map.ID

```

## 8. 미결 / 다음 작업

### 9.1 데이터가 규칙과 어긋나 있다 — 수정 필요

**`QuestParam` 슬롯 순서가 3.2절 표와 다르게 적혀 있다.** 코드(`QuestCatalog`)는 표대로 파싱하므로 해당 퀘스트들이 정상 동작하지 않는다.

| 목표 타입 | 규칙 (표 = 코드) | 현재 데이터 | 결과 |
|---|---|---|---|
| `KillMonster` | P1 몬스터 / P2 수량 / P3 맵 | P1 맵(`20101`) / P2 몬스터 / P3 수량 | 몬스터 ID를 맵 ID로 읽는다 |
| `EquipItemLevel` | P1 레벨 / P2 슬롯 | P1 슬롯(`Weapon`) / P2 레벨 | 레벨 파싱 실패 |
| `ReachLevel` | P1 레벨 | P1 비어 있고 P3 에 `60` | 요구 레벨 0 |

`EquipItemGrade` · `Talk` · `DungeonClear` 3종은 표와 일치한다.

**존재하지 않는 몬스터를 목표로 한다.** 서브퀘 3~5가 `10004` / `10005` / `10006` 을 지정하는데 `Monster` 에는 `10001`~`10003`, `20001`, `30001` 다섯 종뿐이다. 완료 불가 퀘스트다.

**`NpcSpawn` 에 즉시 소멸 조합이 있다.** ID 2(대장장이)가 `UseSpawnEnd = TRUE` 인데 `SpawnEndQuestID = 0` 이다. 판정식이 `ClearedMainQuestID >= 0` 이라 항상 참이 되어 **대장장이가 처음부터 등장하지 않는다.** 6장 검증 규칙이 오류로 잡도록 정한 사례가 실제로 데이터에 들어가 있다.

**`SpawnPointID` 가 대부분 0이다.** 포탈관리인(ID 4)만 `4` 를 갖고 상인·대장장이·창고지기는 0이다. 맵에 대응 마커가 없으면 경고만 남고 NPC가 뜨지 않는다.

### 9.2 비어 있는 데이터

- **`RewardExp` / `RewardGroupID` 가 11행 전부 0이다.** 퀘스트를 완료해도 보상이 없다.
- **`Desc` 가 전량 비어 있다.** 목표 지역명을 `Desc` 에 기재하기로 한 규칙(3.3)이 적용되지 않았다.
- **`AcceptNpcID` / `CompleteNpcID` 가 전부 0이다.** `AcceptType = Npc` / `CompleteType = Npc` 인데 담당 NPC가 지정돼 있지 않아 수락·완료가 불가능하다.
- **`NpcDialog` 가 상인(1001) 4행뿐이다.** 나머지 3 NPC는 대사가 없어 `Default` 폴백도 나오지 않는다.
- **`Npc.PrefabName` 이 포탈관리인만 채워져 있다.**

### 9.3 그 외

- **`DungeonClear` 판정 근거가 인메모리다** — `DungeonProgress` 의 최고 클리어 단계가 서버 미이관이라 재접속하면 초기화된다 (`맵시스템_설계.md` 8.2).
- **`Npc.FunctionID` 가 전부 0이다** — `NpcType = Shop` 인 상인이 어느 상점을 여는지 지정돼 있지 않다.
- **일일/주간 미션 시스템** — 킬 수, 상자 오픈 등. 퀘스트와 분리된 별도 시스템으로 다룬다.
- **로컬라이징** — `Name` / `Desc` / `Text` 를 직접 텍스트로 두었다. 다국어가 필요해지면 키 방식으로 전환한다.
