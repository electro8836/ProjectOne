# 데이터 작성 가이드

> 2D 탑다운 방치형 핵앤슬래시 (Unity, 싱글플레이) — 엑셀 데이터 신규 작성 규칙
> 이 문서는 **설계가 아니라 작업 지시서**다. 규칙의 근거는 각 시스템 설계 문서가 갖는다.

---

## 0. 이 문서의 사용법

데이터를 새로 만들 때 **이 문서 하나만 보면 규칙을 어기지 않도록** 정리했다.

AI에게 데이터 생성을 요청할 때는 **이 문서를 첨부**하고, 8장의 요청 템플릿을 쓴다. 대상 시트의 현재 엑셀 파일도 함께 주면 ID 충돌과 참조 누락을 자동으로 피할 수 있다.

**출력 형식은 항상 탭 구분 텍스트**로 받는다. 엑셀에 그대로 붙여넣을 수 있어야 한다.

---

## 1. 절대 규칙

작업 전에 이 10개를 먼저 읽는다. 대부분의 사고가 여기서 나온다.

1. **빈 칸은 언제나 `None`(0)이다.** "비면 에러"는 컬럼별 검증이지 전역 규칙이 아니다.
2. **자동 폴백을 만들지 않는다.** 값이 자동으로 메워지면 누락을 아무도 못 알아챈다. 안 나오면 바로 보이는 쪽이 낫다.
3. **ID의 카테고리 번호는 enum 순서가 아니라 고정 대역표다.** enum을 재정렬해도 ID는 안 바뀐다. 한 번 쓴 번호는 재사용하지 않는다.
4. **ID 공유 테이블은 세트로 만든다.** `Item` 행만 만들고 `Equipment` / `Consumable` 행을 빠뜨리면 드랍 시 실패한다.
5. **다형 파라미터는 필수가 앞, 선택이 뒤다.** 중간에 빈 칸이 생기지 않게 배치한다.
6. **정의되지 않은 파라미터 슬롯을 채우지 않는다.** 자유 형식 컬럼에서 오타를 잡는 유일한 장치가 "안 쓰는 칸에 값이 있음" 경고다.
7. **`Base` 레이어에는 캐릭터·몬스터만 값을 넣는다.** 장비·노드·버프는 `Add` / `Ratio` / `Amp` 만 쓴다. `Base` 에 넣으면 장비를 벗을 때 기본 능력치가 사라진다.
8. **`Percent` 값은 소수로 적는다.** 15%는 `0.15` 다. `× 100` 은 표시할 때만 한다.
9. **필수 스탯 4종을 빠뜨리지 않는다.** `Atk` / `AtkSpeed` / `MaxHp` / `Def` 의 `_Base`. 특히 `AtkSpeed` 가 없으면 공격 주기가 0으로 나뉜다.
10. **참조는 정방향으로만 만든다.** "나를 쓰는 것들의 목록"을 갖는 컬럼은 만들지 않는다.
11. **비율(Ratio/Amp) 옵션은 5개 스탯에만 붙일 수 있다.** `Atk` · `MaxHp` · `HpRegen` · `Def` · `LifeOnHit`. 나머지 18종은 `Base`/`Add` 레이어뿐이라 `OPT_XXX_RATIO` 를 만들 수 없다.
12. **데이터를 넣었으면 한 번 실행해 부팅 로그를 본다.** 실질 검증은 변환기가 아니라 부팅 시 `Catalog.Build()` 들이 한다. 빌드가 통과했다고 데이터가 맞는 것이 아니다.

## 2. 작성 순서

의존성 때문에 순서가 있다. **위에서 아래로** 채운다.

```
[1] 기반          Stat / StatDetail / Option / Currency
                    ↓
[2] 아이템 본체    Item  →  Equipment  →  EquipOption
                            EquipEnhance / EquipPromotion / EquipQuality
                            EquipPurity / EquipGradeWeight / EquipEnhanceTier
                    ↓
[3] 스킬          Skill / SkillEffect / SkillModifier
                  Projectile / Summon / Buff
                    ↓
[4] 마스터리       WeaponMastery → SkillTreeNode
                  SkillPoint / MasteryLevelExp / MasteryLevelBonus
                  CharacterStat / CharacterLevelExp
                    ↓
[5] 몬스터        Monster → MonsterStat / MonsterSkillSet → MonsterSpawn
                  (보스면) BossMonsterPhase
                    ↓
[6] 맵            Act → Map → Field / Dungeon → DungeonStage
                    ↓
[7] 보상          RewardItemPool → Reward
                    ↓
[8] 소모품         Consumable          (Item + Skill + Reward + SkillPoint 필요)
                    ↓
[9] NPC · 퀘스트   Npc → NpcSpawn → Quest → NpcDialog
```

**역방향 참조가 두 군데 있다.**

| 참조 | 처리 |
|---|---|
| `Monster.RewardGroupID` / `MonsterSpawn.RewardGroupID` → `Reward` | [5]에서 비워두고 [7] 이후 채운다 |
| `DungeonStage.RewardGroupID` → `Reward` | [6]에서 비워두고 [7] 이후 채운다 |
| `Field.ReqQuestID` → `Quest` | [6]에서 비워두고 [9] 이후 채운다 |

## 3. ID 발급 총람

### 3.1 아이템 (`Item` / `Equipment` / `Consumable` 공유)

```
장비    :  1 + MM(2) + SS(2) + TT(2) + NNN(3)
그 외   :  1 + MM(2) + SS(2) + NNNNN(5)
```

| MM | 메인 | SS | 서브 |
|---|---|---|---|
| `01` | Equipment | `01` Weapon / `02` Armor / `03` Accessory / `04` Relic |
| `02` | Material | `01` Crafting / `02` Enhance |
| `03` | Consumable | `01` Usable / `02` Box / `03` SkillBook |
| `04` | Collection | `01` Costume |

**장비의 `TT` (EquipSlotTypes 순번)**

| TT | 슬롯 | 소속 SS |
|---|---|---|
| `01` | Weapon | `01` |
| `02` | Helmet | `02` |
| `03` | Armor | `02` |
| `04` | Gloves | `02` |
| `05` | Boots | `02` |
| `06` | Ring | `03` |
| `07` | Amulet | `03` |
| `08` | Relic | `04` |

`TT` 가 정해지면 `SS` 는 하나로 결정된다. 둘이 어긋나면 잘못된 ID다.

### 3.2 나머지 테이블

| 테이블 | 대역 | 예 |
|---|---|---|
| `Act` | 연번 | `1` ~ `5` |
| `Map` (마을) | `1` | `1` |
| `Map` (필드) | `2` + 액트(2) + 순번(2) | `20101` |
| `Map` (던전) | 던전종류(1) + `001` | `2001` 골드 / `3001` 균열 |
| `Field` | **`Map.ID` 공유** | `20101` |
| `DungeonStage` | 던전종류(1) + `000` + 단계(2) | `10001` 골드1단계 / `20001` 균열1단계 |
| `Monster` | 등급(1) + 순번(4) | `10001` 일반 / `20001` 엘리트 / `30001` 보스 |
| `MonsterStat.GroupID` | 공용이면 `101`, 전용이면 `Monster.ID` | `101` / `20001` |
| `MonsterSkillSet.GroupID` | 등급(1) + 순번(3). 보스 페이즈는 `3001`~ | `1001` / `3001` |
| `MonsterSpawn.GroupID` | `1xxx` 필드 / `2xxx` 던전 웨이브 / `Monster.ID` 단독 | `1001` / `2001` / `30001` |
| `BossMonsterPhase.ID` | 연번 | `1` |
| `Npc` | 연번 (맵 정보를 섞지 않는다) | `1001` |
| `Quest` (메인) | **10 단위 증가** | `1000010` |
| `Quest` (서브) | 연번 | `2000010` |
| `Reward.GroupID` | 용도별 대역 — 아래 참조 | `1001` |
| `RewardItemPool.PoolID` | `1001` / `2001` / `3001` | `3001` |
| `EquipGradeWeight` | `1xxxx` 필드 / `2xxxx` 보스 / `3xxxx` 던전 / `4xxxx` 상자 | `10001` |
| `EquipOption.GroupID` | `Equipment.ID` 와 동일 | `1010101001` |
| `SkillTreeNode.GroupID` | 마스터리별 보드 | `101` |

**`Reward.GroupID` 현재 대역**

| 대역 | 용도 |
|---|---|
| `1001` | 상자 개봉 |
| `2001` | 일반 드랍 |
| `3001` / `3002` | 묶음 상품 |
| `4001` ~ | 단품 (재화·재료) |
| `5001` ~ | 상자 등급별 |

> **⚠ `Reward.GroupID` 와 `RewardItemPool.PoolID` 의 번호가 겹쳐 있다.** 둘 다 `1001` / `2001` / `3001` 을 쓴다. `TargetID` 에 풀 번호 대신 그룹 번호를 잘못 적어도 에러가 나지 않으므로, 여유가 있을 때 대역을 분리하는 편이 낫다.

### 3.3 문자열 ID (`!EnumTable`)

| 테이블 | 접두 | 예 |
|---|---|---|
| `Stat` | `Stat_` | `Stat_Atk` |
| `StatDetail` | `StatDetail_` | `StatDetail_Atk_Add` |
| `Option` | `OPT_` | `OPT_ATK_ADD` |
| `Skill` | `Skill_` | 아래 참조 |
| `SkillEffect` | `SE_` | `SE_DualBlades_Attack_Damage` |
| `SkillModifier` | `SKM_` | `SKM_DualBlades_Active_01_Ratio` |
| `Projectile` | `PJT_` | `PJT_CrossBow_Bolt` |
| `Summon` | `Summon_` | `Summon_Spark` |
| `Buff` | `BUFF_` | `BUFF_Stun` |
| `WeaponMastery` | `Mastery_` | `Mastery_DualBlades` |
| `SkillPoint` | `SkillPoint_` | `SkillPoint_Item` |
| `Currency` | (접두 없음) | `Gold` / `Dia` / `Ruby` |
| `Dungeon` | (접두 없음) | `Gold` / `Rift` / `Labyrinth` / `Ruins` |
| `EquipPurity` | `Purity_` | `Purity_1` (표시는 `DisplayName` D~S) |
| `EquipEnhanceTier` · `DropTier` | `Tier_` | `Tier_1` |

**`Skill` 의 접두 뒤 형식은 참조원에 따라 다르다.**

| 소유자 | 형식 | 예 |
|---|---|---|
| `WeaponMastery.NormalAttackSkill` | `Skill_{WeaponType}_Attack` | `Skill_DualBlades_Attack` |
| `SkillTreeNode` (습득) | `Skill_{WeaponType}_{Active\|Passive}_{NN}` | `Skill_DualBlades_Active_01` |
| `MonsterSkillSet.SkillID` | `Skill_Monster_{종류}_{NN}` | `Skill_Monster_RangeAttack_01` |
| (보스) | `Skill_Monster_Boss_{이름}_{NN}` | `Skill_Monster_Boss_Doom_01` |
| `Summon.SkillID_*` | `Skill_{소환물}_{동작}` | `Skill_SummonSpark_Attack` |
| `Consumable.EffectParam_1` | `Skill_Item_{효과}` | `Skill_Item_HealSmall` |

> **주의 — `Currency` 와 `Dungeon` 이 둘 다 `Gold` 를 쓴다.** 다형 컬럼(`Reward.TargetID`, `Quest.QuestParam_1`)에서 같은 문자열이 서로 다른 뜻이 된다. 접두를 붙이거나 한쪽 값을 바꾸는 결정이 나면 이 표를 갱신한다.

## 4. 레시피

"이걸 추가하고 싶다" → **손대야 할 시트 전부**를 나열했다. 하나라도 빠지면 컨버터가 잡거나 조용히 안 나온다.

### 4.1 신규 무기 (기존 마스터리)

| 시트 | 행 |
|---|---|
| `Item` `#Item` | 1행 — `1 01 01 01 NNN` |
| `Equipment` `#Equipment` | 1행 — `EquipSlotType=Weapon`, `WeaponType` 지정, `EquipOptionGroupID = ID` |
| `Equipment` `#EquipOption` | **6행** — `Normal` ~ `MaxGrade` 전 등급 |

- `WeaponType` 은 반드시 기존 `WeaponMastery` 가 쓰는 값이어야 한다. 새 값이면 4.5로 간다.
- `EquipOption` 의 옵션은 그 무기 `RangeType` 과 일치시킨다. 근접 무기에 `OPT_RANGE_*` 를 넣지 않는다.

### 4.2 신규 방어구 · 장신구 · 유물

| 시트 | 행 |
|---|---|
| `Item` `#Item` | 1행 — `TT` 로 슬롯 지정 |
| `Equipment` `#Equipment` | 1행 — `WeaponType` 은 **비운다**(`None`) |
| `Equipment` `#EquipOption` | 6행 |

- 방어구·장신구에 `OPT_MELEE_*` / `OPT_RANGE_*` 를 **주축 옵션으로 넣지 않는다.** 무기를 바꾸면 절반이 죽는다. 세트 개념으로 의도한 경우에만 쓰고, 그때는 방어구 4종도 함께 갈라야 한다.

### 4.3 신규 소모품

| 시트 | 행 |
|---|---|
| `Item` `#Item` | 1행 — `MainCategory=Consumable` |
| `Consumable` `#Consumable` | 1행 — 같은 ID |
| (`ConsumeEffect=Skill` 이면) `Skill` 계열 | 스킬 + 효과 행 |
| (`ConsumeEffect=Reward` 이면) `Reward` | 보상 그룹 |

| ConsumeEffect | Param_1 (필수) | Param_2 |
|---|---|---|
| `Skill` | `Skill.ID` | — |
| `Reward` | `Reward.GroupID` | 반복 횟수 |
| `SkillPoint` | `SkillPoint` ID | 지급 포인트 |

- `Skill` 타입의 `CastingType` 은 `Instant` 또는 `Casting` 만 쓴다. `OnHit` 은 아이템으로 못 켠다.
- 회복·버프 소모품은 같은 `CooldownGroup` 으로 묶는다. 안 묶으면 번갈아 연타할 수 있다.
- `MaxStack` 은 비운다(무한).

### 4.4 신규 스킬

| 시트 | 행 |
|---|---|
| `Skill` `#Skill` | 1행 |
| `Skill` `#SkillEffect` | **1행 이상** — `EffectID_01`/`_02` 가 전부 비면 아무 일도 안 일어난다 |
| (투사체면) `Projectile` | 1행 |
| (소환이면) `Summon` | 1행 |
| (버프면) `Buff` + 그 버프의 `SkillEffect` | |
| **획득 경로** | 아래 중 하나 필수 |

**획득 경로가 없으면 경고가 뜬다.** 넷 중 하나에 반드시 등록한다.

```
SkillTreeNode (SkillGrant 옵션)  ← 캐릭터 스킬
WeaponMastery.NormalAttackSkill  ← 평타
MonsterSkillSet.SkillID          ← 몬스터 · 보스 페이즈
Summon.SkillID_1 / _2            ← 소환물
Consumable.EffectParam_1         ← 소모품
```

- `SkillCategory=Normal` 이면 `Cooldown` 이 곧 공격 주기다. **0으로 두지 않는다.**
- 소환물 스킬은 `Active` 로 만든다. `Normal` 은 공속을 참조하는데 소환물이 상속하지 못할 수 있다.
- `ScaleStat` 에는 `Stat_` 을, `StatChange` 에는 `StatDetail_` 을 지정한다. 가장 흔한 실수다.
- `AnimName` 은 **애니메이터 트리거명**이다. `Attack` / `Skill` / `Hit` / `Die` 넷뿐이고, **오타는 어떤 검증에도 걸리지 않는다.** 모션 없이 효과만 낼 스킬은 `AnimName` 과 `AnimLength` 를 비운다.
- 조건 발동형(`OnCombo` / `OnHit` 등)은 직접 시전할 수 없다. 자동 전투에서 터뜨릴 액티브는 이쪽을 쓴다.
- `Force` 는 `EffectID_02` 가 아니라 **`ChainEffectIDs`** 로 연결한다. 아니면 빗나가도 밀려난다.
- 투사체의 속도·수명·궤적은 테이블에 없다. **프리팹이 소유한다.**

### 4.5 신규 마스터리 (= 신규 무기 종류)

가장 무거운 작업이다. 순서대로 한다.

| 순서 | 시트 | 내용 |
|---|---|---|
| 1 | `Equipment` `#Enum` | `WeaponType` 에 값 추가 (**끝에만**) |
| 2 | `Skill` | 평타 1 + 액티브 2~3 + 패시브 1~2, 각각 `SkillEffect` 동반 |
| 3 | `Option` | 각 스킬의 `SkillGrant` 옵션 + 계수 `Modifier` 옵션 |
| 4 | `Mastery` `#WeaponMastery` | 1행 — `Mastery_{WeaponType}` |
| 5 | `Mastery` `#SkillTreeNode` | 보드 크기만큼 (6×4면 18~24행) — **새 `GroupID` 를 쓴다** |
| 6 | `Item` + `Equipment` + `EquipOption` | 무기 아이템 (4.1) |

**스킬 트리 작성 규칙**

- 트리 총 용량(`Σ MaxLevel`)은 **스킬포인트 예산 80의 1.5~2배(120~160)**. 같거나 작으면 전 노드를 만렙까지 찍을 수 있어 빌드 선택이 없어진다.
- 행 게이트(`RequireTreePoint`)는 **위쪽 행들의** 용량 합을 넘지 않는다. 같은 행·아래 행 투자는 세지 않는다.
- `PrevNodeID` 는 자신보다 위쪽 행만 가리킨다.
- **노드는 옵션을 2개까지 갖는다.** 스킬 습득 노드는 슬롯 1에 `SkillGrant`(값 미사용), 슬롯 2에 `Modifier` 강화를 함께 두는 것이 기본형이다.
- 계수 노드는 그 트리에서 습득하는 스킬만 대상으로 한다.
- 마스터리 `RangeType` 과 반대인 옵션을 넣지 않는다.
- **`SkillTreeNodeGroupID` 를 기존 값으로 두면 다른 무기의 트리가 그대로 뜬다.** (현재 4종이 전부 `101` 을 공유하는 상태다)

### 4.6 신규 몬스터

| 시트 | 행 |
|---|---|
| `Monster` `#Monster` | 1행 |
| `Monster` `#MonsterStat` | **4행 이상** — 필수 스탯 |
| `Monster` `#MonsterSkillSet` | **1행 이상** — 기존 그룹 재사용 가능 |
| `Monster` `#MonsterSpawn` | 1행 이상 — 없으면 게임에 안 나온다 |
| (보스면) `Monster` `#BossMonsterPhase` | 페이즈 수만큼 |
| `Skill` | 평타 1개 필수 |

**`MonsterStat` 필수 4종**

```
StatDetail_Atk_Base
StatDetail_AtkSpeed_Base     ← 빠지면 0으로 나눈다
StatDetail_MaxHp_Base
StatDetail_Def_Base
```

`CritRate_Base` 를 넣었으면 `CritDamage_Base` 도 넣는다.

- **AI 전용 테이블이 없다.** `AIType` / `AggroType` / `DetectRange` / `LeashRange` 를 `Monster` 행에 직접 적는다.
- 스킬셋 그룹에 `SkillCategory=Normal` 스킬이 **1개** 있어야 한다. 전부 실패했을 때의 폴백이다.
- `Priority` 는 낮을수록 먼저 시도한다. 같은 그룹 안에서 중복되지 않게 한다.
- **엘리트·보스는 `StatDetail_MaxBreakGauge_Base` 도 필요하다.** 없으면 브레이크가 동작하지 않는다.
- 보스는 `AIType = Boss` + `BossMonsterPhase` 행이 세트다. `PhaseSkillID` 는 `CastingType = Casting` 이어야 하고(제한시간이 곧 캐스팅 시간), `GimmickRequired ≤ GimmickCount` 여야 한다.
- `BaseExp` / `PerLevelExp` 를 비우면 경험치가 0이다.

### 4.7 신규 스테이지 / 액트

| 시트 | 행 |
|---|---|
| `Map` `#Act` | (새 액트일 때) 1행 |
| `Map` `#Map` | 1행 — `MapType=Field`, `MapPrefab` 주소 지정 |
| `Map` `#Field` | 1행 — **같은 ID** + `ActID` / `Order` / `ReqLevel` |
| `Monster` `#MonsterSpawn` | 그 지역용 조합 |
| **맵 프리팹** | `MonsterSpawnPoint` 마커에 `SpawnGroupId` 지정 + `MapAnchor` 배치 |

- 액트 내 `Order` 가 중복되면 안 된다. `Order` 는 **맵 배치 좌표의 입력**이기도 하다.
- **`ReqLevel` 이 곧 해금이자 클리어 판정이다.** 별도 클리어 기록이 없다.
- 액트 해금은 첫 필드(`Order=1`)의 `ReqLevel` 로 갈음한다.
- 맵은 씬이 아니라 **프리팹**이다. `MapPrefab` 주소가 어드레서블에 등록돼 있어야 한다.

### 4.8 신규 던전 단계

| 시트 | 행 |
|---|---|
| `Map` `#DungeonStage` | 단계 수만큼 |
| `Map` `#Map` | 새 맵이 필요할 때만 (여러 단계가 한 맵을 공유해도 된다) |
| `Monster` `#MonsterSpawn` | `2xxx` 대역 조합 |
| `Reward` | 클리어 보상 그룹 |
| **맵 프리팹** | `DungeonSpawnSlot` 마커 배치 (익명, `SlotIndex` 만) |

- `MonsterSpawnGroupIDs` 는 배열이고 **길이가 곧 웨이브/페이즈 수**다. 비우면 몬스터가 없다.
- `Stage` 는 1부터 빠짐없이 연속이어야 한다. 중간이 비면 해금이 끊긴다.
- `(DungeonType, Stage)` 조합이 중복되면 안 된다.
- 해금 조건 컬럼은 없다. **직전 단계 클리어**가 코드 규칙이다.
- `TimeLimit` 을 0으로 두면 무제한이다.
- 새 던전 **종류**를 추가하면 `#Dungeon` 행과 함께 **`StageModeFactory` 에 모드 구현**이 필요하다. 데이터만 만들면 입장 시 에러가 난다.
- 부활 컬럼은 `RevivalCostType` / `RevivalCost` / **`RevivalCostRatioStep`**(비율) / `MaxRevivalCount` 네 개다. `MaxRevivalCount` 가 0이면 부활 불가 던전이 된다.

### 4.9 신규 퀘스트

| 시트 | 행 |
|---|---|
| `Quest` `#Quest` | 1행 |
| `Npc` `#Npc` / `#NpcSpawn` | 수락·완료 NPC가 없으면 |
| `Npc` `#NpcDialog` | `QuestAccept` / `QuestProgress` / `QuestComplete` |
| `Reward` | 보상 그룹 |

**`QuestParam` 배치**

| QuestTargetType | Param_1 (필수) | Param_2 | Param_3 |
|---|---|---|---|
| `KillMonster` | `Monster.ID` | 처치 수량 | `Map.ID` (선택) |
| `EquipItemGrade` | `ItemGradeType` | `EquipSlotTypes` (선택) | — |
| `EquipItemLevel` | 장비 레벨 | `EquipSlotTypes` (선택) | — |
| `Talk` | `Npc.ID` | — | — |
| `DungeonClear` | `Dungeon` | Stage | — |
| `ReachLevel` | 레벨 | — | — |

> **⚠ 슬롯 순서를 반드시 위 표대로 적는다.** 현재 데이터에 `KillMonster` · `EquipItemLevel` · `ReachLevel` 3종이 다른 순서로 적혀 있어 동작하지 않는다 (`퀘스트시스템_설계.md` 9.1). 파싱 코드는 이 표를 따른다.

- 메인 퀘스트는 **10 단위**로 부여한다. 중간 삽입 여유를 남긴다.
- `ReqQuestID` 가 빈 Main 퀘스트는 **정확히 1개**여야 한다.
- 두 Main 퀘스트가 같은 `ReqQuestID` 를 가지면 체인이 분기해 깨진다.
- `AcceptType=Npc` 면 `AcceptNpcID` 필수. `CompleteType=Npc` 면 `CompleteNpcID` 필수.
- `Desc` 에 지역명을 적었으면 `Param_3` 도 채운다. 안 그러면 표시와 판정이 어긋난다.
- **반복 서브 퀘스트에는 `RewardExp` 를 넣지 않는다.** 무한 파밍이 된다.
- `NpcSpawn` 에서 **`UseSpawnEnd` 를 켰으면 `SpawnEndQuestID` 를 반드시 채운다.** 비우면 판정식이 항상 참이 되어 그 NPC가 처음부터 나오지 않는다.
- `KillMonster` 외의 목표는 **진행도를 저장하지 않고 매번 재평가**한다. 조건을 이미 충족한 상태로 수주하면 즉시 달성된다.

### 4.10 신규 보상 그룹

| 시트 | 행 |
|---|---|
| `Reward` `#RewardItemPool` | 조건 행 (풀이 필요할 때) |
| `Reward` `#Reward` | 지급 행 |

| RewardType | TargetID |
|---|---|
| `Item` | `Item.ID` |
| `ItemPool` | `RewardItemPool.PoolID` |
| `Currency` | `Gold` / `Dia` / `Ruby` |

- **`Chance` 는 필수다.** 확정 지급도 `1` 을 적는다. 비우면 `0`(봉인)이 된다.
- `MaxCount = 0` 이면 `MinCount` 고정이다.
- **확정 상품은 `FixedGrade` / `FixedPurity` / `FixedQuality` 를 채운다.** 추첨이 끼지 않아 미리보기와 실제 지급이 같아진다. `FixedGrade` 가 있으면 `EquipGradeWeightID` 는 쓰이지 않는다.
- **장비가 나올 수 있는 행은 `EquipGradeWeightID` 필수.** 등급 고정이 필요하면 단일 등급에 가중치를 몰아준 행을 만든다.
- `RewardItemPool.MainCategory` 는 필수, `SubCategory` 는 비우면 전체.
- 풀 조건에 매칭되는 아이템이 **0개면 조용히 아무것도 안 나온다.** 조건을 적었으면 실제 아이템이 있는지 확인한다.

- `WeaponMastery.LevelBonusOption` 에는 `Stat` 타입만 쓴다.

## 5. 자주 깨지는 것

실제로 사고가 났거나 검증에 걸린 것들이다.

| 증상 | 원인 |
|---|---|
| 드랍 풀에서 아무것도 안 나옴 | `DropTier` 미기입 / 조건 매칭 0개 / `MainCategory` 불일치 |
| 보상이 전혀 지급되지 않음 | `Chance` 빈 칸 (= 0 = 봉인) |
| 아이템은 나오는데 장비 생성 실패 | `Item` 만 만들고 `Equipment` · `EquipOption` 누락 |
| 스킬을 써도 아무 일 없음 | `EffectID` 전부 비어 있음 / `CastingType` 이 조건 발동형 |
| 몬스터가 공격을 안 함 | `SkillIDs` 에 `Normal` 스킬 없음 / `Cooldown` 이 0 |
| 몬스터가 극단적으로 느림·오류 | `AtkSpeed_Base` 누락 |
| 퀘스트를 완료할 수 없음 | 대상 몬스터가 어느 `MonsterSpawn` 에도 없음 |
| NPC가 전부 사라짐 | `UseSpawnEnd` 를 안 켜고 `SpawnEndQuestID` 만 채움 |
| 옵션을 붙였는데 효과 없음 | `Base` 레이어에 장비 옵션을 넣음 |
| 무기를 바꾸니 능력치가 반토막 | 방어구·장신구에 근접/원거리 전용 옵션을 주축으로 넣음 |
| 등급을 올려도 옵션이 안 바뀜 | `EquipOption` 에 그 등급 행이 없음 |
| ID가 한 칸씩 밀림 | 소모품에 장비 5자리 분할(`TT+NNN`)을 적용 |
| 퀘스트가 엉뚱한 대상을 요구함 | `QuestParam` 슬롯 순서를 표와 다르게 적음 |
| NPC가 처음부터 안 보임 | `UseSpawnEnd=TRUE` + `SpawnEndQuestID` 빈 칸 |
| 스킬 모션만 안 나옴 | `AnimName` 오타 — 검증에 걸리지 않는다 |
| 소모품을 써도 아무 일 없음 | `EffectParam_1` 이 가리키는 스킬이 `Skill` 테이블에 없음 |
| 장비 등급 추첨이 실패함 | `EquipGradeWeightID` 가 존재하지 않는 값 |
| 보스 3페이즈에서 평타만 씀 | 그 페이즈의 `SkillSetGroupID` 가 비었거나 없는 그룹 |
| 비율 옵션을 만들 수 없음 | `Ratio`/`Amp` 레이어가 없는 스탯 (5종 외) |

## 6. 작성 후 체크리스트

```
□ ID가 대역표를 따르는가 (장비는 SS ↔ TT 대응까지)
□ ID 공유 테이블에 짝이 되는 행을 전부 만들었는가
□ 참조하는 ID가 실제로 존재하는가
□ 필수 컬럼을 비우지 않았는가 (Chance / EquipGradeWeightID / MainCategory)
□ 정의되지 않은 파라미터 슬롯에 값을 넣지 않았는가
□ Percent 값을 소수로 적었는가
□ 스탯 레이어가 맞는가 (장비·노드는 Base 금지)
□ 신규 스킬에 획득 경로가 있는가
□ 신규 몬스터에 필수 스탯 4종 + Normal 스킬 1개 + 스폰이 있는가
□ 신규 아이템에 DropTier를 의도대로 넣었는가 (비우면 일반 드랍 제외)
□ 역방향 참조(RewardGroupID, ReqQuestID)를 나중에 채울 목록에 적어뒀는가
□ 비율 옵션을 Ratio/Amp 레이어가 있는 5개 스탯에만 붙였는가
□ 실행해서 부팅 로그의 Catalog 경고를 확인했는가
```

## 7. 임시 데이터 삭제 시 주의

기존 데이터를 지우고 새로 만들 때, **지우면 안 되는 것**이 있다.

| 유지 | 이유 |
|---|---|
| `Stat` `#Stat` / `#StatDetail` | 구조 데이터다. **23 + 56행**이 설계 그 자체 |
| `Option` `#Option` 의 `Stat` 타입 32행 | 위와 같음. 스킬 연동 옵션 4종은 스킬 데이터와 함께 지운다 |
| `Currency` `#Currency` | 3행뿐이고 구조 데이터 |
| `Equipment` `#EquipEnhanceTier` / `#EquipQuality` / `#EquipPurity` | 등급·품질 구간 정의. 밸런싱 값이지만 구조에 가깝다 |
| 모든 `#Enum` 블록 | enum을 지우면 참조가 전부 깨진다 |

| 지워도 되는 것 |
|---|
| `Item` / `Equipment` / `EquipOption` 의 아이템 행 |
| `Monster` / `MonsterStat` / `MonsterSkillSet` / `MonsterSpawn` / `BossMonsterPhase` |
| `Quest` / `Npc` / `NpcSpawn` / `NpcDialog` |
| `Reward` / `RewardItemPool` |
| `Consumable` |
| `Map` / `Act` / `Field` / `DungeonStage` |
| `Skill` 계열 전부 |
| `SkillTreeNode` |

**`WeaponMastery` 4행과 `SkillPoint` 3행은 구조에 가깝다.** 지우더라도 같은 형태로 다시 만들어야 한다.

`MasteryLevelExp`(300행) · `CharacterLevelExp`(100행) · `CharacterStat`(10행) 도 유지 대상이다. 곡선 데이터라 다시 만드는 비용이 크다.

## 8. AI에게 요청하는 템플릿

이 문서와 대상 엑셀 파일을 함께 첨부하고 아래 형식으로 요청한다.

```
[요청]
무엇을: 신규 무기 마스터리 "단검" 1종 세트

[범위]
- WeaponType 추가
- 평타 1 + 액티브 2 + 패시브 1
- 스킬 트리 6행 × 4열 (새 GroupID)
- 무기 아이템 2종

[제약]
- RangeType: Melee
- 트리 총 용량 140 내외
- 기존 ID와 충돌 없이

[출력]
시트별로 탭 구분 텍스트. 붙여넣을 시작 셀도 함께.
```

**요청 시 반드시 명시할 것**

- 대상 시트와 행 수
- 기존 데이터를 **유지**하는지 **교체**하는지
- 밸런싱 기준값 (레벨대, 예상 스탯 규모)
- 출력 형식 (탭 구분 / 셀 위치)

**AI가 지켜야 할 것** — 요청 시 이 문서를 첨부하면 아래가 자동으로 적용된다.

1. 1장 절대 규칙 10개
2. 3장 ID 대역표 (기존 데이터와 충돌 검사 포함)
3. 4장 해당 레시피의 **모든 시트**를 빠짐없이 생성
4. 6장 체크리스트 자체 점검 후 결과 보고
5. 역방향 참조는 비워두고 **나중에 채울 목록**을 별도로 안내
