# 상점 시스템 설계

> 2D 탑다운 방치형 핵앤슬래시 (Unity, 싱글플레이) — 상점 진열 / 가격 / 구매 한도 / 보물상자
> 관련 문서: `보상시스템_설계.md`, `아이템시스템_설계.md`, `펫시스템_설계.md`, `코스튬시스템_설계.md`, `히어로패스시스템_설계.md`, `뒤끝서버시스템_설계.md`
> **이 문서는 현재 구현 상태를 기술한다.** 컬럼·행 수는 실제 테이블 기준, 동작 서술은 `Contents/Shop/`·`UI/Screen/Shop/` 와 클라·서버 공용 규칙 `Core/Network/Shared/Shop/ShopRules.cs` 구현 기준이다.

## 1. 개요

### 1.1 구성 요소

| 대상 | 파일 | 시트 | 현재 행 수 |
|---|---|---|---|
| 상점 | `Shop.xlsx` | `#Enum` (`GoodsType`, `PriceType`) | 8값 / 5값 |
| | | `ShopCategory` | 6 |
| | | `ShopGoodsGroup` | 9 |
| | | `ShopGoods` | 35 |

| 런타임 | 파일 |
|---|---|
| 진열 구조 캐시 | `Contents/Shop/ShopCatalog.cs` |
| 구매 횟수 (서버 값의 사본) | `Contents/Shop/ShopPurchaseCounter.cs` |
| 보물상자 묶음 오픈 계산 | `Contents/Shop/ShopBoxOpen.cs` |
| 규칙 (클라·서버 공용) | `Core/Network/Shared/Shop/ShopRules.cs` |
| 저장 DTO | `Core/Network/Shared/Dto/ShopDto.cs` |
| UI | `UI/Screen/Shop/ShopPresenter.cs`, `ShopUI.cs`, `Slot/` |

### 1.2 핵심 규칙

> **상점은 "가격을 받고 보상 그룹을 지급하는 곳"이다.** 무엇을 주는지는 상점이 아니라 `Reward` 가 정한다.

- **모든 구매는 서버가 처리한다** (`ShopBuy` 하나). 한도 판정 → 가격 차감 → 보상 추첨 → 지급 → 저장을 서버가 하고 결과를 내려준다.
- 클라의 사전 검사(재화 부족·남은 횟수)는 버튼 상태와 안내를 위한 것이고, **최종 판정은 서버다.** 같은 `ShopRules` 를 쓴다.
- 보상 그룹 대신 **다른 효과**를 갖는 상품이 있다 — 히어로패스(패스 활성화), 칸 확장(최대 칸 수 증가), 광고 제거.

## 2. Enum

```
!Enum   GoodsType
        HeroPass        히어로 패스 상품
        NoAd            광고 제거
        Package         여러 종류(장비·재화 등)가 같이 있는 상품
        Box             보물상자. 등급별 열쇠로 연다
        Item            단일 아이템
        Currency        단일 재화
        InventorySlot   인벤토리 칸 확장
        StashSlot       창고(보관함) 칸 확장

!Enum   PriceType
        Currency        재화
        Item            아이템 (상자 열쇠 등)
        Cash            현금 결제
        Ad              광고 시청
        Free            무료
```

**`GoodsType` 은 두 가지를 정한다** — 어떤 슬롯 프리팹으로 그릴지, 그리고 구매 효과가 보상 그룹인지 다른 것인지.

| GoodsType | 슬롯 | 구매 효과 |
|---|---|---|
| `Currency` / `Item` | 단품 슬롯 | 보상 그룹 지급 |
| `Package` | 패키지 슬롯 | 보상 그룹 지급 |
| `Box` | 상자 슬롯 | 보상 그룹 지급 (묶음 오픈 가능, 5장) |
| `InventorySlot` / `StashSlot` | 단품 슬롯 | `GoodsValue` 만큼 최대 칸 수 증가 |
| `HeroPass` | 패스 슬롯 | 이번 시즌 패스 활성화 |
| `NoAd` | 광고 제거 슬롯 | 구매 횟수만 남는다 (효과 미구현) |

## 3. 테이블 — 3단 구조

```
ShopCategory (탭)  ──Category──  ShopGoodsGroup (제목)  ──GroupID──  ShopGoods (상품)
```

### 3.1 `ShopCategory` (4컬럼, EnumTable)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!ShopCategory` | 접두 없는 enum 키 |
| `Name` | `!string` | 탭 이름 |
| `Order` | `!int` | 탭 순서 (오름차순) |
| `IsEnable` | `!bool` | FALSE 면 탭을 숨긴다 |

**현재 6탭** — `Special`(특가) / `Currency`(재화) / `TreasureBox`(보물) / `Pet`(펫) / `Costume`(코스튬) / `Etc`(기타).

### 3.2 `ShopGoodsGroup` (3컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 카테고리 순번(1) + 순번(2). **ID 오름차순이 곧 표시 순서다** (`Order` 컬럼이 없다) |
| `Category` | `!ShopCategory` | 소속 탭 |
| `Name` | `!string` | 묶음 제목 |

**현재 9묶음** — `101` 특가상품 / `201` 보물상자 / `301` 다이아 · `302` 골드 · `303` 루비 / `401` 펫 / `501` 코스튬 / `601` 스킬 · `602` 보관함.

### 3.3 `ShopGoods` (14컬럼)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `ID` | `!int` | 일련번호. **묶음 안에서 ID 오름차순으로 표시한다** |
| `GroupID` | `!int` | → `ShopGoodsGroup.ID` |
| `Name` | `!string` | 상품명 |
| `Desc` | `!string` | 설명 (줄바꿈 가능) |
| `Bonus` | `!string` | 보너스 표기 문구. 비어 있으면 표시하지 않는다 |
| `Icon` | `!string` | 아이콘 주소 |
| `GoodsType` | `!GoodsType` | 2장 |
| `RewardGroupID` | `!int` | → `Reward.GroupID`. 보상이 효과가 아닌 상품은 비운다 |
| `PriceType` | `!PriceType` | 판별 컬럼 |
| `PriceParam` | `!string` | 가격 종류별 파라미터 (4.1) |
| `Price` | `!int` | 가격 수량 |
| `MaxPurchaseCount` | `!int` | 구매 한도. **0(빈 칸)이면 무제한** |
| `UseDailyReset` | `!bool` | TRUE 면 구매 횟수가 매일 오전 6시에 초기화된다 |
| `GoodsValue` | `!int` | 상품 종류별 수치. 현재는 칸 확장 상품의 늘어나는 칸 수 |

## 4. 가격과 구매 한도

### 4.1 가격 (`PriceType` + `PriceParam`)

`PriceParam` 은 다형 컬럼이다 (`테이블규약_설계.md` 5장). 해석은 공유 `ShopRules` 가 한다.

| PriceType | PriceParam | Price | 처리 |
|---|---|---|---|
| `Currency` | `Currency` enum ID | 수량 | 재화 차감 |
| `Item` | `Item.ID` | 개수 | 아이템 차감 (상자 열쇠) |
| `Free` | — | — | 차감 없음. 한도와 일일 초기화로 "하루 1회 무료"를 만든다 |
| `Ad` | — | — | **[임시] 검증 없이 통과** |
| `Cash` | — | 원화 가격 | **[임시] 검증 없이 통과** |

> **광고·현금 상품이 지금은 무료다.** 광고 SDK 와 영수증 검증이 붙기 전까지의 임시 경로다. 교체 계획은 `출시후 작업.md`.

재화는 서버가 차감을 확정한 양을 응답으로 내려주고, **클라는 그만큼만 뺀다(증감 반영).** 서버의 최종 값으로 덮어쓰지 않는다 (`뒤끝서버시스템_설계.md` 3장).

### 4.2 구매 한도

```
남은 횟수 = MaxPurchaseCount - 지금까지의 구매 횟수        (MaxPurchaseCount = 0 이면 무제한)
```

- **`UseDailyReset = TRUE`** 인 상품은 마지막으로 산 날이 오늘과 다르면 구매 횟수를 0으로 본다. 하루 경계는 한국 시간 오전 6시(`ResetDay`).
- 구매 횟수의 원본은 서버(`USER_SHOP`)다. 클라는 로그인 때 받아 두고, 구매 성공 응답 후 같은 규칙으로 따라 센다 (`ShopPurchaseCounter`).

**한도 판정의 예외 둘**

| 상품 | 판정 기준 |
|---|---|
| 히어로패스 | 상점 횟수가 아니라 **이번 시즌 패스 구매 여부.** 시즌(35일)이 넘어가면 다시 살 수 있다 |
| 수집품 (펫·코스튬) | **이미 보유 중이면 살 수 없다.** 다른 경로(필드보스 드랍 등)로 얻었어도 같다 |

수집품 판정은 상품의 보상 그룹에서 첫 수집품 아이템을 찾아 보유 여부를 본다 (`ShopRules.TryGetCollectible`). 그래서 수집품 상품에는 `MaxPurchaseCount` 를 따로 두지 않아도 중복 구매가 막힌다.

## 5. 보물상자

`GoodsType = Box`. 등급별 열쇠 아이템(`PriceType = Item`)으로 열고, 보상 그룹(`50xx`)을 굴려 장비를 준다.

| 상품 | 열쇠 | 보상 그룹 | 등급 가중치 |
|---|---|---|---|
| 일반 보물 상자 | `1020100001` | `5001` | `40001` (일반 ~ 희귀) |
| 고급 보물 상자 | `1020100002` | `5002` | `40002` (고급 ~ 영웅) |
| 최고급 보물 상자 | `1020100003` | `5003` | `40003` (희귀 ~ 전설) |

**뒤끝 확률표를 쓰지 않는다.** 상자도 다른 보상과 같은 공유 코어(`RewardRoller`)로 서버가 굴린다.

### 5.1 묶음 오픈

상자만 한 번에 여러 개를 열 수 있다 (`ShopBuyRequest.count`).

| 방식 | 여는 개수 | 장비 |
|---|---|---|
| 일반 | `min(보유 열쇠, 25, 인벤토리 빈칸)` | 인벤토리로 들어간다 (상자 1개 = 1칸) |
| 자동분해 체크 | 보유 열쇠 전부 | **인스턴스를 만들지 않고 전부 분해**해 환급 재화로 받는다 |

- 한 번에 여는 상한은 25개다 (`ShopRules.BoxOpenBatchMax`). 자동분해 오픈은 칸을 쓰지 않으므로 이 상한과 빈칸 제한을 받지 않는다.
- 빈칸이 없으면 일반 오픈은 열지 않고 경고만 띄운다.
- 자동분해 체크 상태는 **기기에 상품별로** 저장한다. 유저의 일괄·자동 분해 설정(`DecomposeSetting`)과는 별개다 — 이쪽은 조건 없이 전부 분해한다.
- 슬롯의 버튼 숫자와 실제 요청 개수가 같은 계산을 쓰도록 `ShopBoxOpen` 한곳에 둔다. 최종 판정은 서버가 같은 기준으로 한다.
- 묶음 오픈 결과는 같은 종류끼리 한 줄로 합쳐 내려온다.

> **상점 상자에는 유저의 자동 분해 설정이 적용되지 않는다.** 자동 분해는 드랍·던전 보상에만 걸린다 (`아이템시스템_설계.md` 6.5). 상자에서 나온 장비를 분해하려면 위의 체크를 쓴다.

## 6. 보상이 아닌 효과를 갖는 상품

**칸 확장 (`InventorySlot` / `StashSlot`)** — 보상 그룹 대신 `GoodsValue` 만큼 최대 칸 수가 늘어난다. 현재 인벤토리 +10칸 / 창고 +5칸, 각각 루비 10,000 · 최대 10회. 기본 칸 수와 규칙은 `아이템시스템_설계.md` 4.2.

**히어로패스 (`HeroPass`)** — 이번 시즌 패스를 활성화한다. 응답 처리만 따로 둔다 (`히어로패스시스템_설계.md` 6장).

**광고 제거 (`NoAd`)** — 구매 횟수만 `USER_SHOP` 에 남고 **효과가 없다.** 광고 SDK 연동 때 함께 구현한다.

## 7. 구매 흐름

```
슬롯 클릭
  └ ShopPresenter         사전 검사 (남은 횟수·재화·열쇠·빈칸) — 무료·광고·현금은 볼 것이 없다
       └ 서버 ShopBuy      1. 상품 + 구매 한도 (히어로패스·수집품 예외 포함)
                           2. 가격 차감 (메모리에서만)
                           3. 보상 추첨 → 반영  (골드 보너스 없음)
                           4. 인벤토리·재화·구매 횟수를 한 번에 저장
            └ 응답         차감량을 로컬 재화·아이템에서 뺀다 (증감)
                           지급 결과를 인벤/지갑에 반영 (RewardGranter.FromServer)
                           구매 횟수를 따라 센다 → 결과 팝업
```

- **요청 중에는 같은 상품을 다시 보내지 않는다.** 응답 전 연타를 막는다.
- 계정 반영은 상점 창이 닫혔어도 한다 — 서버에는 이미 저장됐다. 화면 갱신과 결과 팝업만 창이 살아 있을 때 한다.
- 3단계가 실패하면 저장하지 않으므로 2단계의 차감도 없던 일이 된다.
- `ShopBuy` 는 재전송 중복 방지 대상이다 — 통신 실패로 다시 보내도 두 번 구매되지 않는다 (`뒤끝서버시스템_설계.md` 6장).

## 9. 저장 데이터

```
purchases   List<{
                goodsId     ← ShopGoods.ID
                count       ← 구매 횟수
                resetDay    ← 마지막으로 산 날 (ResetDay 값). 일일 초기화 상품은 오늘과 다르면 0회로 본다
            }>
```

서버(`USER_SHOP`)가 보관한다 (`ShopDto`). 칸 확장분은 `USER_INVENTORY`, 패스 구매 여부는 `USER_HEROPASS` 에 따로 있다.

## 10. 참조 관계

```
ShopCategory.ID      ←  ShopGoodsGroup.Category
ShopGoodsGroup.ID    ←  ShopGoods.GroupID

ShopGoods.RewardGroupID  →  Reward.GroupID       (30xx 묶음 / 40xx~43xx 단품 / 50xx 상자)
ShopGoods.PriceParam     →  Currency.ID          (PriceType=Currency)
                         →  Item.ID              (PriceType=Item)
```

## 11. 검증 규칙

| # | 항목 | 분류 |
|---|---|---|
| 1 | `ShopGoods.GroupID` 가 `ShopGoodsGroup` 에 존재하는가 | 오류 (진열되지 않는다) |
| 2 | `ShopGoodsGroup.Category` 가 `ShopCategory` 에 존재하는가 | 오류 |
| 3 | `PriceType = Currency` 인데 `PriceParam` 이 `Currency` 로 해석되지 않거나 `Price` 가 0 이하 | 오류 (서버가 거절한다) |
| 4 | `PriceType = Item` 인데 `PriceParam` 이 `Item.ID` 가 아니거나 `Price` 가 0 이하 | 오류 |
| 5 | 보상이 효과인 상품(`Currency` / `Item` / `Package` / `Box`)의 `RewardGroupID` 가 비었거나 없는 그룹 | 오류 (가격만 빠진다) |
| 6 | `InventorySlot` / `StashSlot` 의 `GoodsValue` 가 0 이하 | 오류 (칸이 늘지 않는다) |
| 7 | `UseDailyReset = TRUE` 인데 `MaxPurchaseCount` 가 0 | 경고 (무제한이라 초기화가 의미 없다) |
| 8 | `PriceType = Free` 인데 `MaxPurchaseCount` 가 0 | 오류 (무한 무료) |
| 9 | 보상 그룹의 `Reward` 가 `Item` 에 없는 ID 를 가리키는가 | 오류 |

## 12. 미결 / 다음 작업

- **결제·광고 검증이 없다** — `Cash` / `Ad` 가격과 히어로패스가 무검증으로 통과한다 (`출시후 작업.md`).
- **광고 제거 효과 미구현** — 구매해도 달라지는 것이 없다.
- **패키지 2종의 보상이 깨져 있다** — 스타터·재료 패키지(`3001` / `3002`)가 `Item` 에 없는 구 강화 재료 아이템(`1020200001` ~ `3`)을 가리킨다 (`보상시스템_설계.md` 10장).
- **상자 열쇠의 획득 경로가 최초 지급뿐이다** — 열쇠 아이템(`10201xxxxx`)을 주는 곳이 보상 그룹 `100`(계정 생성 시)밖에 없다. 같은 이름의 열쇠 **재화**(`BronzeKey` / `SilverKey` / `GoldKey`)가 출석·히어로패스 보상으로 나가지만 상점은 아이템 쪽을 받는다. 둘 중 하나로 정리해야 한다.
- **`Currency` 값이 세 곳에서 겹친다** — `ShopCategory.Currency` / `GoodsType.Currency` / `PriceType.Currency` 가 전부 다른 뜻이다.
- **기간 한정 상품 구조가 없다** — 판매 시작·종료 컬럼이 없어 `IsEnable` 로 탭 단위만 끌 수 있다.
